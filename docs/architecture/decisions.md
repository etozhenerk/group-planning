# Решения по устройству проекта

## Принято

### Один монорепозиторий

`backend/` содержит серверную часть. Клиенты находятся в `frontend/web/`,
`frontend/ios/` и `frontend/android/`. Корневой `AGENTS.md` задаёт общие правила,
каждое из четырёх приложений содержит собственную инструкцию.
Дополнительный `frontend/AGENTS.md` не используется.

У каждого приложения будут самостоятельные сборка, проверки и выпуск.
Единое изменение может согласованно затронуть сервер и несколько клиентов.

### Стандартный SDD

Оригинальный OpenSpec находится в `openspec/`. Постоянные спецификации
хранятся в `openspec/specs/`, работа над изменениями — в `openspec/changes/`.
Готовые навыки устанавливаются в `.agents/skills/` и коммитятся вместе с кодом.
AIFF и корпоративная инфраструктура не входят в этот проект.

### Инструменты воспроизводимы

Версии корневых инструментов зафиксированы в `package.json` и `package-lock.json`.
`.nvmrc` задаёт проверенную версию Node.js для них. Это не выбор стека приложений.
Пакеты устанавливаются из публичного npm registry.

Состав навыков задаёт `scripts/openspec-profile.json`. Обёртка
`scripts/openspec.mjs` запускает официальный CLI, передавая профиль через
игнорируемую `.cache/openspec/`. Настройки профиля и данные CLI изолированы
от пользовательской конфигурации. При запуске обёртки телеметрия и предложения
самообновления CLI отключены; обновление версии выполняется явным изменением проекта.

### Основные технологии и BDUI

Бэкенд пишем на Go, веб — на React + TypeScript. Для мобильных оболочек
выбраны Swift + SwiftUI и Kotlin + Jetpack Compose. Основные продуктовые экраны
и сценарии будут управляться сервером через BDUI.

Цели — управлять тремя платформами из одного места и обновлять интерфейс
уже установленных клиентов, когда выпуск новых сборок через магазин недоступен.
Поддержка ранее выпущенных клиентов входит в архитектурные требования.

Решение, границы поставки и критерии будущего прототипа описаны в
[ADR 0001](0001-bdui.md). DivKit — кандидат на движок; окончательный выбор
будет сделан после прототипа. Приложений и результатов проверки ещё нет.

## Открыто для дальнейшего проектирования

- Описать общий контракт данных, UI и действий сервера и клиентов.
- Проверить движок BDUI и интеграции на web, iOS и Android.
- Выбрать базу данных, библиотеки, версии, сборки и инфраструктуру.
- Начать серверную часть одним приложением с модулями; появление дополнительных
  сервисов обосновывать конкретными задачами.
- Вынести общий код только при наличии реального использования несколькими частями.

Принятые решения фиксируются здесь либо отдельным ADR в этой папке.
При подготовке технического изменения OpenSpec ссылайся на соответствующий ADR
и описывай в артефактах изменения конкретную реализацию и проверки.
