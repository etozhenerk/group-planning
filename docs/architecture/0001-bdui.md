# ADR 0001: общая BDUI-архитектура для трёх клиентов

Статус: заменено [ADR 0002](0002-client-ui.md) 19 октября 2026 года.
Первоначально принято в тот же день; реализация и прототип не начинались.

Этот документ сохранён как история решения. Требования ниже больше не действуют.
Текущая архитектура — интерфейсы в коде клиентов и общий API сервера;
BDUI и выбор его движка исключены из плана.

## Контекст и цели

У Somewhere три клиентские платформы: web, iOS и Android. Первым продуктовым
сценарием будет [«собраться компанией»](../product/mvp-gathering.md).

BDUI выбран по двум причинам:

1. Управлять основными экранами и пользовательскими сценариями трёх платформ
   в одном месте, поставляя изменения с бэкенда.
2. Сохранять возможность менять интерфейс уже установленного мобильного
   приложения, если выпуск новых сборок через магазин станет недоступен,
   например после удаления приложения из каталога.

Вторая цель относится к установленной копии, которая продолжает запускаться
и имеет доступ к серверу. Она не означает гарантию работы при любых причинах
блокировки или изменениях ОС и внешних сервисов.

## Решение

Основные продуктовые экраны и переходы между шагами описываются на сервере
и доставляются клиентам как декларативное описание UI. Сервер управляет
составом блоков, формами и доступными действиями. Клиенты отображают описание
и выполняют заранее реализованные обработчики действий.

| Область | Принятая основа |
| --- | --- |
| Бэкенд | Go; бизнес-логика, данные, права доступа и формирование BDUI-описаний |
| Веб | React + TypeScript; браузерная оболочка и интеграция BDUI-рендерера |
| iOS | Swift; нативная оболочка на SwiftUI, BDUI-рендерер и системные интеграции |
| Android | Kotlin; нативная оболочка на Jetpack Compose, BDUI-рендерер и системные интеграции |

SwiftUI и Jetpack Compose относятся к оболочкам. Конкретный способ встраивания
BDUI-рендерера и нужные платформенные адаптеры проверяются в прототипе.
Продуктовые экраны формируются из общего серверного описания и отображаются
рендерером каждой платформы.

Бизнес-правила, проверка прав и проверка входных данных остаются на сервере.
Клиенты отвечают за отображение, локальное состояние ввода, жизненный цикл
приложения и выполнение поддерживаемых действий. Они сообщают серверу
о результате пользовательского действия и отображают полученный результат.
Точный формат контрактов и обмена данными пока не определён.

Вход через Яндекс ID, обработка ссылок-приглашений, управление сессией
и обращения к возможностям ОС реализуются в оболочках и на бэкенде.
BDUI может вызывать соответствующие обработчики. Переход через авторизацию
должен сохранять исходное приглашение согласно продуктовому сценарию.

## Граница серверной поставки

Изменения экранов и сценариев, которые используют уже поддерживаемые клиентом
компоненты и действия, должны поставляться с сервера без пересборки клиента.
Это целевое свойство архитектуры; его ещё нужно проверить на прототипе.

Новый компонент, новый обработчик действия, обновление нативного SDK
или исправление ошибки оболочки могут потребовать новой клиентской сборки.
BDUI также не обеспечивает установку приложения новым пользователям после
его удаления из магазина. Веб остаётся полноценным способом пройти сценарий
приглашения без установки приложения.

## Совместимость и выпуск изменений

- Клиент сообщает версию контракта и поддерживаемые возможности. Конкретные
  поля и правила согласования предстоит описать в OpenSpec.
- Сервер выбирает описание, которое может обработать поддерживаемая версия
  клиента. Обычная серверная поставка UI не должна требовать обновления
  всех мобильных клиентов.
- Для неподдерживаемых обязательных компонентов и действий нужно определить
  совместимый вариант или понятное состояние ошибки. Нельзя молча терять
  необходимое действие, например возможность ответить на приглашение.
- Изменения описаний UI хранятся по версиям, проверяются на всех трёх платформах,
  включаются постепенно и допускают откат серверной ревизии.
- Поддержка старых клиентов проверяется отдельно от работы последних сборок.
  Срок поддержки версий, наблюдение за ошибками и условия прекращения поддержки
  ещё не выбраны.

## Кандидат на движок: DivKit

DivKit рассматривается первым, поскольку предоставляет рендереры для web,
iOS и Android, JSON-описания UI, формы и обработку действий. Окончательный
выбор зависит от проверки нашего сценария на трёх клиентах.

В официальной документации JSON builders перечислены для Kotlin, TypeScript
и Python. Интеграцию формирования и проверки описаний на Go нужно проверить
отдельно. Выбор движка не меняет принятое решение о Go для бэкенда.

## Следующее техническое изменение

Подготовить изменение OpenSpec для прототипа одного сценария: карточка встречи
с ответом об участии или голосованием. В нём определить контракт, минимальный
набор компонентов и действий, задачи по четырём приложениям и проверки.

Прототип должен позволить:

1. Показать один сценарий из общего серверного описания на web, iOS и Android.
2. Зафиксировать сборки клиентов и изменить описание UI и сочетание известных
   действий на сервере. Проверить новый сценарий на прежних сборках.
3. Выполнить пользовательское действие и увидеть подтверждённый сервером
   результат; проверить ввод, загрузку, ошибки, навигацию и доступность.
4. Проверить совместимый ответ старому клиенту, обработку неподдерживаемой
   возможности и откат серверного описания на предыдущую ревизию.

Результаты этих проверок пока отсутствуют. Прототип проверяет способ поставки
без новых клиентских сборок; удаление приложения из настоящего магазина
для такой проверки не требуется.

## Открытые решения

- Движок BDUI, его версии и способ встраивания в каждую оболочку.
- Формат UI-контракта, команд и данных; генерация и проверка описаний на Go.
- Минимальный набор компонентов и действий, хранение состояния формы.
- Адаптация к размерам экрана, доступность и допустимые различия платформ.
- Поддержка старых версий, обработка несовместимости, включение и откат UI.
- База данных, HTTP-библиотеки, сборщик веба, API-инструменты и окружение сборки.

Эти пункты дополняют [общий список вопросов](../product/open-questions.md).
