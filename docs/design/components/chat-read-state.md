# Прочитанность и окно чата · 2.5.1

Реализует уже принятый [UX v1](../../../openspec/changes/chat-reliability-and-sync/ux.md)
на web, iOS, Android. [Интерактивный фрагмент](../../../openspec/changes/meeting-experience-refresh/assets/revisions/2026-10-27-chat-read-state/index.html)
использует прежний Telegram-chat raw и опубликованные роли. Меняется состояние
чата; настройки, реакции, иконки, шапка и composer сохраняют свои контракты.

## Личные непрочитанные

Список и календарь сохраняют принятую композицию карточки. Число непрочитанных
помещается в свободном правом краю строки названия, не перекрывает дату/меню,
не меняет положение аватаров. Фрагмент `state=list` показывает только это
добавление, а не новый макет списка. При нуле или выключенном read_state badge
отсутствует. Значение приходит с сервера; язык доступности — «N непрочитанных
сообщений» с русским склонением. Не подменять отсутствие данных нулём.
Роли: color.accent/ownText, typography.size.caption/weight.semibold,
radius.pill, space.s8; минимальная геометрия24 из существующей шкалы space.s24.
Длинное decimal значение не обрезается; заголовок может переноситься.

«Непрочитанные» — один разделитель перед первым чужим непрочитанным сообщением
в начале сессии чтения. Он не движется при продвижении marker. Роли
color.muted/borderStrong, typography.size.caption, space.s12/s16. Линии заполняют
свободную ширину; текст не изображает кнопку. При отсутствии unread разделителя нет.

## Кто прочитал

Только у своего подтверждённого сообщения доступно «Прочитали N». При нуле —
действие «Кто прочитал» в меню сообщения; нулевой счётчик постоянно не выводится.
Локальное pending и серверный ACK не создают read receipt. Подпись находится
под своим bubble справа, рядом с metadata по композиции raw, без отдельной
иконки глаза/кнопки просмотра реакций. Роли color.muted, typography.size.caption,
space.s4; нажатие/фокус использует существующее выделение и native target44/48.
До получения server counts никакого выдуманного числа или успеха нет.

`state=context-zero` показывает вход при нулевом receipt: long press собственного
подтверждённого сообщения открывает прежний anchored reaction popup. Под полоской
реакций, внутри того же контейнера, идёт одна строка «Кто прочитал» без иконки;
separator color.borderStrong (`--border` в raw), inset space.s16 по горизонтали/space.s12 по вертикали,
body typography, target44 iOS/web и48 Android. Строка сохраняется в расширенной
панели. Web также поддерживает context menu и клавиатурный вход. Чужое/pending
сообщение не получает этот пункт. Menu exit завершается до открытия readers;
закрытие readers возвращает фокус к исходному bubble и прежний scroll offset.
Постоянная кнопка нулевого счётчика и отдельный экран не добавляются.

На телефоне открывается существующий bottom sheet, на широком web —
центрированный Dialog, с прежними enter/exit/Reduce Motion. Заголовок «Прочитали»,
затем строки avatar+имя; крестик остаётся только в desktop Dialog.
В нижних панелях крестика нет; никаких email/телефонов/времени чтения.
Композиция и размеры — те же people rows, sheet title, padding и safe area,
что у списка участников/реакций. Список имеет ограниченную высоту и внутренний
scroll. По коррекции 4.0.0 viewport списка с первого кадра резервирует три
component.mobileRoster.rowHeight и два space.s12; загрузка, пустой результат,
ошибка и список не меняют положение панели. Свайп вниз не обновляет данные.
Чат под ним неподвижен и не продвигает read-through. Повторное закрытие
анимации безопасно; завершение exit возвращает фокус к исходному сообщению,
сохраняет его anchor/offset. Web Escape/доступный handle, Android Back,
iOS системный жест/VoiceOver escape; hardware
Escape на iOS не заменяет проверку телефонного сценария.

Состояния: loading — три skeleton строки avatar/имя и одно AX название
«Загружаем список»; empty — «Пока никто не прочитал»; error — «Не удалось
загрузить список» + «Повторить»; ready — текущие разрешённые имена. Ошибка
следующей страницы оставляет уже загруженных людей и повтор у нижней границы.
Изменения состава обновляют count/list; потеря доступа закрывает приватную панель.

## История и новый хвост

Лента — единственный вертикальный scroll. Догрузка показывает2–3 скелетона
только у загружаемой границы; ошибка — «Не удалось загрузить сообщения» +
«Повторить» там же, composer остаётся доступен. Existing skeleton роли и
Reduce Motion сохраняются. Первичная загрузка использует SkeletonConversation.

При чтении прошлого приход сообщения не двигает anchor: над composer справа
появляется «N новых сообщений» с русским склонением; только собственные записи —
«К новым сообщениям». Кнопка не накрывает видимую строку: в ленте оставляется
соответствующий нижний inset. Действие загружает хвост и включает следование.
Роли существующих small action/pill, color.raised/text, space.s8/s16,
caption, native target44/48. У хвоста кнопки нет. Порог следования64 из UX.

## Границы и редактура текста

Badge отвечает «сколько непрочитанных в этой встрече», разделитель — «откуда
начать», receipt — «кто прочитал моё сообщение», ошибка — «что повторить».
Эти тексты не повторяются в баннере. Нет «Доставлено», «Успешно», технических
названий транспорта и обещания чтения по факту загрузки. Это применение
product-copy-editor к уже принятому UX, без расширения продуктовых решений.

Нативная типографика, Dynamic Type/TalkBack/VoiceOver, targets и safe area
следуют platforms.md. Скриншоты raw и source preflight не дают acceptance
клиента. Нужны independent feature-test/design-review на точной сборке.
