# Основа дизайна · предложение v0.4

Статус: проверяется на [макетах ленты](../../openspec/changes/gathering-activity-feed/ux.md).
Это ещё не утверждённая дизайн-система и не библиотека BDUI-компонентов.

## Визуальный принцип

Разговор друзей — основа интерфейса. Сообщения, предложения и решения остаются
рядом. Текст читаемый, формы мягкие, лица участников заметны. Служебные сведения
компактны; отдельная рамка вокруг каждого события не нужна.

Графит и белый задают основу. Фотографии и небольшие эмоциональные детали
добавляют жизни. Акцент используется по смыслу; цвета чужих приложений не копируются.
Ориентиры пользователя: Telegram, Instagram, Discord.

## Предложенные токены

| Роль | Значение в CSS-макете |
| --- | --- |
| Фон разговора | `#24252a` |
| Фон навигации и деталей | `#1d1e22` |
| Входящее сообщение / действие | `#33343a` |
| Собственное сообщение | `#e0dce8`, текст `#27252d` |
| Основной текст | `#f5f4f1` |
| Вторичный текст | `#b9b9c2` |
| Основное действие | `#f0efeb`, текст `#252429` |
| Ошибка на тёмном фоне | `#ffb8b2` плюс текстовое пояснение |
| Видимый фокус | `#d6d1f5` |
| Текст сообщения | 15 px / 1.5; настраиваемый системным размером в приложениях |
| Заголовок встречи | 24 px на телефоне, 27 px в широком экране |
| Заголовок действия | 20–21 px |
| Сетка отступов | 4, 8, 12, 16, 20, 24, 32 px |
| Скругление сообщения | 20 px, угол у автора 6 px |
| Скругление действия | 21–24 px |
| Обычное действие | Минимум 44 CSS px по высоте; платформенные цели уточняются |

Окончательные размеры, соответствия pt/dp, контраст, системный размер шрифта
и формат хранения токенов нужно проверить при реализации. Значения не копируются
в три несвязанных набора. Текущее определение — CSS рядом с UX-макетами.

## Компоненты текущего сценария

| Компонент | Состав и состояния | Действия |
| --- | --- | --- |
| Краткие детали встречи | Название, время, место, участники | Открыть подробности |
| Событие ленты | Текст изменения, автор, время; краткое/раскрытое | Раскрыть детали |
| Сообщение | Автор, текст, время; входящее/своё/неотправленное | Повтор отправки |
| Опрос о месте | Предложение, варианты, голоса; открыт/голос учтён/закрыт | Голосовать |
| Задача подготовки | Название, автор, адресат; предложена/принята | Принять задачу |
| Поле сообщения | Текст и добавление действия | Отправить, открыть меню |
| Панель действия | Меню либо форма места/задачи | Выбрать, закрыть, подтвердить |

У каждого действия есть подпись и отдельное состояние. Принятое решение,
выбранный голос и ошибка должны быть понятны без различения цветов.
Названия компонентов здесь смысловые; схема SDK, обработчики и совместимость
старых клиентов будут определены в техническом решении.
