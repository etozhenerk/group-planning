# Группировка сообщений · desktop · APPROVED

04.11.2026 пользователь поручил перенести разобранный принцип Telegram.
Кандидаты: ../chat-r4/preview.html и ../entry-r5/preview.html. Один общий
модуль MessageRow/MessageBubble/FileContent используется обеими сборками.
Предыдущие черновики сохранены в sender-study. 04.11.2026 пользователь подтвердил «да, так лучше, оставляем». Точные hashes — в APPROVAL.json обеих ревизий.

Имя находится в первом пузыре входящей группы, аватар — возле последнего.
Продолжение имеет 4 px промежутка; при смене человека начинается новая группа.
Текст, файл и фото используют один порядок автора, содержимого и времени.
Файл без реакции имеет высоту 64 px: действие загрузки, имя, размер, время
справа в том же пузыре. Реакция добавляет необходимую строку, время не налезает
на неё. У своих сообщений имя скрыто одинаково для текста и вложений.

В демонстрационном алгоритме объединяются соседние обычные сообщения одного
автора в пределах пяти минут. Системная запись, задача/опрос, граница
непрочитанного и неподтверждённая отправка разрывают группу. Это критерий
предложения UI; для будущей реализации нужно закрепить его в UX/specs/cases.
Сервер, модели данных и действующее приложение этим макетом не изменяются.

Проверка: две сборки; strict TypeScript знакомства и общего модуля;
8 проверок границ группировки. IAB: чат при 740×800 и 1440×900, знакомство
при 740 px и в текущем окне. Имена не повторяются, колонки аватаров сохранены,
нет горизонтального overflow; реплика про пиццу остаётся одной строкой.
Просмотрены входящий/свой файл и фото; проверены реакция файла через Enter
и список прочитавших. Скачивание демонстрационного PDF не реализовано.
Это самопроверка прототипа, без заявления полной приёмки приложения.

Новые сообщения появляются в прежней ленте, новое содержимое не масштабируется.
Группа не скрывает сообщение или его действия. Статусы отправки/прочитанности
сохраняются, ошибка остаётся рядом с конкретным сообщением. Reduced Motion
не требует отдельной анимации группировки. Входы общей дизайн-публикации подготовлены, запись общей версии согласуется
с мобильным выпуском; текущие tokens/contracts/manifests и мобильный выпуск не тронуты.
