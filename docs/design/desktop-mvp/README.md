# Принятые desktop-макеты somewhere

Снимок согласованного дизайна на 05.11.2026. Это исходники и интерактивные
макеты с демонстрационными данными; клиентское приложение ими не заменяется.
Дальнейшая проработка остановлена пользователем до следующей сессии.

| Экран | Актуальная ревизия | Решение |
| --- | --- | --- |
| Чат, сообщения и вложения | [chat-r4](chat-r4/preview.html) | Принят; единый автор текста/файла, системные строки ответов |
| Мои встречи, список/календарь | [list-r2](list-r2/preview.html) | Принят; ровные вкладки |
| Знакомство и вход | [entry-r5](entry-r5/preview.html) | Принят; использует реальные компоненты чата/карточек |
| Приглашения «Возможно» | [invitations-r2](invitations-r2/preview.html) | Принят; общий результат изменения ответа |
| Создание встречи | [create-r2](create-r2/preview.html) | Принят; ручное место, CTA в потоке на wide и на всю ширину на compact |
| Будущая карта создания | [create-map-r2](create-map-r2/preview.html) | Принята отдельно; скруглённая карта с отступом, вне стартового MVP |
| Приглашение по ссылке | [invite-r2](invite-r2/preview.html) | Принято 05.11; ответы сразу ведут к своему результату |

У всех активных макетов круглая подложка знака по [принятой коррекции](brand-round-r1/README.md).
После подтверждённого RSVP «Приду» открывает чат, «Возможно» — приглашения,
«Не смогу» — подтверждение с «К моим встречам». В чате системное событие
содержит имя, конкретный ответ и время. Вход, ошибка, неизвестный результат,
повтор и повторное открытие ссылки не создают новый ответ или событие.
Общий контракт — [invitation-response](../components/invitation-response.md).

Сборка каждого активного макета: `node docs/design/desktop-mvp/<ревизия>/build.mts`
из корня после установки зависимостей проекта. Исходники fixture заморожены
внутри ревизий; постановочная обвязка и sessionStorage не идут в приложение.
Превью рассчитаны на существующий локальный сервер8797 и соседние маршруты;
самостоятельное открытие `file://` не проверяет переходы.

Исторические одобрения/отклонения сохранены в [history.txt](history.txt) и history/.
Они не заменяют таблицу актуальных ревизий. Новые hashes — snapshot-files.json.
Прежние APPROVAL.json сохранены как решения о соответствовавшей им ревизии,
а новая общая коррекция записана в approval.json.

На завтра: продолжить оставшиеся desktop-экраны после приглашения по ссылке,
начиная со сведений/настроек встречи; сверять общие элементы с принятой основой.
При переносе в приложение нужны отдельные SDD-задачи и независимые приёмки.
