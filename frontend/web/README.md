# Веб Somewhere

Веб-клиент somewhere: встречи и приглашения, общий разговор, опросы даты и
места, задачи подготовки, вложения и реакции, фотографии прошедшей встречи.
Профиль показывает данные Яндекс ID и настройки аккаунта; публичные страницы
содержат помощь, сведения о приложении и форму обратной связи.

## Установка и запуск

Нужны Node.js **22.22.3** (`nvm use` из корня) и Go **1.27.2**.
Все команды ниже запускаются из корня репозитория после `npm ci`.

```sh
npm run web:demo
```

Открой `https://127.0.0.1:8443`. Сертификат локальный и самоподписанный:
для этого адреса браузер попросит разрешить подключение. На странице входа
можно выбрать тестовый профиль Саши или Лены; для второго участника открой
ссылку в отдельном профиле/приватном окне браузера.

Демо собирает клиент в режиме `demo` и запускает `TestBrowserFixture` из
`backend/internal/httpapi/browser_fixture_test.go`. Это настоящий Go HTTP API,
куки, CSRF и in-memory Store. Подменяется только внешний OAuth-provider,
который существует исключительно в `_test.go`. Обычный сервер и обычная
сборка не получают обхода входа. Не публикуй этот тестовый процесс в интернете.
Ctrl+C останавливает его; перезапуск удаляет встречи, сообщения и сессии.
`GO_BIN` позволяет явно выбрать исполняемый файл Go, если его нет в PATH.

Для обычной разработки отдельно запусти `go run ./cmd/server` из `backend/`,
затем `npm run web:dev`: Vite проксирует `/api` на `127.0.0.1:8080`.
Без настройки Яндекс ID доступны публичные экраны, а начало входа даёт
понятное сообщение. Секреты провайдера остаются на сервере.
Конфигурация — в [инструкции бэкенда](../../backend/docs/auth.md).

## Проверки

```sh
npm run web:check
npm run web:build
npx --no-install playwright install chromium webkit
npm run web:test:e2e
npm run format --workspace @somewhere/web
```

`web:check`: типы, ESLint, отступы между CSS-блоками, AST-правила FSD,
Prettier и Vitest. `web:build` создаёт обычный production bundle в `dist/`.
Демо и browser-тесты собираются отдельно в корневой `.cache/web-demo`, поэтому
проверки не подменяют web работающего локального сервера с Яндекс ID.
Браузерные тесты собирают отдельный demo bundle и запускают свежий Go-процесс
на `https://127.0.0.1:8444`. Рабочий процесс демо на 8443 им не подходит:
изолированное состояние необходимо для проверки пустого списка и повторов.

CI использует те же команды, устанавливая Chromium и WebKit с `--with-deps`.
Мобильная прокрутка дополнительно проверяется WebKit с эмуляцией телефона;
системную клавиатуру и панели Safari нужно проверять на iPhone отдельно.
Результаты сценариев и снимки — в
[отчёте веб-среза](../../openspec/changes/gathering-activity-feed/web-verification.md).

## Устройство

React 19.3.1, TypeScript 6.0.3, Vite 8.3.4, React Router 8.5.0,
TanStack Query 5.104.5. Точные версии всех инструментов — в `package.json`.

- `app` — маршруты, провайдеры, общие стили и смысловые токены v0.7.
- `pages` — композиция экранов и переходы.
- `widgets` — навигация, лента, состав и детали встречи.
- `features` — вход, создание, приглашение, ответ, настройки и отправка.
- `entities` — модели сессии/встречи, запросы, преобразование DTO и доступ.
- `shared` — проверяемый JSON transport, время, инфраструктура и UI-примитивы.

Внутренние импорты используют `@/`; между slices доступен только публичный API.
Компонент — один `const` со стрелочной функцией и свой тип Props в `.tsx`.
Хуки, мапперы и сетевой код находятся отдельно. Остальные функции тоже `const`.
Код, тесты и конфигурации — TypeScript; CSS хранится отдельно от компонентов.
ESLint проверяет фигурные скобки и пустые строки между логическими блоками,
Prettier — отступы/переносы. Проверка на PostCSS AST разделяет CSS-блоки.

JSON принимается как `unknown` и проверяется Zod; nullable и неизвестные типы
ленты не заменяются вымышленными данными. Куки не читаются из JavaScript;
CSRF хранится в памяти. Черновик и контекст приглашения изолированы по профилю
в sessionStorage. При 401 приватные кеши очищаются. При 403 поколение доступа
меняется, поздние ответы старого поколения не открывают переписку.

## Приглашения и превью

Новые ссылки используют `/i/` и 22-символьный случайный токен. Старые
`/invitations/` и 43-символьные токены поддерживаются, включая возврат после
входа. Полное описание встречи видно до входа; форма заранее сообщает об этом.
Переписка открывается по прежним правилам после «Приду».

Метатеги приглашения формирует Go в исходном HTML: title/description, canonical,
Open Graph и адрес PNG. Приложение не зависит от запуска React у бота.
Если у встречи нет обложки, используется `public/share-card.png`
(1200×630); исходник — `public/share-card.svg`. Оба используют существующий знак.

Для публикации собирай обычный web build и подключай его к Go через
`SOMEWHERE_WEB_DIST`/`SOMEWHERE_WEB_ORIGIN`; [пример](../../backend/README.md).
Демо использует тот же обработчик. Внешние мессенджеры не могут получить
localhost: их фактическое превью проверяется после публикации по HTTPS.
[Проверки](../../openspec/changes/gathering-activity-feed/share-preview-verification.md).

## Детали и действия

В шапке встречи одно название. На широком экране детали находятся справа,
на узком — в панели по кнопке `i`. В ленте остаются сообщения и события.
Пустой личный список показывает одну кнопку создания внутри пустого состояния;
при наличии встреч, загрузке или ошибке она находится в шапке.

Общий `dialog` появляется по центру широкого экрана или поднимается снизу
на телефоне. Анимации учитывают `prefers-reduced-motion`, фокус возвращается
к действию, открывшему панель.

## Поля даты и времени

Календарь и поля используют Gravity UI: обёртки находятся в `shared/ui/DateInput`,
`TimeInput` и `SelectInput`, тема — в `app/ui/App/App.module.css`. Иконки календаря и часов
занимают одинаковую область слева; очистка даты остаётся справа.
Календарь одинаков в настольном и мобильном браузере, ввод доступен с клавиатуры.
Для времени цифровая клавиатура дополняет `1900` до `19:00`.

У новой встречи пояс определяется браузером. Черновик и редактирование сохраняют
исходный пояс; подпись под полями поясняет, к какому месту относится время.
Сервер получает прежние `starts_at` и `timezone`; расчёт и неоднозначные часы
обрабатывает Temporal. [Проверки и снимки](../../openspec/changes/gathering-activity-feed/date-time-verification.md).

## Каталоги компонентов

```text
ui/
  MeetingCard/
    MeetingCard.tsx
    MeetingCard.module.css
    index.ts
```

Личные `hooks/`, `lib/` и `utils/` добавляются при необходимости. Компонент без
собственных стилей содержит только TSX и реэкспорт. Другой компонент всегда
получает отдельный каталог. Доменные `model/api/lib` остаются в своих slices FSD.
Все внутренние импорты используют алиасы и публичные API.

Стили принадлежат компоненту: CSS Modules изолируют классы, варианты передаются
пропсами. Общими остаются токены, типографика, reset и базовые HTML-контролы.
`web:check` проверяет структуру, соответствие имён, реэкспорты и границы стилей.

## Вложения, реакции и фото встречи

Выбор вложения не очищает текст сообщения. Клиент получает ограничения сервера,
проверяет каждый файл, резервирует загрузку, передаёт байты с прогрессом и
подтверждает публикацию. Повтор использует прежние ключи; успешно добавленные
файлы не отправляются повторно. Приватные изображения загружаются с проверкой
доступа, object URL освобождаются после закрытия или отзыва прав.

Системный выбор открывает отдельный экран `/meetings/:id/upload`. Выбранные
`File` остаются только в приватном кэше текущего пользователя и поколения доступа,
не попадают в URL, историю браузера или localStorage. Подпись документа отправляется
вместе с ним; после начала загрузки подпись и ключ публикации закреплены до повтора.
Фотографии и альбом не имеют подписей. При уходе с экрана выбор очищается, а текст сообщения сохраняется. После
перезагрузки страницы файлы нужно выбрать заново; успешная отправка подтверждается API.

Реакции запрашиваются пачками по загруженным сообщениям, без отдельного запроса
на каждую строку. Каталог эмодзи локальный и совпадает с
`contracts/emoji/emoji-ru.json`: Unicode 17.0, русские названия CLDR 48.
Выбор вставляет эмодзи в позицию курсора; недавние эмодзи сохраняются локально.
Предложения даты, места и задачи открываются отдельными страницами встречи
`?action=date|place|task`. Back и Escape сохраняют незавершённую форму в памяти;
подтверждённый результат очищает её. Пояснение нового места передаётся в API.

Профиль показывает полученные от Яндекса личные и контактные данные. Пропущенные
части даты рождения остаются пропущенными; редактирования и вымышленных значений нет.

Альбом открывается по `/meetings/:id/memories`; серверный `period` определяет
доступность добавления воспоминаний. Фото альбома не создают сообщения в чате.
Стопка, сетка и полноэкранный просмотр сохраняют выбранное фото; запросы страниц
и изображений ограничены текущим окном просмотра.

Форма `/support` отправляет только введённые сведения. Почта, выбранный скриншот
и диагностика необязательны; успешное состояние требует номер, принятый API.
Окончательные юридические реквизиты не подменяются примерными данными:
`/privacy` и `/cookies` явно обозначают проект документа.

Футер существует только на десктопном онбординге: ширина от 740 px и основное
устройство ввода с hover/fine pointer. Внутренние страницы и мобильный web,
включая горизонтальный телефон, не показывают футер; ссылки доступны из профиля.
Нижняя мобильная навигация доступна только на списке/календаре встреч,
списке приглашений и основном профиле. Вложенные экраны используют Back;
десктопный sidebar сохраняется.
На мобильной форме дата представлена кнопкой: полный год не обрезается,
календарь, ввод и очистка находятся в доступном всплывающем окне. Редактируемые
поля сохраняют 16 px для предотвращения автоматического масштабирования Safari.

## Визуальная проверка

Утверждённые HTML/CSS находятся в
`openspec/changes/meeting-experience-refresh/assets/`. Для сравнения экранов
с эталоном на 320, 390, 768 и 1440 px:

```sh
npm run build:demo --workspace @somewhere/web
npm exec --workspace @somewhere/web -- playwright test --config playwright.visual.config.ts
```

Сценарий использует отдельный тестовый API и сохраняет пары
`*-actual.png` / `*-reference.png` в `/tmp/somewhere-web-design`.
Для чата с теми же участниками, сообщениями и задачей, что в нативных клиентах,
используется отдельный режим fixture:

```sh
SOMEWHERE_BROWSER_DESIGN=1 npm exec --workspace @somewhere/web -- playwright test --config playwright.visual.config.ts
```

Это визуальная приёмка, а не замена функциональным browser-тестам. Системную
клавиатуру и панели настоящего Safari проверяют отдельно на устройстве.
