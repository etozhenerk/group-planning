# Встречи, вложения и сведения о сервисе

Клиент реализует общий `meeting-experience-refresh` нативно в SwiftUI.
Метаданные и операции приходят через общий API; контакты профиля не входят
в `UserProfile`, использующийся для участников, авторов и реакций.

## Личные данные Яндекс ID

`AccountProfile` декодирует необязательные `login`, `first_name`, `last_name`,
`birthday`, `sex`, почту, телефон и аватар только из приватного `/me/profile`.
Старый сервер без новых полей совместим. Панель личных данных расположена перед
контактами. Нули в дате рождения означают неизвестную часть; клиент не дополняет
дату текущим или вымышленным годом. Неизвестные значения явно показаны как
«Не указано». Эти поля не копируются в публичные модели участника.

Закреплённый YandexLoginSDK 3.2.0 не передаёт `scope`/`optional_scope`
в `AuthorizationParameters`. Публичный `authorize` не имеет параметра `scopes`;
`customValues` не является способом назначения прав. По официальному
[контракту OAuth](https://yandex.ru/dev/id/doc/ru/codes/code-url), отсутствие обоих
параметров использует зарегистрированные права. Проверены также
[официальные методы SDK](https://yandex.ru/dev/id/doc/ru/mobileauthsdk/ios/2.1.1/sdk-ios-methods)
и исходники закреплённого пакета. Старые токены сами не приобретают новые права:
пользователь может выйти и войти заново. Автоматический принудительный выход
не добавлен.

## Предложения в чате

Дата, место и задача используют полноэкранные формы с общим оформлением панели,
полей и кнопок из `action-*.html`. Нативные календари и меню открываются из полей;
системного `Form` для этих сценариев нет. Опрос даты сохраняет правило как минимум
двух разных вариантов и добавление до 20 дат. Необязательное «Почему здесь»
передаётся как `explanation` (до 2000 Unicode codepoints), показано участникам
в карточке опроса и сохраняется с телом/ключом при повторе после потери ответа.

## Владение состоянием

`HomeView` сохраняет `MeetingListOwner` при выборе нижнего раздела. Поэтому
возврат из чата сохраняет календарный день, месяц и период. После ответа API
на создание закрывается форма и открывается встреча без промежуточного экрана.
Часовая отсечка RSVP использует серверную причину/границу, обновление приглашения
при foreground и локальные часы для изменения доступности без нового запроса.

`ProfileOwner`, `MediaTransferOwner`, `MediaContentOwner`, `MemoriesOwner` и
`ReactionOwner` связаны с `SessionStore` и lease `PrivateData`. Ответ после
выхода или отзыва доступа не возвращает частные данные. Действия при уходе
с экрана отменяются; неопределённая загрузка остаётся доступной для повтора.
Реакции загружаются сразу при регистрации видимых сообщений, затем обновляются
одним batch-запросом в существующем активном цикле ленты. Если набор видимых
сообщений изменился во время запроса, догружается новый набор. Повтор после потерянного ответа сохраняет исходные emoji/active/key, а ревизия
сообщения отсекает устаревший GET после PUT. Новый realtime-транспорт относится
к отдельному изменению.

## Эмодзи и ввод

`ComposerTextView` — адаптер UITextView для поддерживаемого iOS 17: он сохраняет
выделение в UTF-16 и вставляет эмодзи без отправки. Полный каталог Emoji 17 / CLDR 48
лежит в `Somewhere/Resources/emoji-ru.json`; источник — `contracts/emoji/emoji-ru.json`.
`sh scripts/check-emoji.sh` сравнивает копию перед сборкой и тестами. После обновления
общего генератора скопируйте JSON и `LICENSE` в ресурсы iOS. Недавние эмодзи живут
в `PrivateData` и очищаются вместе с сессией.

## Фото и файлы

Photo Picker и Documents дают только выбранные пользователем файлы. ImageIO
превращает фото, включая HEIC, в JPEG без исходных метаданных. Тип, размер и
число файлов проверяются по `/media/limits`, затем сервером. Создание загрузки,
запись байтов и публикация имеют отдельные этапы; ключи сохраняются при повторе.
Успех одной загрузки не отменяется ошибкой другой. Фото чата и фото вайба — разные
назначения. Неподтверждённые загрузки не показываются как сообщения. У документа есть
необязательная подпись до 2000 Unicode codepoints; граница сохраняет целые
составные эмодзи. После начала загрузки подпись фиксируется вместе с ключом
публикации, чтобы повтор не менял неизвестный серверный результат. У фото
и альбома поля подписи нет.

Бинарный URL строится из ID встречи/медиа на настроенном API origin. Значения
`download_url` и `thumbnail_url` не могут направить Bearer на другой хост.
Приватные изображения хранятся в памяти экрана; файлы записываются пользователем
через системный экспорт. Публичный аватар Яндекса загружается без Bearer.
Альбом доступен для серверного `period=past`, а не по времени на телефоне.

## Обращения и документы

Форма сохраняет ввод при ошибке. Почта вводится явно, диагностика по умолчанию
отключена; токены, переписка и контакты профиля не прикладываются. Публичный
приём отправляется без Bearer. Повтор неизменённого обращения использует один
`client_request_id` и Idempotency-Key; изменение полей создаёт новый ключ.
Успех и номер показываются только после `status=accepted`.

Помощь и документы доступны также с экрана знакомства. Политика и описание
cookie помечены проектами до заполнения реквизитов оператором. Версия/сборка
берутся из Bundle. Публикация в App Store и реальные подписи этим изменением
не выполняются.

## Проверка

Команды сборки, unit и UI — в `../AGENTS.md`. Дополнительный сценарий
`sh scripts/test-ui.sh experience` проверяет новые экраны, ввод эмодзи, отмену
выбора и крупный текст на уже запущенном симуляторе. Как и остальные сценарии,
он использует отдельный UI target и настоящий Go API, без обходов production.
Результаты текущего изменения находятся в
`../../../openspec/changes/meeting-experience-refresh/ios-verification.md`.

## Сверка дизайна

Нативные компоненты следуют финальному CSS согласованных HTML-макетов:
карточки с плавающими датой/обложкой/аватарами, нижняя навигация, сообщения,
панели меню и эмодзи, профиль, альбом и формы. Нижняя панель есть только в списках встреч/календаре/приглашениях и основном
профиле; внутренние страницы используют Back/Close. В iOS нет web-футера; ссылки
на сервисные страницы находятся обычными строками в профиле. Раскрываемый
блок обложки при создании сохранён по отдельному решению пользователя.

`sh scripts/test-ui.sh design` снимает экраны с общей детерминированной
серверной fixture, `media` проверяет публикацию/полный экран/реакции,
`experience` — профиль, альбом, служебные страницы и реальное принятие
обращения. `ExperienceScreenshot` сохраняет исходные PNG в runner tmp,
а также в xcresult. Это реальные SwiftUI-снимки, а не HTML-прототип.
Для UI отключён автоматический сбор sysdiagnose при сбое; журнал,
accessibility hierarchy, видео и скриншоты XCUITest сохраняются.
