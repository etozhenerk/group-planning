# group-planning

**Somewhere** — сервис для совместного планирования встреч и путешествий
компанией друзей. `group-planning` — постоянное техническое имя репозитория.

## Начало работы

Для инструментов разработки нужен Node.js 22.22.3. Проверенная версия
задана в `.nvmrc`. При использовании nvm:

```sh
nvm use
npm ci
npm run agent:check
```

Пакеты устанавливаются из публичного npm registry по lock-файлу. Node.js
в корне обслуживает инструменты агента. Бэкенд написан на Go, веб — на React +
TypeScript, мобильные приложения — на Swift + SwiftUI и Kotlin + Jetpack Compose.
Интерфейс реализуется в коде каждого клиента, сервер предоставляет данные
и бизнес-операции через общий API. Решение — в
[ADR 0002](docs/architecture/0002-client-ui.md).

## Работа с агентом

Открой корень репозитория как рабочую папку агента. Начни с
[AGENTS.md](AGENTS.md), [контекста продукта](docs/product/overview.md) и
[процесса разработки](docs/workflow.md). Для нового чата достаточно запроса:

> Изучи репозиторий и предложи следующий шаг, перечислив принятые и открытые
> решения. Код пока не меняй.

Фичи с интерфейсом проходят [подготовку UX/UI](docs/design/README.md)
до реализации. [Общие соглашения кода](docs/development.md) и правила
в инструкциях приложений действуют с первого кода, включая прототип.

В проект подключён оригинальный OpenSpec 1.14.3 с семью готовыми навыками,
включая проверку реализации. Они хранятся в `.agents/skills/`.
Для текстов интерфейса и онбординга добавлен проектный
[product-copy-editor](.agents/skills/product-copy-editor/SKILL.md). Он начинает
с потребности читателя и структуры страницы, затем редактирует формулировки.
Семь навыков OpenSpec восстанавливаются или генерируются командой `npm run agent:setup`.
Обновление сгенерированных файлов закреплённой версией — `npm run agent:update`.
После генерации просматривай diff и запускай проверку.

CLI запускается через обёртку проекта:

```sh
npm run --silent openspec -- list --json
npm run --silent openspec -- list --specs --json
```

Обёртка использует локальный профиль из `scripts/openspec-profile.json`.
Состояние CLI хранится в игнорируемой `.cache/openspec/`.

## Что уже работает

- Общие и локальные инструкции агента, навигация по контексту проекта.
- Go-модуль с memory.Store, демонстрацией и тестами атомарности/конкурентности.
- Правила подготовки UX/UI, общие соглашения кода и правила четырёх стеков.
- Стандартный процесс OpenSpec с локальным воспроизводимым набором навыков.
- Проверка конфигурации, версий, навыков, локальных ссылок и структуры OpenSpec.

Подготовлены [макеты общей ленты и пути создания встречи](openspec/changes/gathering-activity-feed/ux.md):
онбординг, личные встречи списком и календарём, форма, приглашение, ответы
друга, сообщения, голосования и задачи.
Покрытие основного пути описано в [journey.md](openspec/changes/gathering-activity-feed/journey.md).
Макеты и тексты v0.7 одобрены пользователем 19 октября 2026 года.
Редакторский навык применён ко всему пакету; онбординг показывает примеры интерфейса.
Сценарий входа и личных встреч — в [entry-home.md](openspec/changes/gathering-activity-feed/entry-home.md).
Новый сгенерированный знак предложен отдельно и пока не утверждён.
Подготовлены [технический план](openspec/changes/gathering-activity-feed/design.md),
[проект API](openspec/changes/gathering-activity-feed/api.md),
[авторизация](openspec/changes/gathering-activity-feed/auth.md) и
[задачи](openspec/changes/gathering-activity-feed/tasks.md) первого рабочего среза.
Для последующих этапов MVP указаны продуктовые условия до начала реализации.

В backend добавлен Go-модуль с mock-хранилищем в памяти для встреч, RSVP и ленты.
Команды проверки и демонстрации — в [backend/README.md](backend/README.md).
База данных и Docker пока не нужны; после перезапуска mock-данные сбрасываются.
Добавлены запускаемый HTTP-сервер, анонимное приглашение,
[OpenAPI и общие fixtures](contracts/README.md), проверки контракта и Go в CI.
Добавлен серверный вход Яндекс ID и собственные web/native сессии, проверенные
с тестовым провайдером. [Настройка OAuth](backend/docs/auth.md) включает вход явно;
реальный цикл Яндекса ещё не пройден и по решению пользователя отложен до конца
разработки. На сервере реализованы создание встречи, личный список, приглашение,
RSVP, настройки, состав и чат. Они проверены через HTTP с тестовым провайдером.
Результаты и ограничения — в
[отчёте серверного среза](openspec/changes/gathering-activity-feed/meetings-verification.md).
Первый веб-срез по v0.7 реализован на React + TypeScript. Проверить его без
регистрации OAuth-приложения можно командой `npm run web:demo`:
[инструкция](frontend/web/README.md). Проверки — `npm run web:check`,
`npm run web:build`, `npm run web:test:e2e`; результаты — в
[отчёте](openspec/changes/gathering-activity-feed/web-verification.md).
Компоненты и функции оформлены через `const`, стиль TS/TSX/CSS и Go
проверяется командами проекта и в CI. Добавлена [основа iOS](frontend/ios/README.md):
SwiftUI, iOS 17, закреплённый Xcode, swift-format и simulator-сборка в отдельном CI.
API, Keychain, онбординг, личный список и создание iOS реализованы;
UI-тесты используют отдельную схему с настоящим Go API. Приглашение, Share,
RSVP, состав, полная лента, отправка, история и настройки организатора iOS
подключены. Далее — проверка мобильного интерфейса и доступности, затем Android.
Реальный вход остаётся отложенным.
Runtime не принимает подставной user ID.
Backend, web, iOS и Android имеют отдельные задачи.
Версии и команды четырёх приложений закреплены. Добавлена
[основа Android](frontend/android/README.md): Compose, minSdk 26, SDK 36,
Gradle wrapper, ktlint, Lint и отдельный CI. Пока она показывает только бренд;
следующий этап — API и состояние, затем согласованные пользовательские экраны.
Открытые решения собраны в [документе](docs/product/open-questions.md).
Это самостоятельный процесс пет-проекта, без AIFF.
