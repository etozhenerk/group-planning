# Независимое исследование

Этот файл — для основного агента. Запускай только по явному запросу человека
на такое исследование. «Проверь фичу», завершение apply, подготовка релиза,
CI и создание/обновление навыка его не запускают. Создание навыка не является
согласием на проход приложения. `allow_implicit_invocation: false` в
`agents/openai.yaml` отключает автоматический выбор Codex.

## Подготовить нейтральную сессию

Уточняй только отсутствующие данные, без которых нельзя начать. Используй
известные URL/сборку и ранее разрешённые тестовые аккаунты. Ambient-вкладка
с макетами сама по себе не задаёт цель: нужен работающий продукт с API.
Не считай production разрешённым для записи только потому, что он доступен.

Бриф сохрани в `.qa-runs/exploratory/<session-id>/brief.md`:

- цель явного запроса пользователя без подсказок об известных багах,
  назначение приложения в одном предложении;
- фактический URL или app/build ID, платформа, устройство, viewport, язык,
  часовой пояс; неизвестное пометь, не выдумывай;
- доступные роли, тестовые аккаунты/данные, безопасный способ входа без секретов
  в тексте брифа; какие изменения и внешние эффекты разрешены;
- область, исключения, бюджет; по умолчанию объяви 30 минут исследования
  суммарно на выбранные платформы, затем оформление отчёта;
- доступные browser/device инструменты и их нейтральные инструкции;
- абсолютные пути папки сессии, инструкции исследователя и шаблона отчёта.

Не включай кейсы, specs, UX/макеты, код, diff, известные дефекты, прошлые
отчёты или подсказки разработчика. Не составляй маршрут из этих материалов.
Подготовка окружения и чтение правил репозитория — твоя задача; не пересылай
их исследователю вместе со ссылками на продуктовые документы.

## Передать независимому исследователю

**Запусти отдельного субагента с `fork_turns: "none"`.** Это явное разрешение
на делегирование при вызове навыка. Передай только бриф и пути
[инструкции](references/explorer.md) и [шаблона](assets/report.md), без этого
оркестрационного файла и истории диалога. Субагенту разрешены чтение этих
материалов, взаимодействие с заявленным UI и запись отчёта/evidence.

Не используй прежнего ревьюера или full-history fork. Если runtime не позволяет
создать свежий контекст, зафиксируй blocked и не подменяй независимость своим
проходом. Это ограничение контекста инструкциями, не файловый sandbox.
При обнаруженном чтении запрещённых материалов сохрани причину и запусти
новую чистую сессию с другим ID и оставшимся общим бюджетом, без прежних
наблюдений; не выдавай загрязнённый проход за независимый.

Не направляй исследователя к подозреваемому багу по ходу сессии. Пользовательские
уточнения области/доступа передавать можно. По бюджету или явной паузе останови
исследование и сохрани частичный отчёт, не продлевай его автоматически.

## Зафиксировать результат и разобрать

Сразу при получении, до запросов на уточнение и разбора, зафиксируй первую
версию `report.md` и evidence: вычисли SHA256 в отдельном `checksums.json`
с относительными путями. Затем проверь реальные ссылки и ограничения отчёта.
Не меняй независимый отчёт под известные ожидания. Ошибку записи исправляй
отдельным `addendum-<номер>.md` с объяснением и собственным checksum;
исходные файлы и прежние checksums сохраняй.

Теперь в отдельном `triage.md` сопоставь ID находок с требованиями, кейсами
и известными дефектами: подтверждено / дубликат / согласованное поведение /
нуждается в уточнении. Не передавай эти выводы обратно в исходное исследование.
Для подтверждённых ошибок предложи регрессию на минимальном достоверном уровне
пирамиды: unit для правил, integration для границ, E2E для сквозного UI-пути.
В уже разрешённой задаче используй `test-spec`; иначе сохрани предложение.

Навык сам не исправляет продукт и не меняет статусы автоматизации/приёмки.
Разрешённые исправления идут отдельным apply с обычными feature-test и
design-review, когда применимы. Отчёт не заменяет qa:ready/release-ready.
Итог: важные наблюдения, проверенные/непроверенные области, ограничения и ссылка
на отчёт. Нет находок — честный результат ограниченной сессии, а не release pass.
Обезличенный итог/evidence сохрани долговременно по
[правилам testing](../../../testing/README.md); приватные данные не коммить.
