# Независимое дизайн-ревью

Прочитай `docs/design/review.md`, manifest изменения, authority и контракты
проверяемых компонентов. Проверь `npm run design:check`. Перед ревью вычисли
текущий hash: `npm run design:context -- --manifest <путь>`.

## Исполнитель

**Запусти отдельного субагента для ревью.** Это явное поручение проекта на
делегирование проверки. Передай ему manifest, опубликованные источники,
запуск/URL или сборку приложения, fixture, окружение, доступные инструменты,
путь отчёта и evidence. Не передавай ожидаемый вердикт, собственную оценку
качества или список подозреваемых ошибок. Модель/effort наследуются по умолчанию.

Поручи только чтение приложения/эталонов и запись отчёта/evidence в указанное
место. Read-only поручение не является технической песочницей: проверь его diff.
Не поручай ревьюеру исправлять код, токены, baseline или объявлять чужую работу
готовой. При недоступном делегировании явно сохрани blocked; собственное ревью
исполнителя не подменяет независимую проверку.

## Ревьюер

1. Прочитай raw-эталоны и последние коррекции. Проверь, что fixture/шрифты/дата/
   размер/состояние совпадают; зафиксируй окружение. Исторические screenshots
   пригодны для предварительных замечаний, но никогда не дают pass текущему UI.
2. На каждой платформе просмотри actual и reference, проверь композицию,
   типографику, интервалы, роли цветов, размеры, переполнение и состояния.
   Прокликай указанные переходы, Back, клавиатуру, ошибки, жесты и motion;
   проверь увеличенный текст, фокус и reduced motion, где применимо.
3. Каждую пару screen/platform/state отметь pass, needs-fixes или blocked.
   Замечание содержит наблюдаемое расхождение, правило/эталон и доказательство.
   Отличай ошибку от платформенной адаптации и вкусового предложения.
   Нет инструмента/данных/живого сценария — blocked, не условный pass.
4. Сохрани отчёт по схеме и evidence с hash. Pass требует actual, reference и
   записи выполненных взаимодействий. Не выдавай pixel regression за успешный,
   если только сохранил картинки; не обновляй baseline из реализации.
5. Верни родителю вердикт, пути и ограничения. Не меняй задачи или приложение.

## Завершение

Родитель проверяет отчёт и допустимые изменения ревьюера. При needs-fixes
исправляет приложение и повторяет независимое ревью; новый hash делает прежний
отчёт устаревшим. Перед отметкой задачи выполненной запускает
`npm run design:ready -- --manifest <путь>`. Не игнорируй отсутствующую платформу.
Явная пауза пользователя прекращает работу; сохрани phase=paused без ложного pass.
Не распространяй это ревью на документационные/серверные правки без UI.
