# Обращения

`POST /api/v1/support/feedback` доступен без входа. Поля и ответ закреплены
в `contracts/openapi.yaml`; клиент показывает успех только после `201` с номером
`SW-…`. При повторе того же UUID и содержимого возвращается прежний номер,
изменённое содержимое с прежним UUID даёт `409`. Номер подтверждает запись,
а не прочтение человеком и не доставку внешнему получателю.

Допускаются описание 10–3000 символов после trim, выбранная тема и экран.
Почта, один PNG/JPEG/WebP до 5 MiB и диагностический блок необязательны.
Вложенные поля проверяются по закрытому списку. Диагностика содержит только
версию, платформу и явно переданные OS/browser/viewport; сервер не подставляет
профиль, сессию, чат, URL или контакт. Неизвестные поля запрещены. Изображение
проверяется по содержимому, ориентируется по EXIF и кодируется заново без
метаданных; WebP преобразуется в PNG. Общий HTTP body ограничен 7 MiB.
Публичного чтения обращения/скриншота нет.

`memory.Support` и `postgres.Support` хранят до 1000 обращений и 50 MiB текста/контактов/
изображений; при заполнении возвращает `503`, сохраняя принятые записи.
Лимит — пять новых обращений за десять минут на хеш адреса соединения.
Повтор уже принятого запроса лимит не расходует. `X-Forwarded-For` не доверяется:
за прокси общий адрес делит один лимит; перед облачным включением нужна
согласованная граница доверенного прокси. Сырые IP не хранятся; временные
счётчики очищаются при новых запросах и фоновым worker. Перезапуск теряет только
локальную memory-очередь. PostgreSQL хранит приём, номер, rate window, lease и
подтверждённые части доставки атомарно; внешние запросы не удерживают транзакцию.

По умолчанию внешняя доставка выключена. Серверный адаптер подготавливается
значениями `SOMEWHERE_SUPPORT_BOT_TOKEN` и `SOMEWHERE_SUPPORT_CHAT_ID`, которые
нельзя помещать в Git или клиентские сборки. Используется только фиксированный
HTTPS endpoint [Telegram Bot API](https://core.telegram.org/bots/api#sendmessage),
без переходов по redirect. Текст отправляется без HTML/Markdown и предпросмотра
ссылок; длинные сообщения делятся без потери Unicode. Картинка передаётся
через [sendDocument](https://core.telegram.org/bots/api#senddocument) с номером
обращения. Подтверждённые части повторно не отправляются при сбое следующей.

Задача доставки получает lease на две минуты; внешние запросы идут за пределами
транзакции с общим дедлайном 30 секунд. Повтор — через 1, 2, 4… минут, максимум
раз в час, максимум 12 автоматических попыток. После исчерпания запись остаётся
в очереди с признаком отказа и кодом `delivery_attempts_exhausted` в журнале;
прикладная операция `RetryDelivery` позволяет оператору возобновить доставку,
не стирая подтверждённые части. Публичного маршрута этой операции нет;
операторский доступ настраивается на облачном этапе. Ошибка не удаляет принятую
запись. Telegram не предоставляет ключ
идемпотентности: при потере ответа или аварии между отправкой и сохранением
подтверждения возможен дубль части. Стабильный номер позволяет его сопоставить;
гарантия exactly-once не заявляется. Логи содержат только код отказа, без
содержимого, почты, скриншота, upstream-ошибки или токена бота.

При `SOMEWHERE_STORAGE=postgres` применяется миграция `008_support_feedback.sql`:
отдельные таблицы обращений и краткоживущих счётчиков, отдельный advisory lock.
`cmd/server` передаёт `db.Support()` в сервер. Обе серверные переменные бота
обязательны для публичного приёма; без них endpoint возвращает `503`, а очистка
существующих записей продолжает работать. Используется уже настроенный бот
владельца; новый бот/канал не создаётся. Конфигурация не появляется в клиентах.

Все обращения — ожидающие, доставленные и исчерпавшие повторы — удаляются
через 30 суток от принятия вместе с текстом, почтой, диагностикой, скриншотом,
номером и прогрессом доставки. Очистка выполняется перед приёмом и при каждом
тике worker, включая отключённую доставку. После удаления прежний ключ уже не
восстанавливает номер. Бэкапы могут сохранять удалённое ещё до 7 дней; срок и
фактическая настройка backup lifecycle проверяются отдельной приёмкой.

Обновление: сначала миграция от DDL-роли и выдача runtime-роли DML на новые
таблицы, затем новый сервер и обе переменные существующего бота. Старый сервер
не поддерживает схему 8; откат на него без совместимого бинарника не заявляется.
Автотесты используют fake delivery/transport и изолированную облачную БД, без
отправки реальным людям. Полная production-доставка и резервное хранение требуют
отдельной проверки точного релиза; локальный pass её не заменяет.
