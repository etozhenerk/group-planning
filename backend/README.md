# Бэкенд Somewhere

На первом этапе используется mock-хранилище в памяти Go-процесса. PostgreSQL,
Docker, SQL-миграции и внешние Go-зависимости не нужны. Версия Go — **1.27.2**,
закреплена в `go.mod`; установить её можно с [go.dev](https://go.dev/dl/).

Из корня репозитория:

```sh
cd backend
go run ./cmd/storage-demo
go test -race ./...
go vet ./...
go build ./...
```

Демонстрация создаёт встречу, ответ друга и две записи ленты; печатает:

```text
Вечер с друзьями: ответов — 1, событий — 2
```

Это демонстрация адаптера хранения. HTTP API, бизнес-операции и вход Яндекс ID
добавляются следующими задачами; команда не открывает сервер и не подменяет вход.

## Устройство

- `internal/meetings` — модели и порт Store, который будут использовать операции встреч.
- `internal/storage/memory` — временный адаптер этого порта.
- `cmd/storage-demo` — явное заполнение вымышленными данными для примера.

`memory.New()` создаёт пустое независимое хранилище. Внутри `Update` прикладная
операция проверяет права и ревизии, затем сохраняет связанные изменения.
Если callback вернул ошибку, context отменён до публикации или произошёл panic,
изменения не публикуются. Все записи одной операции видны вместе.
`View` получает согласованный снимок; конкурентная запись его не меняет.

Полученные значения — копии. Reader/Writer закрываются после callback;
их нельзя сохранять для последующего использования. Внутри `Update` нельзя
вызывать View/Update того же экземпляра или выполнять внешние запросы.
Сетевой обмен и авторизация происходят до входа в атомарное изменение.

Адаптер хранит встречи, одну ссылку приглашения на встречу, RSVP, ленту
и receipts запросов. Он назначает последовательность ленты и проверяет
уникальность записей/запросов, наличие встречи у связанных записей.
Права участников, допустимые бизнес-переходы, TTL, фильтрация и страницы API
должны быть реализованы в прикладных операциях: само хранилище не авторизует пользователя.

## Ограничения временного этапа

Каждый процесс имеет собственное состояние. Перезапуск сбрасывает записи,
в том числе будущие профили и сессии, когда будет добавлен модуль identity.
Сейчас identity ещё не реализован. Несколько независимых mock-процессов
не образуют общий сервер: все три клиента должны обращаться к одному экземпляру API.

Изменение копирует состояние целиком и сериализует записи. Это подходит для
локального прототипа. Постоянное хранение и его SQL-тесты появятся отдельным
этапом; API-контракт при смене адаптера сохраняется. Перенос временных данных
из мока не обещается.

Форматирование без записи: `gofmt -l .` — вывод должен быть пустым.
Исправление форматирования: `gofmt -w .`. Команды и правила — в
[AGENTS.md](AGENTS.md), план — в
[design.md](../openspec/changes/gathering-activity-feed/design.md).
