# Мониторинг somewhere

`dashboards.json` — несекретный каталог пяти панелей с placeholders: обзор,
ВМ, PostgreSQL, эксплуатация и бизнес-показатели.
`render-dashboards.py` создаёт JSON нового Monium с устойчивыми ID графиков:

```sh
python3 infra/monitoring/render-dashboards.py \
  --folder-id FOLDER_ID --instance-id INSTANCE_ID \
  --output-dir infra/local/dashboards
```

В Monium: Дашборды → Создать → Настройки → JSON → Diff «Отключен» → вставить
соответствующий JSON → Применить → Сохранить. Для изменения существующей панели
открывать **её** JSON, не создавать дубликат. Доступ остаётся закрытым аккаунтом.

Terraform provider 0.239.0 при создании через прежний Dashboard API вернул
`expected operation response ... Dashboard, but got ''`; панелей в списке не
появилось. Пять панелей созданы UI; их IDs есть в отчётах развёртывания.
В Terraform state они не включены. Повторять неудачный apply или считать
локальный JSON подтверждением создания нельзя.

Наблюдаемые метки: `project=folder__FOLDER_ID`, `cluster=default`, `service=custom`,
`host=INSTANCE_ID`, диск `vda`, интерфейс `eth0`, mountpoint `/`.
У суммарного CPU отсутствует `cpu`, выбирается через `cpu="-"`.
Не суммировать его с отдельными ядрами. Нормализация к гарантированным 50%:
`200 * UsefulTime / (UsefulTime + IdleTime)`; это диагностическая гостевая
оценка, не тарифная метрика Compute CPU и не измеренная пропускная способность.
Метрики RATE уже приходят в секунду; повторно `rate()` к RX/TX/IOPS не применять.

Старый REST MetricsData API использует **имя до скобок**:
`"sys.filesystem.FreeB"{service="custom",mountpoint="/"}` и folderId в URL.
Новый UI использует `name` внутри селектора. Запросы/формулы проверены по живым
данным. Разрывы данных не заполняются нулём.

## Алерты текущей подготовки

Пять алертов, все значения окна должны нарушать порог; задержка вычисления 30 с.
В обоих случаях отсутствия данных выбран `No data`. Канал Cloud email —
только аккаунт владельца, категории «Мониторинг» и «Биллинг» включены.
Уведомления Alarm/Warning/No data/Error/Ok, повторная отправка «Никогда»:
новое письмо только при изменении статуса. После проверки доставки оценить
необходимость редкого повтора длительных аварий.

| Суффикс ID | Метрика/формула | Warning | Alarm | Окно | Действие |
| --- | --- | --- | --- | --- | --- |
| somewhere-disk-free | FreeB для `/` / 2³⁰ | <3 ГиБ | <2 ГиБ | 5 мин | Копия, оценка роста, увеличение диска |
| somewhere-cpu | Нормализованный CPU | >70% | >90% | 10 мин | Проверить процессы, запросы и I/O; затем масштабирование |
| somewhere-memory | 100 × (MemTotal − MemAvailable) / MemTotal | >80% | >90% | 5 мин | Проверить RSS, OOM, лимиты и нагрузку |
| somewhere-postgres-up | somewhere_postgres_up | <0,9 | <0,5 | 2 мин | Проверить службу/место/журнал, не удалять данные |
| somewhere-backup-age | somewhere_backup_age_seconds / 3600 | >25 ч | >26 ч | 5 мин | Проверить timer, S3, IAM и место; повторить копию |

Полный ID алерта: `folder__FOLDER_ID_СУФФИКС`. Формулы содержатся в соответствующих
панелях. При создании алертов через UI добавить фильтр host для конкретной ВМ,
если в каталог добавляются новые узлы; текущий каталог custom содержит один host.
Пороги стартового диска и окна bootstrap уточняют полный design.md; дополнительные
условия API/worker/I/O, network limit и inode не объявляются реализованными.

Тестовый алерт `somewhere-notification-test`: `0 * postgres_up` дал Alarm,
`4 + 0 * postgres_up` дал Ok. Системные службы не останавливались. После теста
алерт деактивирован. Cloud email показывал **Obsolete**, владелец сообщил,
что письмо не пришло. Доставка **не прошла проверку**; не считать этот канал
достаточным для допуска production. Повторная проверка — отдельный открытый пункт,
обращение в поддержку не отправлять по решению владельца.

Собственный [бот с PNG](../telegram-bot/README.md) создан, токен и личный получатель
настроены. Доставка из облачной функции пока не работает: `telegram transport failed`;
успешная локальная отправка не закрывает облачную проверку. Штатный канал через
`@YandexCloudNotify_bot` также не считается подключённым без проверки владельцем.
HTTPS-probe развёрнут отдельной закрытой Cloud Function с минутным таймером;
результаты и ограничения проверки — в [отчёте](../../openspec/changes/deployment-and-store-release/monitoring-live-verification.md). Grafana остаётся
необязательным расширением, платные ВМ для неё не создавались.

## Границы готовности

Системные, PostgreSQL- и бизнес-метрики поступают раз в минуту. После подключения
probe в custom наблюдалось 470 рядов / 426 имён (25.10.2026), без пользовательских
меток. До добавления API-метрик нужно ограничить системный набор, сохранив общий
предел 500 рядов. В «Обзор» поступают PG, копия и результаты HTTPS-probe.
RPS/p95/5xx/worker также не подключены. Их отсутствие
не равно нормальному состоянию. Логи в Monium/OTel Collector, retention облачных
данных и прогнозный бюджет остаются непроверенными; journald на ВМ ограничен
256 МБ / 14 днями. Ежемесячный лимит Billing 3 950 ₽ активен, 50/80/100% настроены,
автоостановка не включена. По API нет доказательства доставки бюджетного письма.

Полный [каталог метрик](metrics.md) разделяет подключённые источники, готовый код
и план инструментирования API/трафика.
