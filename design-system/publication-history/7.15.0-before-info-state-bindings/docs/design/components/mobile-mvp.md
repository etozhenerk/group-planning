# Мобильный пакет MVP · 6.3.0

Область — iOS/Android и mobile web по действующему useMobileLayout: ширина
меньше740 CSS px либо coarse pointer при высоте не более500px. Desktop
740/1100/1440 сохраняет прежнюю композицию и значения. Этот контракт уточняет
новый мобильный вариант; старые snapshots/evidence не переписываются.

Источники: [UX](../../../openspec/changes/mobile-mvp-design-refresh/ux.md),
[принятые входы](../../../openspec/changes/mobile-mvp-design-refresh/approved-designs.json),
[пакеты и матрицы](../../../openspec/changes/mobile-mvp-design-refresh/preparation/packets.md).
Flow-r1 и карты исключены. Создание и предложение места используют ручной ввод;
provider-ссылку в About не добавляем. Отдельный блок карт явно отложен пользователем.

## Общие элементы

Back — тонкий шеврон component.mobileBack.iconSize/strokeWidth, без видимого
«Назад», постоянного фона/рамки. Контекстное доступное имя и история обязательны.
Hit area — target.web/ios/android, focus только при соответствующем вводе,
pressed/disabled — опубликованные роли. Главные разделы не получают лишнего
Back; дочерний sheet не дублирует Route Back.

Фото — публичный avatar_url через mapping/session/cache во всех местах
идентичности. При отсутствии/ошибке — нейтральный силуэт той же геометрии,
не инициалы и не подставное фото. Приватные поля владельца не копируются
в участников/авторов/читателей. Геометрия — component.mobileAvatar и прежние
роли compact/chat/participants; новый смысл fallback не меняет размер строки.

MobileSheet использует component.mobileSheet и motion.mobileSheet. Одна
активная поверхность, отдельные формы/детали/параметры и возврат фокуса.
Dirty guard защищает ввод, unknown не выдаётся за отмену/успех. Системные
safe area/IME берутся из платформы; рамка Stageshow не задаёт реальные insets.

## Закреплённые области и формы

Только действительно закреплённая область при прокрутке получает новый вид:
снизу и по бокам вплотную к экрану, скруглены только верхние углы,
component.mobileSticky.shadowUpOffset направлен вверх, shadowBlur и
color.mobileStickyShadow. Измеренная высота резервируется в scroll content.
Это относится и к реально fixed нижней навигации новых мобильных композиций;
desktop sidebar и обычные блоки не получают такой стиль.

Короткая форма с действием в потоке не получает подложки/тени/верхних углов.
Overflow пересчитывается после IME/изменения высоты/системного текста.
Общие error/unknown находятся возле действия, полевая ошибка — у поля.
У обязательных полей заметная звёздочка и легенда, label не заменяется
placeholder; invalid/describedBy и первый ошибочный фокус связаны с полем.

## Запуск и знакомство

Native launch: typography.size.mobileLaunchWord44, mark53/gap16 из
component.mobileLaunch. Один оборот360° за motion.duration.mobileLaunch1200ms
по quintic smoothstep, слово неподвижно. Долгое восстановление не повторяет
оборот; resume/recreation не перезапускают вступление. Reduce Motion — угол0.
iOS системная/SwiftUI геометрия совпадает; Android сохраняет прозрачный
system placeholder и рисует полную подпись в Compose вне icon mask.
Web не получает искусственной задержки.

Знакомство — восемь страниц о встречах: композиция r4 и принятые тексты r5,
источник [onboarding-copy.json](../../../openspec/changes/mobile-mvp-design-refresh/preparation/onboarding-copy.json).
Pager использует motion.navigation, локальные иллюстрации — motion.cover,
новый ввод прерывает прежнее доведение. Примеры inert, нет автолистания.
Busy сохраняет геометрию кнопки/футера, без новой кнопки отмены; error/cancelled
позволяют повтор с прежним return context. Прямое приглашение обходит pager,
авторизация не равна RSVP. На низком экране слайд прокручивается над действиями;
постоянный слот статуса последней страницы не накрывает пример.

## Экранные пакеты

- Список/календарь/«Возможно»: один переключатель вида, ровные табы, сохранение
  дня/периода/scroll, 20 встреч без обрезания. Выделение календаря36/radius9
  центрируется в target. Unread footer скрывается при нуле; фото/силуэт едины.
- Создание/приглашение: обложка и черновик, отдельные поля/ошибки/unknown,
  ручное место и права. Закрытый приём не предлагает новые ответы; going
  сохраняет доступ, вход сам не открывает чат.
- Чат/сведения/настройки: угол пузыря к отправителю, реакции внутри пузыря
  без скачка, компактная ошибка с доступными действиями, одна/две галочки
  по подтверждённым данным. Send — target44, circle38/icon20. Все реальные
  outbox/media/PDF/файловые операции и readers сохраняются. Формы настроек,
  даты/времени/обложки/conflict/dirty — отдельные состояния.
- Дата/место/подготовка: пять параметров даты, hidden/anonymous/сроки и разные
  правила большинства сохраняются. Место вводится вручную. Задача требует
  явного принятия; роли/подтверждения/unknown не подменяются анимацией.
- Вайб: физический drag/flick/rollback/cycle, вертикальная прокрутка и
  pointercancel, contain-viewer, стабильные счётчик/переключатель. «Сохранить
  все» едино; реальный export/permission/partial/cancel подтверждается клиентом.
- Профиль/сервис: реальные полные данные, read-only приватная sheet, выход
  последний, удаление скрыто. FAQ сохраняет plus/minus disclosure; обращение
  сохраняет восемь ключей раздела в sheet, файл/unknown и opt-in диагностики.
  About использует реальные метаданные, без повторных ссылок. Reader сохраняет
  полный черновой текст/TOC/позицию/возврат; юридические условия не финализируются.

Движение и доступность адаптируются по platforms.md. Large text, Reduce Motion,
системные Back/Share/сохранение и клавиатура проверяются в каждом клиенте.
Реализация не копирует DOM-адаптеры, iframe или fixture timers макетов.
Публикация не является live-приёмкой: нужны независимые design-review и
feature-test на frozen candidate платформы, design:ready/qa:ready до checkbox.

Код клиентов содержит одну актуальную реализацию. По решению пользователя прежние мобильные экраны и код без потребителей удаляются при переносе; runtime-версий v1/v2 и старых запасных маршрутов нет. Desktop сохраняется в действующей адаптивной компоновке. Исторические материалы проверки не подключаются к приложению.
