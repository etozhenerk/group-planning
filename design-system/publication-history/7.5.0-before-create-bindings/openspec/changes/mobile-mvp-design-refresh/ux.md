## Решения

### Запуск · APPROVED · launch-r1

Прямое решение: «да, оставляем увеличенный вариант с одним оборотом».
Название 44 pt/sp, знак 53 pt/dp, промежуток 16 pt/dp; подпись по центру, знак слева. Графитовый фон и светлый текст сохраняются. Реальный макет: [launch-r1.html](assets/launch-r1.html).

Это одобрение дизайна, не выполненная задача приложения. Прежняя геометрия 37,5/45/13,5 заменяется только на native-заставке; шапки приложения не увеличиваются.

Холодный запуск → та же подпись с одним оборотом за 1200 ms → готовое содержимое после восстановления. Знак сохраняет центр и геометрию; слово неподвижно. Долгий запрос оставляет подпись статичной, без нового оборота/процентов. Возврат из фона не повторяет вступление. Reduce Motion исключает вращение. Нынешняя пауза 1,2 с и правило восстановления не сокращаются этим решением.

Движение — существующий brand quintic smoothstep из branding.md. Новые геометрические роли публикуются перед реализацией. iOS: одинаковый размер системного LaunchScreen и SwiftUI. Android: существующий прозрачный системный placeholder, затем полная Compose-подпись; не помещаем слово в маску app icon. Web не имитирует системный splash и принудительное вступление.

Пояснение и срок сохраняются. При текстовом редактировании выбранные координаты очищаются. Геолокация не запрашивается.

На схеме можно выбрать демонстрационную точку; поиск фильтрует локальные примеры. Подтверждённый объект хранится в модели макета, строка попадает в карточку локального опроса. Полный сквозной wire mapping координат/идентификатора в API ещё не реализован и отдельно поставлен в план. Кнопка подтверждения и выбранное место прилегают к нижнему/боковым краям, имеют только верхнее скругление и тень вверх. Handle/Escape/системный возврат из карты возвращают к форме; вложенная карта не закрывает встречу. Пустой запрос, отсутствие результатов, ошибка/повтор и ручной ввод — разные состояния.

Ритм: панель сохраняет поверхность, меняется содержимое без масштабирования текста; выбор обновляет маркер и нижнее место. После подтверждения возвращается тот же черновик, точка больше не меняется при отмене следующего выбора. Reduce Motion — статично. На iOS/Android планируется настоящий MapKit, на mobile web JS API; schematic preview и рамка телефона в приложение не переносятся.

[Place-r2](assets/place-r2-rejected/index.html) сохранён как отклонённая версия после «пока плохо» / «страшно выглядит всё»: тяжёлая тёмная схема, постоянный список, повтор выбранного места. UI-проход check-map: 320/390/402 без горизонтального переполнения, footer bottom874; 320×600 сохраняет кнопку. ## Вайб r3 · свайпы и обычное действие добавления, 04.11.2026

Уточнение пользователя: оформление sticky-панели допустимо только для элемента, действительно закреплённого при прокрутке. В короткой форме добавления фото для этого нет основания. В r3 кнопка «Добавить в альбом» и связанная ошибка включены в общий прокручиваемый поток формы; отдельные подложка, тень и верхние скругления убраны. Горизонтальная лента выбранных фото остаётся самостоятельной галереей. При ограниченной высоте прокручивается вся форма вместе с действием. Общее правило дополнено в AGENTS.md; принятый стиль настоящих закреплённых панелей не отменён.

Обнаруженные пробелы r2: стопка не обрабатывала горизонтальные wheel-жесты трекпада; полноэкранный просмотр использовал дискретную смену фото на pointerup. В r3 стопка поддерживает pointer/touch/горизонтальный wheel, вертикальную прокрутку и pinch не перехватывает. В просмотре одновременно смещаются текущий и соседний кадры, непосредственно следуя за жестом; отпускание завершает переход260мс или возвращает кадры220мс.
