# Ответ на приглашение · 7.2.0

Прямое решение пользователя 05.11.2026, затем «окаю дизайн». Общее поведение
для desktop web, mobile web, iOS и Android; прежняя промежуточная кнопка
«Открыть встречу» отменена. Композиция остальных desktop-страниц не меняется
этой общей коррекцией; их новые макеты публикуются отдельно как согласованный
дизайн, до реализации соответствующих экранов.

| Подтверждённый ответ | Результат |
| --- | --- |
| Приду | Сразу чат той же встречи |
| Возможно | Список приглашений с этой встречей; уже открытый список остаётся, поверхность ответа закрывается |
| Не смогу | Отдельное подтверждение с названием встречи и «К моим встречам» |

Действует по публичной ссылке и при изменении ответа из приглашений/сведений.
Отказанная встреча не считается приглашением «Возможно» или подтверждённой
личной встречей. Ошибка и неизвестный результат остаются возле действия на
исходной поверхности; нет оптимистического открытия чата или ложного успеха.
Повтор использует действующий контракт идемпотентности/сверки. После успеха
повторная отправка при Back/возврате не нужна; клиент использует подтверждённые
данные, обновляет списки/роль/доступ, не сохраняет устаревшую поверхность ответа.

Вход сам по себе не записывает RSVP. Ранее ответивший «Приду» и организатор
после проверки защищённых данных сразу переходят в чат. Такой переход не
создаёт RSVP или системного события; ошибка роли не превращается в приглашённого.
При закрытом участии новый RSVP не предлагается; существующий доступ сохраняет
обычные проверки. При смене «Приду» на другой ответ переписка закрывается.

## Подтверждение отказа

Заголовок: «Вы ответили «Не смогу»». Ниже название встречи и
«Организатор увидит ваш ответ.». Основное действие: «К моим встречам».
Результат не выглядит ошибкой, не выражает сожалений за пользователя и не
требует дополнительного подтверждения уже сохранённого ответа.

Mobile: шапка и safe area, карточка в потоке с одним действием. Desktop:
ограниченная по ширине карточка и принятая шапка. Sticky-панель не используется.
Роли: color.background/surface/text/muted/action/actionText/accent/line,
radius.card/control и действующие платформенные targets. Новых токенов нет.
При открытии доступен заголовок результата; имя встречи переносится, кнопка
сохраняет доступное имя и область нажатия. Reduce Motion не задерживает результат.

## Системные строки в чате

Серверное изменение ответа показывается компактной системной строкой в общей
хронологии: автор, конкретный ответ, время. Примеры: «Миша ответил «Приду»»,
«Саша ответил «Возможно»», «Дима ответил «Не смогу»». Это не пользовательский
пузырь: нет стороны отправителя, галочек, реакций и дополнительной кнопки.

Событие видят участники с доступом. Ответивший «Возможно»/«Не смогу» не получает
чат ради показа уведомления. Первый отказ не называется присоединением и не
увеличивает подтверждённый состав. Ошибка, локальный выбор, повтор запроса,
reload и повторное открытие ссылки не создают новое событие. Источник — серверная
хронология и её ID/sequence; prototype sessionStorage/DOM adapter в клиент не идут.

## Эталоны и приёмка

- [Desktop-пакет](../desktop-mvp/README.md), invite-r2 и invitations-r2.
- [Мобильная ревизия](../../../openspec/changes/mobile-mvp-design-refresh/assets/response-routing-r1/decision.md).
- Спецификация: mobile-interface, требования «Единый результат ответа на приглашение»
  и «Системные сообщения об ответе в чате».
- Реализация/приёмка: tasks15.2–15.7 и отдельные rsvp-routing manifests трёх платформ.

Приёмка проверяет рабочие клиенты, серверный ответ и события, а не fixture.
Скриншоты/интеракции прототипа не являются design:ready или qa:ready приложений.

Публикация7.1.0 связывает размеры/типографику уже принятого результата с
component.rsvpResult; композиции mobile Declined и desktop DeclinedScreen прежние.

При раннем серверном отзыве доступа до ACK приватная поверхность сразу
закрывается. Owner intent/ошибки/повтора живёт выше неё; публичная поверхность
восстановления использует принятый invite-r3 error/no-cover и реальные публичные
факты. Private cover URL/переписка/состав туда не переносятся. Desktop исходного
приглашения сохраняется; новая шапка относится только к явно принятому отказу.

Шапка нового desktop-результата сохраняет адаптации принятого эталона: padding28/48; при ширине≤1000 —24/32; ≤850 —20/24; при высоте≤780 и ширине>850 —20 по вертикали. Границы опубликованы в component.rsvpResult, без влияния на прежние desktop-экраны.

Ревизия7.3.0 завершает привязку неизменённого InvitationNotice: icon34/gap11/radius11, заголовок13/1.4 и пояснение12/1.5 перед действиями. Runtime error-copy не утверждает, что ответ не изменился при потере ACK. Для desktop сохраняются paragraph margins исторической карточки; закрытая поверхность заменяет только свежие варианты ответа на Status «Участие закрыто»/текущий ответ, без будущей двухколоночной композиции. Нативный sheet сохраняет системное закрытие, без дополнительной стрелки Back.

## Приглашение: loading и unavailable · 7.4.0

Источник — неизменённый invite-r3/source/InvitationPreview и его SkeletonDetails.
Mobile loading сохраняет шапку и показывает скелетон фактов без панели ответа.
Недоступная ссылка: светлая карточка, CloudOff, заголовок «Приглашение недоступно»
и «Повторить загрузку»; повтор заново читает публичный preview и не записывает RSVP.
На native используются системные символы и реальные safe area; ошибка нативного
входа остаётся системным alert. Роли invitationState связывают принятые размеры.
Desktop-композиция этих состояний сохраняется.
