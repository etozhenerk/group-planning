# Контракт Somewhere

[openapi.yaml](openapi.yaml) описывает первый серверный срез: вход,
назначенную встречу, приглашение, RSVP, чат и календарные выборки. Общие примеры находятся
в [fixtures/cases.json](fixtures/cases.json); правила операций —
в [api.md](../openspec/changes/gathering-activity-feed/api.md).

Все описанные маршруты зарегистрированы и имеют `x-implemented: true`.
Это серверная готовность: клиентские приложения и реальный Яндекс ID ещё
не проверены. Подключение реального входа пользователь отложил до конца
разработки. По умолчанию auth выключен: старт даёт 503, приватные операции — 401.
[Настройка OAuth](../backend/docs/auth.md) сохраняется для заключительного этапа.

Публичный preview содержит только разрешённые поля. Без действительной сессии
`my_rsvp: null`, `my_rsvp_revision: "0"`; с ней добавляется только собственный
ответ. Вход не сохраняет RSVP. Приватные детали, состав и лента доступны
организатору и текущему going. Сервер не принимает подставной user ID.

Из корня репозитория с закреплёнными версиями Node.js и Go:

```sh
npm ci
npm run api:check
npm run api:test
```

`api:check` проверяет OpenAPI через Redocly CLI и общие схемы/fixtures через
Ajv 2020-12. Негативные проверки отклоняют приватные поля приглашения,
неверную дату, числовую ревизию и неизвестный ответ RSVP.
`api:test` запускает Go-сценарии HTTP: публичные ответы, вход/сессии,
несколько профилей с созданием встречи, ответом и чатом, календарь и его пагинацию. Статусы, JSON и заголовки
сверяются с контрактом, включая пустые 303/204. Временные captures удаляются;
`GO_BIN` позволяет явно задать путь Go. В тестах используется внедрённый provider,
который недоступен из конфигурации запускаемого сервера.

Fixtures включают неизвестный тип записи и sequence больше безопасного целого JS:
клиенты сохраняют строковое значение и показывают безопасную заглушку.
Дополнительные поля ответа клиент игнорирует; публичный DTO проверяется закрытой
схемой. Тела запросов не допускают неизвестных полей. Успех RSVP имеет RsvpResult,
а конфликт — RsvpSnapshot: ответ может быть null до первого сохранения,
can_access_feed всегда false. Изменение схемы ошибки расширяет допустимый ответ,
успешные DTO сохраняют формат; выпущенных клиентов пока нет.

Валидаторы и их зависимости закреплены в корневом lock-файле.
Основа: [Redocly lint](https://redocly.com/docs/cli/commands/lint),
[Ajv JSON Schema 2020-12](https://ajv.js.org/json-schema.html#draft-2020-12).

## Совместимость приглашений

`InvitationPreview.description` — явно публичное nullable-поле. Профили,
чужие ответы и переписка остаются вне preview. Новые ссылки используют
`/i/` и 22-символьный токен; прежние 43-символьные токены и публичный путь
поддерживаются. Пути JSON API не меняются. Серверные HTML/Open Graph и статическая
картинка обслуживаются web-обработчиком и описаны в [backend README](../backend/README.md).

## Совместимость календаря

Запрос без `period` использует `LegacyMeetingsPage`, с разделом — `CalendarPage`.
`MeetingsPage` объединяет эти варианты. Частичные метаданные календаря
не принимаются за старую страницу: это проверяется отрицательными fixtures.
Новые поля карточки `period` и `local_date` обязательны только в календарной
выборке. Старые клиенты продолжают получать прежнюю форму списка.
`409 calendar_changed` означает повтор загрузки с сохранением выбора пользователя.
