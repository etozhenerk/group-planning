## Проверка доставки

Проверка 18:59–19:11 UTC / 21:59–22:11 МСК использовала отдельный алерт
«somewhere — ТЕСТ доставки, сервер исправен». Production не останавливался.

1. После привязки канала активирован тест с прежней формулой
   `4 + 0 * postgres_up`, временными Warning<6 / Alarm<5, окном 1m.
   UI сначала показал Alarm, затем No data. REST API одновременно подтвердил
   пятнадцать свежих минутных точек `postgres_up=1` и `probe_success=1`.
   Причина расхождения вычисления в UI не установлена; источник исправен.
2. Для независимой проверки транспорта выбран синтетический
   `constant_line(4, 1m)` с явной минутной сеткой, окном 3m и задержкой 30s.
   Это только тестовый сигнал; он не заменяет метрики рабочих алертов.
   Preview подтвердил значение 4 и Ok при <3/<2; <6/<5 дал устойчивый Alarm.
3. После сохранения и активации проверены переходы Alarm → Ok → Alarm.
   Последний статус отправки Telegram и email оставался **Obsolete**.
   Владелец подтвердил: **сообщение не пришло**. Скриншот и ссылка на Monium
   в доставленном сообщении поэтому не проверены.
4. Проверена другая штатная возможность: политика `somewhere-telegram-test`,
   24/7, один Telegram-получатель, нулевая начальная задержка, шаг только
   на первой итерации. Политика временно присоединена только к тестовому алерту,
   выполнен новый переход Ok → Alarm. Статус также **Obsolete**, в её истории
   «Уведомлений не было». Общая лента периодически возвращала
   `Gateway request error`; смена способа не дала подтверждённой доставки.

По [документации Monium](https://yandex.cloud/ru/docs/monium/concepts/alerting/notification-channel)
`Obsolete` означает, что уведомление не отправлено до следующего события.
Это не успешная отправка и не доказательство ошибки именно Telegram.

После проверки возвращены Warning<3 / Alarm<2, UI показал Ok; тест
**деактивирован** (в меню снова доступно «Активировать»). Политика эскалации
отвязана от теста и не используется рабочими правилами. Она оставлена для
диагностики без привязок и назначений по умолчанию. Неработающий собственный
Cloud Function-канал также не подключался.

## Что остаётся заблокировано

Привязка и конфигурация завершены, но **оповещение владельца пока не работает**.
Задачи 3.7 и 3.6 не закрываются по наличию настроек. Доставка биллинга не
проверялась реальным достижением бюджетного порога; включённая категория
не является подтверждением доставки бюджетного уведомления.

На обновлённой [странице инцидента 2136](https://status.yandex.cloud/ru/incidents/2136)
инцидент ещё открыт, среди сервисов есть Monitoring и Monium. Последний
общий апдейт — 16 октября. Связь нашей недоставки с инцидентом не установлена;
[рекомендации](https://yandex.cloud/ru/recommendations) не подтверждают
восстановление отправки уведомлений. В поддержку не писали по решению владельца.

После восстановления облачного пути повторить изолированный тест по
[инструкции](../../../infra/monitoring/README.md), получить подтверждение
Alarm/Ok/No data, изображения и рабочей ссылки. Затем проводить учения
по отказам диска/БД/копии/агента и добавлять алерты HTTPS-probe. Графики
и успешное чтение метрик не заменяют эту приёмку.

## Штатный бот в личном Телемосте

После обсуждения собственного бота проверен готовый **Yandex Cloud Notify**.
Своя бот-платформа требует организацию Яндекс 360; в текущем аккаунте её нет.
Для штатного бота организация и покупка подписки не потребовались: переход
из настроек Yandex Cloud «Яндекс Мессенджер» открыл чат в личном Телемосте,
`/start` получил ответ, код успешно привязал аккаунт к облаку. Токены собственного
бота не выпускались, организация не создавалась, IAM не расширялся.

Создан канал `folder__b1g8siv8ve2si1qp04nm_somewhere-owner-telemost`,
«somewhere — Телемост Яндекса», метод **Cloud Ya.Messenger**, получатель —
владелец, скриншот включён. После обновления страницы Monium предупреждение
о недоступном Мессенджере исчезло. Канал подключён только к изолированному
`somewhere-notification-test`, со всеми пятью статусами и без повторов;
у рабочих правил остались прежние Telegram/email. Каталог `trialChannels`
отдельно отражает экспериментальный канал, не прошедший приёмку доставки.

В 22:31–22:34 МСК включён тест с `constant_line(4, 1m)`, прежним окном 3m
и задержкой 30s. При активном правиле выполнены переходы Alarm → Ok → Alarm.
Вычисление показывает ожидаемые статусы и значение 4, однако отправка
в Телемост остаётся **Obsolete**. В открытом чате виден ответ на `/start`,
а тестовых алертов нет. Работоспособность диалога и успешная привязка
не подтверждают путь Monium → бот. Скриншот и ссылка в сообщении не проверены.
После проверки возвращены пороги <3/<2 и тест деактивирован.

Отсутствие организации не блокирует штатный канал. Дополнительный код и
платный Яндекс 360 для этого варианта не нужны. Причина недоставки Monium
остаётся неустановленной; связь с общим облачным инцидентом не доказана.
В поддержку не обращались. Задача 3.7 остаётся открытой.

Источник привязки: [официальная инструкция Monium](https://yandex.cloud/ru/docs/monium/operations/alert/create-channel).
Ограничения собственной бот-платформы: [документация Яндекс 360](https://yandex.ru/support/yandex-360/business/admin/ru/telemost/bot-platform).
