# Публикация somewhere на iOS и Android

Проверено по публичным источникам 24.10.2026. У пользователя есть Apple-аккаунт,
Google Play Console ещё нет. Страна, тип аккаунта и способ оплаты не проверялись;
для оценки принят сценарий физлица в России. Стоимость — в [смете](cost-estimate.md).

## iOS: существующий Apple-аккаунт

1. Проверить действующее платное членство, команду, роль владельца и срок
   продления. Бесплатного Apple Account для TestFlight/App Store недостаточно.
2. Закрепить Bundle ID. В проекте сейчас `dev.groupplanning.ios`; проверить,
   что он доступен и зарегистрирован в нужной команде, до первого выпуска.
   Добавить приложение в App Store Connect, настроить подпись и provisioning.
3. Настроить production HTTPS-origin, версию/номер сборки и параметры Яндекс ID
   для release-приложения. Серверный client secret в приложение не помещается.
4. Сделать подписанный **device archive** Xcode Release, проверить его и загрузить
   в App Store Connect. Имеющиеся simulator Debug/Release-проверки этого не заменяют.
5. Для друзей использовать внешнюю группу TestFlight: им не нужны роли в команде
   App Store Connect. Первая внешняя сборка проходит beta review; срок сборки —
   до 90 дней. Проверить установку, вход и общую встречу на физических устройствах.
   [TestFlight](https://developer.apple.com/help/app-store-connect/test-a-beta-version/testflight-overview/).
6. Подготовить карточку, скриншоты поддерживаемых устройств, privacy/support URL,
   возрастную анкету, сведения о данных/SDK и шифровании. Включён iPad target —
   проверить его отдельно либо согласовать сужение поддерживаемых устройств.
7. После выполнения условий допуска ниже выбрать сборку, страны распространения
   и отправить на review; первый выпуск сделать вручную после одобрения.
   Ревьюеру нужны рабочий сервер и полноценный способ проверить вход и сценарии.
   [Процесс App Review](https://developer.apple.com/app-store/review/).

Месячной платы за каждое приложение нет; стандартное членство $99/год уже
учтено как ежегодный резерв. Оплаченный текущий период повторно не покупается.
[Apple Developer Program](https://developer.apple.com/programs/).

## Android: Google Play

1. Создать личный аккаунт Play Console на реальные данные владельца, оплатить
   разовый сбор $25 и пройти проверку личности/контактов и требуемую проверку
   Android-устройства. До оплаты проверить доступный способ платежа: российская
   регистрация в официальной таблице разрешена, но приём конкретной карты этим
   не гарантируется. Купленные чужие аккаунты в план не входят.
   [Регистрация](https://support.google.com/googleplay/android-developer/answer/6112435?hl=ru),
   [доступные страны](https://support.google.com/googleplay/android-developer/answer/9306917?hl=en).
2. Закрепить application ID (сейчас `dev.groupplanning.android`), создать upload
   keystore, сохранить резервную копию ключей и настроить release signing.
   Собирать подписанный AAB через Gradle; APK оставить для RuStore/проверки.
3. Настроить Play App Signing. Различать upload certificate и сертификаты
   фактически устанавливаемых APK; зарегистрировать нужные fingerprints в Яндекс ID.
   Для совместимых обновлений из нескольких магазинов заранее определить
   стратегию ключей. Не считать, что Google-generated ключ автоматически
   совпадает с подписью самостоятельно собранного APK.
   [Play App Signing](https://support.google.com/googleplay/android-developer/answer/9842756?hl=en).
4. Проверить действующий target API: с 31.08.2026 новые обычные приложения
   требуют API 36; проект уже задаёт `targetSdk = 36`. Проверка актуальности
   остаётся частью каждого выпуска.
   [Требования API](https://support.google.com/googleplay/android-developer/answer/11926878?hl=en).
5. Заполнить карточку, скриншоты, Data safety, privacy policy, возрастную анкету,
   сведения о рекламе и доступ ревьюера; дать рабочую ссылку удаления аккаунта.
6. Начать с internal testing для проверки release-подписи и входа. Затем для нового
   личного аккаунта провести closed testing: **не менее 12 тестировщиков,
   непрерывно подключённых 14 дней**, после чего подать заявку на production access.
   Это не автоматическое одобрение. Компании из шести друзей недостаточно для
   этого требования, нужны ещё подходящие участники теста.
   [Требования тестирования](https://support.google.com/googleplay/android-developer/answer/14151465?hl=en).
7. После допуска отправить выпуск на review, опубликовать и проверить установку
   именно из магазина, обновление и доступ к production API.

Бесплатные приложения остаются доступны пользователям РФ. Ограничения покупок
и выплат с российскими платёжными реквизитами не следует смешивать с публикацией
бесплатного MVP; будущую монетизацию проектировать отдельно.
[Пользователи РФ](https://support.google.com/googleplay/android-developer/answer/11950272?hl=en),
[выплаты разработчикам](https://support.google.com/googleplay/android-developer/answer/15685001?hl=en).

## Android: RuStore

Параллельный канал для российской аудитории: создать аккаунт физлица через VK ID,
заполнить карточку/документы, загрузить подписанный release APK и отправить на
модерацию. Проверить совместимость подписи обновлений и SDK-входа на устройстве.
Регистрация и публикация бесплатны; подключение монетизации требует отдельной
проверки типа аккаунта и условий. Стандартного требования Google «12/14»
на эту публикацию не переносим.
[Аккаунты](https://www.rustore.ru/developer),
[публикация](https://www.rustore.ru/help/developers/publishing-and-verifying-apps/app-publication).

## Условия допуска, обнаруженные при оценке

| Условие | Что требуется в проекте |
| --- | --- |
| Постоянный сервер | Завершить хранение/очередь группы 14, восстановление и HTTPS; memory.Store не подходит для реальных сохраняемых данных |
| Удаление аккаунта | Отдельные specs/UX/API и проверенный путь в приложении; для Google также web-ресурс запроса удаления. Выход из сессии не заменяет удаление |
| Сторонний вход на iOS | Проверить применимость Apple 4.8 и исключений к выбранным storefronts/договору. Для обычного случая Яндекс ID предполагает необходимость альтернативы с требуемыми свойствами, обычно Sign in with Apple |
| Пользовательский контент | Реализовать согласованный минимум жалоб, блокировок, разбора и обжалования; проверить требования магазина к фильтрации/модерации |
| Приватность и возраст | Документы и анкеты должны соответствовать реальному API, логам и подключённым SDK; возрастная политика пока не определена |
| Доступ ревьюера | Рабочий обычный путь входа и тестовые данные; не переносить QA bypass в production |

Apple: [правила 1.2, 4.8, 5.1.1](https://developer.apple.com/app-store/review/guidelines/).
Есть опубликованное [дополнение для российских разработчиков](https://developer.apple.com/contact/request/download/russian_developer_addendum.pdf)
с ограниченной областью действия; его применимость к конкретному аккаунту,
договору и регионам не установлена. Оно не является автоматическим разрешением
игнорировать текущие правила review. Решение о дополнительном способе входа
сейчас не меняет работу соседнего агента и требует отдельного согласования продукта.
Google: [удаление аккаунта](https://support.google.com/googleplay/android-developer/answer/13327111?hl=ru).
Модерация: [принятые правила проекта](../../../docs/product/trust-and-safety.md).

Новые экраны и тексты здесь не проектируются. Удаление аккаунта, модерация и
возможный второй вход должны получить свои изменения OpenSpec с UX трёх
клиентов и проверкой product-copy-editor. До их готовности публичная публикация
не считается доступной; beta review также может выявить невыполненные требования.

## Сроки и результат

Длительность реализации неизвестна до завершения пользовательских функций,
авторизации и инфраструктуры. Из внешних зависимостей у нового личного Google
аккаунта есть минимум 14 непрерывных дней закрытого тестирования **после**
подключения нужных 12 человек; верификация и review добавляются сверху.
Время Apple/RuStore и доступность облака не гарантируются.

Для каждого канала сохранить отдельно: commit, номер сборки, fingerprint/Team ID
без приватных ключей, результаты устройства, статус review, ссылку на опубликованное
приложение и ограничения. Откат мобильного приложения — остановка дальнейшего
распространения и новая исправленная сборка; backend сохраняет совместимость
с уже установленными версиями.
