# Восстановление существующей копии · 01.11.2026

После отдельного явного согласия владельца выполнена подготовленная
[репетиция](verification-plan.md). Первоначальный отказ automatic reviewer
сохранён в плане; операция повторена только после разрешения конкретной передачи.

**Компонент восстановления PASS:** существующая ежедневная age-копия скачана
из приватного Object Storage на Mac, SHA256 совпал с manifest. Расшифрование
выполнено локально потоком через pinned SSH в новую отдельную marker-guarded БД.
`age` и `pg_restore --exit-on-error` завершились0. Ключ не покидал Mac;
plaintext dump не сохранялся. Production не изменён и не перезапускался.

Восстановлены **28 таблиц**. Количество строк и агрегатный хеш содержимого
каждой таблицы совпали с текущей рабочей БД: различий нет. Совпали все восемь
версий/checksums миграций, владельцы/права таблиц и флаги ролей. Невалидированных
FK нет; runtime не имеет INSERT/UPDATE/DELETE на schema_migrations. Сверка
охватывает сохранённые identity/session/receipt/job/cover/support данные, но
не является реальным OAuth-входом или проверкой всех HTTP-операций на восстановленной БД.

Создание БД → restore → сверка заняли **8.458с**. Возраст выбранной ежедневной
копии на начало проверки — **11.485ч**. Это измерения одной репетиции на уже
подготовленной ВМ, а не доказанный общий RTO при потере сервера/региона или
измеренная величина потери данных при аварии.

Временная БД удалена после проверки name/owner/comment marker,
`remaining_own_restore_db=0`. API PID88760, Caddy3465 и PostgreSQL14970 остались
прежними, NRestarts0, active/running; health/readiness успешны. Значения строк
и архив в Git не сохранялись: [receipt](receipt.json) содержит только metadata,
counts, hashes и ACL; [cleanup](cleanup.txt) — фактическое завершение.

## Остаток исходных задач

Deployment3.4 и gathering14.4 целиком не закрываются этим результатом.
Автоматический ежедневный экспорт на постоянно доступный независимый узел
вне региона ещё не настроен, семь дней retention не прожиты этой репетицией.
Нужны отдельная проверка расписания/свежести экспорта и остальные failure/load/
monitoring сценарии14.4. Выдавать этот component PASS за весь lifecycle нельзя.
