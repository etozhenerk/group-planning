# Репетиция восстановления · 01.11.2026

Связанные критерии: deployment3.4 и gathering14.4. Это отдельный компонент
приёмки; он не закрывает мониторинг, нагрузку или автоматический экспорт.

## Исходное состояние

Через pinned SSH прочитан manifest ежедневной копии:
`database/20261101T030801Z.dump.age`, SHA256
`9e69ba7d52131e5d89b80903df148469a8bfb139feb741ac1ac2cff574a9f753`.
Таймер active, последний запуск01.11.2026 03:07:58UTC, следующий02.11.2026
03:01:52UTC. Размер рабочей БД по read-only запросу31538199байт.
Эти наблюдения не доказывают успешного восстановления.

Ключ age находится только в защищённом локальном `infra/local/backup.agekey`.
Официальный age1.3.2 установлен в игнорируемый каталог инструментов из Go module
с проверкой go.sumdb; приложение и его зависимости не менялись.
Команда расшифрования следует [официальному руководству age](https://github.com/FiloSottile/age#usage)
и [инструкции хоста](../../../../../infra/host/README.md#репетиция-восстановления).

## Подготовленный проход

1. Получить отдельное согласие на существующую зашифрованную production-копию
   в закрытый `infra/local/sdd-restore-20261101.dump.age` на Mac и поток
   расшифрованного архива обратно на существующую ВМ по pinned SSH.
2. Штатным pull-backup.py скачать только объект текущего manifest, проверить
   SHA256. IAM остаётся в памяти; bot/OAuth/SSH/age ключи не передаются.
3. Создать отдельную БД с новым уникальным именем и comment marker, владельцем
   somewhere_migrator без superuser/CREATEDB; запретить PUBLIC CONNECT.
   Существующую somewhere не изменять. Проверить свободное место до создания.
4. Выполнить age decrypt → SSH stdin → pg_restore --exit-on-error.
   Не сохранять plaintext dump, не печатать строки пользовательских таблиц.
5. Зафиксировать длительность, версии миграций/checksums, количество и хеши
   восстановленных таблиц, referential integrity, владельцев и runtime ACL.
   Сравнение с живой БД учитывать как отдельное наблюдение: backup создан раньше,
   поэтому новые записи после03:08UTC не должны давать ложный дефект восстановления.
6. Проверить session/receipt/job/cover данные без вывода их значений. HTTP-вход
   реальным пользователем и его приватная сессия этим не подменяются.
7. Проверить name/owner/marker перед удалением только собственной временной БД.
   Сверить health/readiness и счётчики перезапусков до/после. Зашифрованную копию
   хранить только локально, не добавлять её или ключ в Git.

## Исходный отказ до отдельного согласия

Автоматический reviewer отклонил скачивание: payload может содержать всю
приватную production-БД, а конкретная передача на Mac ещё не была разрешена
явно. Запрос согласия отправлен; на момент отказа скачивания, расшифрования и
создания restore-БД не было. Отказ не обходился другим маршрутом.
Позже владелец разрешил конкретную передачу и репетицию; фактическое успешное
исполнение и cleanup описаны в [отчёте](report.md), исходная диагностика сохранена.

Даже успешный этот проход не означает автоматического ежедневного независимого
экспорта вне региона, полной проверки RPO/RTO при аварии или успешного общего
qa:release-ready. Эти границы сохраняются до собственных доказательств.
