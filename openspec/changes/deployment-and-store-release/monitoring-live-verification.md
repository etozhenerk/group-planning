## Минутная HTTPS-проверка

Из проверенного `monitoring/v0.1.0-rc.3` развёрнута закрытая функция
`d4eq5kamb3hahso52njt`, ACTIVE-версия `d4eh4bj4ks88td83cgta`.
Runtime SA может только записывать метрики; отдельный invoker вызывает одну
функцию. Память 256 МиБ, timeout 30 с, concurrency 1, лимиты по одному
экземпляру/запросу на зону, без provisioned instances.

Два ручных вызова вернули HTTP 200 / `written=true`; REST API подтвердил
девять `somewhere_probe_*`. После этого в 18:29:43 UTC создан таймер
`a1s7n67rcmj53argvhp8`, cron `* * * * ? *`, ACTIVE, один повтор через 10 с.
Без дополнительных ручных вызовов получены результаты в 18:31, 18:32 и 18:33 UTC:
success=1, HTTP 200, полный HTTPS-запрос 50–57 мс; DNS/TCP/TLS/TTFB присутствуют,
срок сертификата около 89,5 дня. Проверка работает вне ВМ приложения.

Terraform: сначала 6 create, затем 1 create для таймера, без изменения/удаления
других ресурсов. Итоговый **полный** plan выполнен: только прежнее несоответствие
async-конфигурации Telegram-функции, других изменений нет; этот plan не применялся.
Текущие лимиты и ресурсы probe сверены с реальным API.

При минутном расписании — 44 640 вызовов за 31 день без повторов.
По [официальному тарифу](https://yandex.cloud/ru/docs/functions/pricing)
free tier составляет 1 млн вызовов и 10 ГБ·ч в месяц. Для 256 МиБ это соответствует
среднему тарифицируемому времени около 3,23 с на запуск при полностью свободном
лимите. Учитывать полное исполнение функции, запись метрик, округление 100 мс,
повторы и другие функции; 50 мс HTTP-запроса не являются её billed duration.
Фактические начисления и длительный профиль пока не подтверждены в Billing.
