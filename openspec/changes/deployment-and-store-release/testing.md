изменения. Пользовательский UI/API и runtime не меняются. Клиентские кейсы,

Для кода 3.9 и других срезов нужны собственные фактические проверки.

## HTTP middleware: локальный срез 3.9

Реализуется закрытый opt-in loopback exporter HTTP API. Это server-only
диагностика, API-контракт и клиентский UI не меняются. Продуктовые кейсы
каталога не заменяются проверками мониторинга.

Проверить на реальном локальном HTTP: взаимоисключающие 2xx/3xx/4xx/429/
5xx/504/deadline/cancel/101, panics и write/flush errors; сохранение
ResponseController/Hijack/FlushError и graceful shutdown; реально прочитанные
байты, cumulative histogram/reset/no-observations, concurrent scrape, bounded
labels и отсутствие приватных URL/UA/query/ID. Непроверенный UA/XFF не даёт
verified_bot/synthetic. Адрес exporter — только numeric loopback; public
origin `/metrics` возвращает 404. Проверить startup conflict и закрытие listener.

Обязательны реальные race/unit/integration, vet/build/architecture/format и
OpenAPI HTTP-проверки, независимый проход отдельного агента. Исходный FAIL
ResponseController.FlushError и исправленный повтор сохранить раздельно.
После переноса patch из private worktree сверить bytes и повторить нужные
проверки интеграции. Отдельный frontend-прогон при неизменном контракте
не доказывает и не требуется для приёмки локального exporter.

Внешние части 3.9 остаются открыты: глобальная cardinality всех источников
не более 500 (исторические 470 не позволяют просто добавить новые 217),
scrape/панели/алерты, Caddy, PG/worker, trusted sources, нагрузка и cloud rollout.
Exporter по умолчанию выключен; production-конфигурация этим срезом не меняется.
