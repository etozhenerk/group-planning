# Оценка размещения и публикации somewhere

Дата проверки: **24 октября 2026 года**, регион Yandex Cloud — Россия.
Это расчёт расходов, а не оплаченный счёт. Развёртывание выбранной конфигурации
в пределах 5 000 ₽/месяц разрешено пользователем 24.10.2026.

## Принятый вариант и доступность облака

24.10.2026 пользователь подтвердил одну обычную непрерываемую ВМ
Intel Ice Lake 2 vCPU 50% / 4 ГБ RAM, SSD **10 ГБ с последующим расширением**:
Go API, web, обработчик задач и PostgreSQL. БД и очередь подключаются только
на заключительном этапе 14 после функциональной проверки на моках.
Принятый бюджет — **5 000 ₽/месяц**, включая домен, ежегодный
резерв Apple и распределённый на первый год взнос Google. Расчёт без резерва —
**3 605,35 ₽/месяц** с базовым мониторингом. Это один узел без автоматического
переключения при отказе. Возможный бот с PNG добавляет около 21,95 ₽/месяц
при допущениях ниже; покупка/реализация бота пока не выполнены.

**Начинать размещение в Yandex Cloud сейчас без проверки доступности нельзя.**
На момент чтения официальной страницы открыт инцидент российского региона
с 11 октября; последняя видимая запись от 16 октября говорит об ограниченном
режиме. Провайдер сообщал о приостановке выдачи дополнительных квот и
рекомендовал альтернативные площадки. Проверить конкретную конфигурацию
в своём аккаунте перед покупкой. Временное освобождение текущих клиентов
от оплаты 8–31 октября не учитывается как постоянная скидка.
Источники: [инцидент](https://status.yandex.cloud/ru/incidents/2136),
[рекомендации провайдера](https://yandex.cloud/ru/recommendations).

Проверка консоли владельца 24.10.2026: для ru-central1-a доступны 2 vCPU
и 16 ГБ RAM; запрос `BC213813091` повысил квоту SSD с 25 до 40 ГБ.
Статических IPv4 доступно 2. Форма создания выбранной ВМ подтверждает
2 793,25 ₽/720 ч с НДС за CPU, RAM, SSD и IP; это совпадает с расчётом ниже.
Квота и заполненная форма ещё не подтверждают выделение ВМ.
Выбран домен `smwhere.ru`; пользователь оформляет его отдельно на Timeweb.

После разрешения пользователя уменьшить диск попытка **20 ГБ в ru-central1-a**
также отклонена. **10 ГБ в ru-central1-d успешно выделены**, ВМ запущена.
CPU и RAM сохранены. Базовая ВМ/SSD/IP — **2 363,41 ₽/720 ч**.
Состояние и проверки — [deployment-verification.md](deployment-verification.md).
На 10 ГБ нельзя заранее обещать размещение БД 2 ГБ вместе со всеми временными
файлами: это предел пилота после проверки свободного места, при необходимости
диск расширяется **до** загрузки данных. Расчёт по тем же ставкам:

По сравнению с первоначальным расчётом 20% CPU и 20 рядов/8 алертов:
доля CPU добавляет 331,20 ₽/месяц, расширенный мониторинг — 19,60 ₽/месяц.
Порог 5 RPS и всплеск 20 RPS остаются целями будущего теста, не результатом;
методика ступенчатого измерения описана в [design.md](design.md).

Бэкапы БД входят в 20 ГБ Object Storage: например, семь ежедневных сжатых
копий до 2 ГБ каждая и остаток под артефакты/обложки. Это бюджетный предел,
а не обещание коэффициента сжатия. Снимки диска — дополнительный быстрый способ
восстановления ОС; они не заменяют согласованную копию БД. Рост копий, версии
объектов и временные файлы тоже оплачиваются. Для защиты от аварии региона
предлагается ежедневная зашифрованная копия на уже имеющийся компьютер владельца;
новое оборудование и отдельное платное внешнее хранилище не включены.
Без такой копии нельзя обещать восстановление при потере доступа ко всему региону.

Web раздаёт Go-сервер за Caddy; платный CDN и отдельный frontend-сервер
не нужны. Для файлов предполагается доступ через API/ВМ, поэтому трафик
пользователей учтён в VPC. Прямая раздача из S3 требует пересчёта его трафика.
Kubernetes, балансировщик, NAT Gateway, Redis, Kafka, Container Registry и
отдельный сервер очереди в конфигурацию не входят. Это сохраняет Monolith First.

## B. Та же небольшая нагрузка, управляемая PostgreSQL

Для снижения ручной работы с БД: сохранить API/web/worker на выбранной
ВМ 2 vCPU 50% / 4 ГБ RAM, SSD 40 ГБ; добавить один закрытый хост PostgreSQL
`s3-c2-m8` (2 vCPU 100%, 8 ГБ RAM)
и 50 ГБ сетевого SSD. Один хост БД также не обеспечивает отказоустойчивость.

| Позиция | Расчёт | ₽/месяц |
| --- | --- | ---: |
| Базовые ресурсы A после расширения SSD до 40 ГБ | В этой оценке B диск уже расширен | 2 985,19 |
| Вычисления PostgreSQL | 720 × (2 × 1,8792 + 8 × 0,5072) | 5 627,52 |
| SSD PostgreSQL | 50 × 720 × 0,0218 | 784,80 |
| **Облако B** | A + один хост БД и его диск | **9 397,51** |

Доплата к A с диском 40 ГБ — 6 412,32 ₽/месяц; к текущему A с 10 ГБ — 6 842,16 ₽/месяц. Предыдущая оценка B предполагала отдельную
уменьшенную ВМ API и диск 20 ГБ; текущая описывает реальный перенос с сохранением
выбранного узла. Уменьшение диска/ресурсов не обещается автоматически. Временные
тестовые окружения, увеличенный экспорт и дополнительные копии при миграции
оцениваются отдельно. Критерии перехода и порядок работ — в design.md.

Публичный IP БД не нужен. Резервные копии Managed PostgreSQL в расчёте остаются
в пределах включённого объёма; превышение оплачивается дополнительно по 0,00307
₽/ГБ·час. Внешний логический экспорт остаётся в S3-бюджете.
[Правила хранения копий](https://yandex.cloud/ru/docs/managed-postgresql/pricing),
[официальные ставки](https://github.com/yandex-cloud/docs/blob/master/md-docs/managed-postgresql/pricing.md).

## C. Оценка роста

ВМ API 2 vCPU **100%** / 4 ГБ RAM и SSD 40 ГБ; два хоста `s3-c2-m8` в разных
зонах, по 50 ГБ SSD; S3 100 ГБ, оплачиваемые снимки 20 ГБ; 300 ГБ исходящего
трафика; 1 000 временных рядов в минуту, 15 ГБ логов и 30 условий алертов. До 10 000 операций
записи / 100 000 чтений S3 остаются в бесплатном объёме. Копии БД — внутри
включённого объёма; превышение пересчитывается.

| Позиция | ₽/месяц |
| --- | ---: |
| ВМ API и её SSD | 3 309,12 |
| Два хоста PostgreSQL и их SSD | 12 824,64 |
| IPv4 | 189,73 |
| S3 и снимки | 308,66 |
| Lockbox и Monium | 171,79 |
| Трафик сверх 100 ГБ | 284,00 |
| **Облако C** | **17 087,95** |

Это оценка масштаба затрат, не готовая HA-архитектура: API всё ещё один,
а региональная авария затрагивает оба хоста БД. Выбор числа реплик и failover
нужно проверить испытанием. Полная HA потребует минимум второго API-узла,
балансировки и отдельного расчёта. Переход к C не привязан автоматически
к числу зарегистрированных пользователей: основание — измеренная нагрузка.

## Что не включено и почему

- Работа разработчика, администратора, модератора, юриста и маркетинг: здесь
  стоимость ресурсов и каналов публикации. Для пилота это работа владельца.
- Новые Mac/iPhone/Android-устройства и интернет: предполагается имеющееся
  оборудование. Аренда Mac и платные CI-runner не заложены.
- CI/CD: выпуск можно собирать на имеющемся компьютере; дополнительные платные
  минуты GitHub Actions — вне сметы до проверки тарифа аккаунта и потребления.
- Платные AI/media moderation API, SMS, почта на домене, карты/геокодирование,
  комиссия посредника для зарубежной оплаты: не выбранные услуги не выдаются за 0 ₽.
  Для публичного запуска стоимость обязательных средств модерации пересчитывается
  после отдельного проектирования по `docs/product/trust-and-safety.md`.
- Продажи и комиссии магазинов: текущий MVP бесплатный, платежей нет. Будущая
  монетизация потребует отдельной экономики и проверки региональных правил.
- Постоянный staging, нагрузочные ВМ, временное окружение восстановления,
  DDoS-фильтрация и платная поддержка не включены в базовое потребление.
  Разовые проверки и небольшие отклонения покрывает резерв; постоянное включение
  новых сервисов требует обновить таблицу.

Таким образом, **5 000 ₽/месяц — принятый бюджет инфраструктуры пилота и всех
трёх магазинов**, при допущениях выше. Он не объявляет публичный продукт готовым
и не оценивает ещё не выбранные коммерческие сервисы будущих функций.
