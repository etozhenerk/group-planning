# Состав Git checkpoint

Коммит сохраняет реализацию web/iOS/Android, test-only fixtures, актуальную
публикацию дизайн-системы, утверждённые входные HTML/ресурсы с исходными hashes,
OpenSpec/cases/manifests, компактные отчёты и план следующей сессии.

Первый широкий staging (6893 файла, около1.9 млн строк) отклонён автоматической
проверкой из-за объёма QA artifacts и риска включить постороннее. Коммит не был
создан. Staging снят без удаления файлов, выбран меньший набор: код и необходимые
дизайн-источники вместо полного payload проверок. Старые несвязанные QA artifacts
не включаются. Все изменения приложений сохранены в меньшем наборе.

Полные screenshots/video/trace, raw logs и исторические пакеты evidence текущей
задачи остаются в этой рабочей папке без изменений и с исходными hashes. В Git
сохраняются тексты отчётов, матрицы и индексы для продолжения; наличие индекса
не означает, что все перечисленные бинарные evidence приложены к коммиту.
Для независимой приёмки нужна эта локальная evidence либо новый фактический
проход, а не условный pass по одному отчёту. Все продуктовые задачи остаются
открытыми, текущие manifests paused. Релиз/деплой этим checkpoint не выполняется.

Второй узкий коммит также отклонён auto-review с запросом доказательства владения
application changes. Audit preparation/checkpoint-ownership.json сверяет исходный
worktree-before.nul и SHA256 inventory: до реализации изменений приложений не было;
181 существующий изменённый файл совпадал с HEAD, 97 файлов приложений созданы
в этой работе, конфликтов0. Raw QA и посторонние QA не staged.

После последней успешной проверки появились параллельные незаписанные
 docs/design/desktop-mvp (их не было в baseline); текущий agent:check сообщает4
отсутствующие ссылки в их history.md. Эти чужие документы не меняются и не
включаются. Их состояние надо согласовать отдельно; прежний успешный
agent:check не объявляется текущим pass.
