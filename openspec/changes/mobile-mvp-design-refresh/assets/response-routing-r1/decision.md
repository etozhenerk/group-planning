# Единый результат RSVP · APPROVED

Решение пользователя 05.11.2026: «Приду» сразу открывает чат; «Возможно» —
список приглашений; «Не смогу» — экран с текстом и кнопкой ко встречам.
«Открыть встречу» лишняя. Правило относится ко всем поверхностям. Дополнение:
не забыть системные сообщения в чате. Итоговое подтверждение: «окаю дизайн,
давай заканчивай и пуш все правки в дизайне».

Контракт — docs/design/components/invitation-response.md. Прежние композиции
принятых экранов сохраняются; отменяется промежуточный результат RSVP.
Ошибка/unknown не ведут дальше до подтверждения. Вход не равен ответу.
Повторное открытие участником/организатором ведёт в чат без нового события.
Системная строка содержит имя, ответ и время; доступ к чату не расширяется.

| Макет | Вход |
| --- | --- |
| Desktop приглашение | /desktop-invite-r2/preview.html?state=ready |
| Desktop список приглашений | /desktop-invitations-r2/preview.html |
| Desktop системные сообщения | /desktop-chat-r4/preview.html?state=responses |
| Mobile сценарий | /response-mobile-r1/preview.html?surface=invite&state=ready |
| Mobile отказ | /response-mobile-r1/preview.html?surface=declined |
| Mobile системные сообщения | /response-mobile-r1/preview.html?surface=chat&state=responses |

Исходники — source/, сборка — build.mts, полученные mobile/*/frame.html и
preview-mobile.html. Мобильная обвязка сохраняет прежние реальные макеты и
добавляет prototype-only adapter ожидания подтверждения fixture. Desktop-исходники
сохранены в docs/design/desktop-mvp; исходная история до коррекции — там же.
Ни адаптер, ни локальные storage/синтетические события не являются кодом приложения.

В браузере проверены: desktop «Приду» → чат, «Возможно» → приглашения,
изменение в списке → «Не смогу» → подтверждение → личный список без отказанной
встречи; mobile «Приду» → чат и «Не смогу» → подтверждение; три системные строки
в mobile/desktop. Сборки макетов воспроизводятся из сохранённых источников.
Это авторская проверка прототипа в IAB, не независимая приёмка клиентов и не
полная матрица устройств. Новые cases manual/unknown, задачи реализации открыты.

Согласованная публикация7.0.0 использует существующие роли без новых токенов;
major нужен из-за смены действующего результата ответа. Прежние отчёты остаются
с прежними hash; переноса pass нет. Дальнейший дизайн на сегодня paused по просьбе
пользователя; продолжение оставшихся desktop-экранов — в следующей сессии.
