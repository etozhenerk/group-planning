# Подготовка короткого Saved/«Приглашения» checkpoint

До явного handoff нового frozen UIhost устройство не используется. Старый bundle/результат не принимается за новый. Только три targeted метода, без матрицы/manifest/gates/архивов.

Источник — approved invitations-r2, ux.md § «Приглашения», design/meetings-ios.json/invitations и общий canonical RSVP contract.

1. Ready: заголовок/счётчик, постоянное пояснение только про «Возможно», дата/название/место/организатор и «Изменить ответ →». Само открытие не меняет Maybe. Going после настоящего подтверждения→чат; Maybe из сведений→приглашения; Decline→подтверждение→личные встречи. После отказа empty ведёт к встречам без повторного абзаца. Контролируемый первый отказ saved fixture обрабатывается как error/retry, не как сохранённый Going.
2. Initial503: цельный MobileStatusView, отдельный «Повторить загрузку» и восстановление карточки. Затем refresh503 с сохранённой карточкой: «Не удалось обновить приглашения»/«Повторить обновление», успешный повтор. Ошибки и payload не выдумываются, используется отдельный memory API.
3. Brief narrow320 и accessibility5: фактические UIWindow/physicalScreen, счётчик и карточки не обрезаны; при AX пояснение находится в scroll и не блокирует доступ к карточке. До нажатия элемент целиком выводится выше bottom navigation.

После handoff — temp runner + проверка точного нового bundle, эти действия, визуальный spot-check против raw, короткий markdown со снимками/actions и освобождение устройства. VO/полные unit/UI/final gates не запускаются. Никаких инфраструктурных работ и переноса старых pass.
