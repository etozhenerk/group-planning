## Why

Следующий этап MVP somewhere — последовательный редизайн существующих мобильных экранов. Решения нужно сохранять рядом с макетами и задачами SDD, чтобы согласованный прототип не терялся и не считался реализованной функцией.

## What Changes

- Прорабатываем экраны по инвентаризации в `ux.md`, начиная с запуска, затем знакомства и входа; каждое следующее решение отдельно согласуется в разговоре.
- Общий объём: iOS, Android и мобильный web. Desktop web не редизайним; общие стили и токены не должны менять его внешний вид и поведение.
- Подтверждена заставка: название 44 pt/sp, знак 53 pt/dp, промежуток 16 pt/dp, знак слева, один оборот 360° за 1,2 с. Это изменение native-заставки; для web не вводим искусственную обязательную задержку или имитацию системного splash.
- Для остальных экранов готовим изолированные мобильные прототипы с `somewhere-motion`/Stageshow и редактурой `product-copy-editor`. Сохраняем текущие предметные правила и путь приглашения; отдельно планируем совместимое расширение данных места для согласованной интеграции карт.
- До переноса каждого одобренного набора в клиент публикуем его токены/контракты/эталоны и manifest. Реализация и независимая приёмка разделены по платформам.

## Capabilities

### New Capabilities

- `product-onboarding`: мобильный вход следующей версии MVP — увеличенная native-заставка и общее знакомство на iOS, Android и mobile web. Продолжает одноимённую capability из активного `gathering-activity-feed`; при архивировании эти требования объединяются, а не образуют второй сценарий входа.

- `meeting-place-picker`: выбор организации/адреса или точки через Яндекс Карты в формах предложения места и создания встречи на iOS/Android/mobile web, с ручным вводом и совместимой передачей координат. Запрос пользователя от 04.11.2026.

### Modified Capabilities

Нет изменений уже архивированных продуктовых спецификаций. Остальные возможности MVP сохраняют действующие требования из активных изменений; их delta specs добавляются только при согласованной смене поведения.

## Impact

- Затронуты `frontend/ios`, `frontend/android`, мобильные композиции `frontend/web`, дизайн-материалы и каталог тестирования.
- На этапе макетов backend, модели и OpenAPI не меняются. Для интеграции Яндекс Карт запланированы расширение данных места и совместимый API; реализация отдельно на backend/web/iOS/Android. Реальные вход и RSVP сохраняют действующие серверные правила.
- Десктоп вне продуктового объёма; узкая web-композиция определяется действующим breakpoint.mobile (740 px). Ширины от 740 px проверяются на отсутствие регрессии.
- Предыдущие активные изменения и их evidence остаются самостоятельными. Этот план не разрешает считать их незавершённые задачи выполненными и не запускает релиз.
- Номер клиентских релизов и полный состав новой версии MVP пока не назначены: базовый объём — редизайн; дополнительно по запросу 04.11.2026 запланирован picker Яндекс Карт, ещё не реализованный.
