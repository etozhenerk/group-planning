## Правила выполнения плана

Текущий запрос apply разрешает реализацию клиентов по опубликованным эталонам и test-spec; деплой/релиз не входят в этот запрос. `approved-designs.json` задаёт источники; поздние явные коррекции из ux.md имеют приоритет. Незавершённый flow-r1 остановлен пользователем и не используется как эталон, приложение или evidence.

Кодовая задача выдаёт кандидата для QA. Её галочка закрывается после независимых design-review и feature-test, а не до них; QA стартует по готовому кандидату, не ожидая галочки кодовой задачи. Не требовать циклической зависимости по checkbox. После фиксации общего кандидата платформы все её приёмки используют один актуальный план/source hash; промежуточные passes не переносятся через изменения кода/контрактов. Старые отчёты сохраняются.
