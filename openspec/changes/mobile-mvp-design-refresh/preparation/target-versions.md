# Целевые версии мобильного редизайна

Решение 06.11.2026 для задачи4.3. Это выбор номеров будущих кандидатов,
не создание тегов, не выпуск и не утверждение готовности артефактов.

| Клиент | Целевой кандидат | Native version | Номер сборки |
| --- | --- | --- | --- |
| mobile web и сохранённый desktop | `web/v0.1.0-rc.16` | неприменимо | фактический номер будущего CI-запуска |
| iOS | `ios/v0.1.0-rc.1` | `0.1.0` | `1` |
| Android | `android/v0.1.0-rc.1` | `0.1.0` | `1` |

Основание: [правило первой линии](../../../../docs/releases.md) задаёт0.1.0;
переход к1.0.0 требует отдельного решения. Пользователь подтвердил, что native
версии ещё не выпускались. Номер42 и0.1.0-rc.2 из макета не используются.

`git ls-remote --tags origin` проверен06.11.2026 в16:20–16:21UTC.
Самый старший занятый web-тег — `web/v0.1.0-rc.15`, commit
`dd9ab2863439e872e716bc1ba811578e5c8cbf07`. Native-тегов нет.
Перед реальным резервированием номера проверяются повторно; занятый тег
не перемещается, следующий кандидат получает следующий RC/build.

Идентичность будущего CI-артефакта: компонент, полный SemVer, неизменяемый тег,
точный commit из чистого `origin/main`, build number и SHA256 файлов из
`manifest.json`/`SHA256SUMS`. Для native магазинный номер остаётся трёхчастным;
полный RC относится к release manifest. Подготовка карточки и публикация тегов
остаются в4.2 после отдельного разрешения выпуска.

Текущая feature-приёмка использует зафиксированные QA/demo-сборки с их
фактическими метаданными и SHA256 из `qa/final/*/candidate.json`.
Они не объявляются подписанными store-кандидатами или уже выпущенными RC.
Правильность отображения доступных/отсутствующих метаданных проверяется
отдельно в12/13; выбор номера не закрывает эти продуктовые проверки.
