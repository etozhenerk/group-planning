# Полноэкранный picker · вход 2.11

Композиция: place-r4/create-r5 с общими коррекциями navigation-r2.
[Производный макет](references/map/frame.html?state=map) показывает оболочку,
поиск/выбор и подтверждение. Рисунок карты и названия заведений демонстрационные;
они не pixel-эталон provider-content и не доказательство интеграции.

Входы: создание встречи и предложение места; владелец формы передаёт
подтверждённый draft и callback подтверждения/отмены. Picker не создаёт встречу,
опрос или RSVP. Он хранит отдельного кандидата, поисковый запрос/поколение,
камеру и состояние загрузки. Закрытие не применяет неподтверждённый выбор.

| Область | Контракт |
| --- | --- |
| Оболочка | Полный viewport, safe area платформы, без sheet handle/скругления всего контейнера/видимого фона встречи. Back: «К созданию встречи» либо «К предложению места» |
| Поиск | Доступное поле/список, loading/results/empty/error раздельно; новое поколение запроса отменяет/игнорирует старый ответ. Выбор не применяет форму до подтверждения |
| Организация | Название, адрес и доступный provider ID/URI из фактического ответа; не выдумывать отсутствующие поля |
| Адрес/точка | Тип явно отличим от организации. Координаты именованные latitude/longitude; без адреса читаемая подпись координат, без вымышленного заведения |
| Подтверждение | Один блок кандидата и «Выбрать это место»; при отсутствии валидного выбора действие недоступно. Обновляет только place/place_location родительского draft |
| Отмена/Back | Исходные название/описание/дата/время/обложка/пояснение/срок/место сохраняются. Системный Back ведёт к форме, не к главному экрану |
| Ручной ввод | Доступен при сбое карты/отказе разрешения. Ручная замена текста очищает неактуальные координаты и provider ID; место создания остаётся необязательным |
| Жесты | Pan/pinch/+/− управляют картой. Pointercancel/вертикальный/краевой жест не закрывают sheet и не подтверждают точку. Нативный экран не использует interactive sheet dismissal |
| Ошибки | Отдельно init/map/search/geocode/limit/offline/нет адреса; повтор без сброса родительской формы. Ошибка не превращается в пустую успешную выдачу |
| Геолокация | Только по отдельному явному действию и системному запросу; отказ не блокирует ручной поиск/выбор |
| Доступность | Список результатов и явные кнопки доступны без pan/pinch. Фокус возвращается к месту родительской формы; большой текст не накрывает подтверждение |
| Движение | Обычный полноэкранный переход клиента; без выезда как sheet. Маркер/кандидат обновляются локально; Reduce Motion без декоративного движения |

Предметные права/revision/idempotency и большинство места после срока
сохраняются. Строковый place совместим со старыми клиентами. Окончательные DTO,
patch/null-clearing, validation и roundtrip задаёт 5.1, проверяя создание,
чтение опроса и применение к встрече. Хранение этапа — memory.Store/мок.

## Provider-content и актуальные входы интеграции

Проверено 04.11.2026 по официальным источникам:

- [JS API](https://yandex.ru/maps-api/docs/js-api/index.html) — web-карта и её интерфейсы; версия/ограничения ключа проверяются при подключении.
- [MapKit iOS](https://yandex.ru/maps-api/docs/mapkit/ios/generated/getting_started.html) и [Android](https://yandex.ru/maps-api/docs/mapkit/android/generated/getting_started.html) требуют API-ключ. Поиск/геокодирование входят в full-вариант, lite не заменяет весь сценарий.
- [Условия сервисов](https://yandex.ru/legal/maps_api/ru), разделы 4–5: нельзя перекрывать фирменные элементы/атрибуцию; нужны «Открыть в Картах» и ссылка на условия в native-разделе сведений. Длительное хранение полученных данных не следует считать автоматически разрешённым: описанное исключение временного cache ограничено 30 днями.

Применение: оболочка резервирует место под фактические controls/атрибуцию,
не перекрашивает логотип и не перекрывает нижней панелью условия/масштаб.
Шрифт/геометрия дорог, POI и подписи провайдера исключены из pixel-сравнения;
доступность/видимость controls, выбор и данные проверяются функционально.

Перед реальным подключением нужны разрешённые ключи web/native с domain и
bundle/package ограничениями и подходящий режим использования данных места.
Ключей/договора этот документ не создаёт и покупку не разрешает. Долгое хранение
provider-derived названия/адреса/координат в истории встречи требует проверки
доступного договора; нельзя молча сократить продукт до 30 дней или заменить
реальную карту рисунком.

Финальный вид provider controls и native-ссылка условий отличаются от
вымышленной схемы/старого about-r2. При подключении — конкретный обновлённый
макет → отсутствующее решение пользователя → revisions/design-system-publish
→ реализация → новый независимый review. Текущий пакет фиксирует оболочку и
эту границу; не объявляет ещё не показанный provider UI утверждённым.

Матрица структурных/ошибочных/жестовых состояний трёх клиентов —
[picker.json](picker.json). Реальные SDK/поиск/атрибуция и обе родительские
формы требуют live evidence задач 5/8/10. Отсутствие ключа/доступа — blocked.
