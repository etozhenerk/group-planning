# Следующая ревизия после независимой приёмки R1

R1 сохранён без изменений: design6.2.0/meetings-web-r1 и feature-meetings-web-r1.
Продуктовые задачи7.1/7.4 открыты. Визуальный отчёт содержит60 pass,
51 needs-fixes и12 blocked; функциональный проход97 pass,1 failed,6 blocked.
Результаты нельзя переносить на новый hash.

Исправления по действующему дизайну:
- F1: desktop-фоны CalendarDay ограничены data-mobile=false; мобильная
  подложка остаётся только36×36 псевдоэлементом. Цвет selected сохранён.
- WebKit: выходной определяется ISO-днём недели в timezone встречи,
  а не регистром локализованного названия. Семь unit-кейсов включают границу дня.
- Desktop-валидация создания снова проходит через прежний draftInput;
  ранний выход с полевыми сообщениями применяется на mobile. Старый alert
  на desktop и отсутствие POST проверены штатным E2E.
- Проверки пустого списка и календарной ошибки обновлены по утверждённым
  мобильным состояниям; отсутствие прежних карточек после403/смены периода
  по-прежнему проверяется.
- Переполнение skeleton408 при320 воспроизведено по кадрам: matchMedia уже
  true, React data-mobile=false до первого rAF. Сетка ограничена одной колонкой
  сразу CSS-условием; ожидание/таймаут в прежнюю проверку не добавлены.
  breakpoint читается из generated foundation-токена на этапе PostCSS.

F2 (компактный экран «Ваш ответ») ещё реализуется. Это отдельный контекст
открытия из списка приглашений, не копия публичного приглашения и не v1/v2.
Карточка должна использоваться из того же pages/invitations slice; перенос
её CSS в другой слой и новые literal-исключения не требуются.

Окружение R2: новый opt-in SOMEWHERE_BROWSER_MEETINGS=1 требует DESIGN=1,
добавляет настоящую legacy-встречу «Поход» с обоими отсутствующими датами,
GET/POST /__test/meetings-clock и POST /__test/run-transition. Только Go test
binary, без production route/env и без ослабления create/PATCH API.
Identity использует реальное время; часы meetings отделены. Автоматический
transition-worker в этом режиме ждёт завершения процесса, а ручной вызов
выполняет настоящий ClaimTransition/CompleteTransition. Read/realtime включаются
своими существующими opt-in флагами. Unit подтвердил сохранение upcoming
после смены времени и past только после worker, повтор не исполняет job снова.

Старый fixture без этих флагов и native-клиенты сохраняют прежнюю обвязку.
Карта и VoiceOver не входят в текущий проход по решению пользователя.
