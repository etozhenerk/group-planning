# Проверка навыка и процесса

Продуктовое поведение не меняется: test-spec фиксирует неприменимость
пользовательских case/platform mapping, feature-test, design-review и релизного
прогона. Изменение регистрируется как nonProduct/nonUi, его spec — excludedSource
с причиной. Никакие существующие продуктовые cases и статусы не меняются.

Риски: самопроизвольный запуск, передача кейсов исследователю, фиктивное runtime
evidence, автопочинка, потеря нерегулярного наблюдения, смешение отчёта и приёмки.

| Проверка | Метод и ожидаемое наблюдение |
| --- | --- |
| Политика вызова | Валидатор навыка; agent:check отклоняет отсутствующий/true/строковый implicit flag |
| Нейтральный запуск | Независимый агент на синтетическом запросе формирует ограниченный бриф без корпуса продукта |
| Границы задач | Запросы «проверь фичу», «готовь релиз», «создай навык» не запускают исследование |
| Доказательства | Синтетические UI-наблюдения дают отчёт с неопределённостью/1 из 3, без выдуманных скриншотов |
| Ограничения | Недоступная платформа остаётся blocked; zero findings не превращается в release pass |
| Интеграция | agent:check, qa:check, qa:test, design:check и git diff --check |

Независимая проверка использует только навык и вымышленные задания в `/tmp`,
без доступа к живому приложению, браузеру пользователя или его данным.
Это оценка инструкций, не продуктовый exploratory run. Результат и ограничения
сохраняются в verification.md изменения.

Пирамида: для metadata — детерминированная проверка структуры; для многошагового
решения агента — ограниченная синтетическая оценка. Новые продуктовые E2E не нужны.
В будущем подтверждённые находки превращаются в unit/integration/небольшой E2E
по минимальному уровню, который достоверно ловит дефект, после независимого отчёта.
