# Proposal

## Why

Приёмка по известным кейсам не ищет все неожиданные сочетания действий.
Нужен независимый исследователь, который узнаёт приложение через интерфейс,
не наследуя ожидания разработчика и существующих тестов.

## What Changes

- Проектный навык `exploratory-test`, запускаемый только по явной просьбе
  пользователя; автоматический выбор отключён в метаданных Codex.
- Свежий субагент без истории разработки, кейсов, specs, макетов и исходников;
  ограниченный бриф, адаптивное исследование web/iOS/Android и отчёт с evidence.
- Отдельные категории дефектов, нерегулярных наблюдений, неудобств и вопросов;
  без квоты находок и без автоматического исправления приложения.
- Разбор основным агентом после фиксации отчёта, с последующим регрессионным
  покрытием подтверждённых ошибок на подходящем уровне пирамиды.
- Документация SDD и проверка обязательной политики вызова навыка.

## Capabilities

### New Capabilities

- `exploratory-testing`: независимое исследование работающего интерфейса
  по запросу пользователя и передача наблюдений на последующий разбор.

### Modified Capabilities

Нет. Обязательные feature/release/design gates сохраняются.

## Impact

Затронуты инструкции агента, `.agents/skills`, `testing`, `openspec/config.yaml`
и проверка обвязки. Backend, API, данные и интерфейсы web/iOS/Android не меняются;
UX/UI-материалы неприменимы. Новые зависимости не нужны. Создание навыка
не запускает исследование приложения; проверяем его на синтетических заданиях.
