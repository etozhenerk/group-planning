# Проверка инструментов приёмки

Продуктовый UI/API этой задачей не меняется. Основная проверка — unit/integration
инструментов каталога, выбора полного набора и gates. Проверяем потерю кейса,
неполное покрытие платформ, stale inputs, изменение артефакта/evidence, ложную
автоматизацию, checkbox без pass, несовпадающую личность проверяющего и отсутствие
доказательств. CLI проверяется на временных fixture-репозиториях.

Реальный функциональный пилот использует существующий web E2E и изолированный
Go fixture. Native/runtime OAuth требуют доступных инструментов; чужие
симуляторы/эмуляторы и пользовательское демо не перезапускаются. Этот пилот
не заменяет приёмку store-сборок. Доступность и фактический результат сохраняются
в verification.md. Для новых навыков — независимый read-only пробный проход
с записью только временных отчётов.
