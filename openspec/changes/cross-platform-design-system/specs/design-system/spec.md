# Spec Delta

## Purpose

Даёт разработчикам всех клиентов somewhere единый проверяемый источник
утверждённых значений, компонентов и правил адаптации интерфейса.

## ADDED Requirements

### Requirement: Published design authority
Система MUST связывать каждую публикацию с решением пользователя, версией,
эталонами, состояниями и явно перечисленными платформенными отличиями.
Последующая подтверждённая коррекция MUST иметь приоритет над старым изображением.

#### Scenario: Correction supersedes a mockup
- **WHEN** пользователь заменил мобильную страницу нижней панелью
- **THEN** публикация отмечает старую оболочку как отменённую и проверка не принимает её как актуальный эталон

### Requirement: Shared tokens
Клиенты MUST получать цвета, типографику, размеры, интервалы и движение
из единого версионного источника с проверяемой генерацией. Платформенные
единицы и различия MUST быть заданы явно.

#### Scenario: Reproducible generation
- **WHEN** источник не менялся и генерация запущена повторно
- **THEN** результаты для web, iOS, Android и каталог совпадают побайтно

#### Scenario: Invalid source
- **WHEN** токен ссылается на отсутствующее значение, содержит цикл или неподдерживаемый тип
- **THEN** проверка завершается ошибкой до обновления клиентских файлов

### Requirement: Controlled evolution
Новые UI-значения MUST использовать опубликованные токены либо обоснованное
утверждённое исключение. Существующий долг MUST иметь явный инвентарь;
он не разрешает добавлять новые расхождения или считать старые проверенными.

#### Scenario: New literal
- **WHEN** разработчик вводит новый цвет или размер в контролируемом UI-коде
- **THEN** проверка отклоняет его и указывает файл, значение и путь публикации токена

#### Scenario: Component contract
- **WHEN** разработчик переносит карточку встречи на другую платформу
- **THEN** он получает состав, состояния, поведение, токены и допустимые адаптации, а не только палитру
