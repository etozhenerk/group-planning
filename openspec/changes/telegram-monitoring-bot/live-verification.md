# Подключение Telegram — 25.10.2026

## Release and configuration

Владелец создал `@somewhere_alerts_bot`, нажал Start и разрешил отправку в свой
личный чат. Получатель получен из единственного private `/start`; chat ID
хранится только в игнорируемой локальной конфигурации и runtime environment.
Токен загружен в Lockbox вне Terraform state и не хранится в репозитории.

Функция: `somewhere-mvp-telegram`, ID `d4ekh3a1pg1nmo70qu90`.
Runtime и invoker — разные service accounts. Runtime читает метрики каталога
и payload одного секрета. Invoker имеет только права просмотра/вызова этой
функции. Публичных IAM-bindings нет. Лимиты: 128 МБ, 35 с, concurrency 1,
zone instances/requests 1, без provisioned instances. Async retry 1 запланирован,
но асинхронная версия ещё не создана.
Используется стандартное журналирование функции; код не пишет токен, event или URL Telegram.

## Deployment findings

- `monitoring/v0.1.0-rc.1` успешно собран в CI, но настоящий Cloud Functions
  builder запускает `go get`, игнорирующий vendor. Сборка остановилась по
  timeout `proxy.golang.org`; работающий деплой RC1 не заявляется.
- `monitoring/v0.1.0-rc.2` исправляет упаковку: зависимости поставляются как
  локальные replacement-модули, в корневом `go.mod` архива нет `go`/`toolchain`.
  Пакет проверен офлайн с пустым module cache на Go 1.27.2 и 1.23.12;
  SHA-256 в обоих случаях `51969732c55503a1e4692609d1da40f70aff190d753466022eceaa3f902bc73d`.
- RC2 прошёл загрузку зависимостей в облаке, но сборщик потребовал
  `package main` для `-buildmode=plugin`. Исправление RC3 переводит оба entrypoint
  в main и добавляет реальную plugin-сборку с тегом `ycf` в упаковку. Локально
  прошли format/vet/race/build, Go 1.23 tests и offline plugin package; SHA-256
  `f70c031b8ddeaba82354cfc1e6d8f6e415dc5c53cac0a591544a68c5c74e0dc3`.
- Provider Yandex 0.239.0 перезаписывает `log_options.folder_id` пустым
  `log_group_id`, поэтому явный каталог в этом блоке не используется. Это не устранило
  отдельный отказ авторизации асинхронной версии.
  Блок `log_options` больше не передаётся, сохраняется стандартное журналирование.
  Отдельная лог-группа не создана: Cloud Logging закрыт для новых клиентов
  с 22.10.2026, API отвечает Unavailable. Используется переход на Monium.
  Дополнительные широкие IAM-роли для обхода не выдавались.
- Provider может оставить объект без версии и выдать warning. После apply
  требуется проверить новый ACTIVE version ID и реальный вызов. Postcondition
  по version ID не используется: provider сохраняет старое значение на стадии
  plan и такая проверка блокирует исправление объекта без версии.
- Terraform validate и восемь mock-тестов прошли; они не доказывают доставку.

## Live status

`monitoring/v0.1.0-rc.3` опубликован в GitHub, скачан и проверен по manifest,
commit и SHA256SUMS. Terraform создал ACTIVE-версию
`d4epeleofou6ve3sh0il` с тегами `production` и `$latest`.
Реальный API подтверждает лимиты по 1 для обоих тегов; запрос без авторизации
получил HTTP 403. Первый read Terraform вернул version=null сразу после сборки,
поэтому версия дополнительно проверена CLI. Это не ошибка компиляции RC3.

Синхронный вызов проходит metadata и Lockbox, но завершается HTTP 502 с безопасной
ошибкой `telegram transport failed`. Независимая проверка с ВМ: HTTPS к GitHub
и Яндексу успешен, IPv4 TCP 443 к `api.telegram.org` (`149.154.166.110`) — timeout.
Локально тот же DNS-адрес отвечает успешно. Причина недоступности из облака
не установлена; это не доказательство глобального сбоя Telegram или Yandex.

Контрольная отправка **с компьютера**, с использованием кода релиза и актуальных
метрик Monium, успешна: Telegram API принял PNG с 59 реальными измерениями CPU
за час и кнопкой на согласованный Monium dashboard. Подпись прямо сообщает,
что это локальная проверка, а облачный канал ещё настраивается. PNG проверен
визуально. Это подтверждает токен, получателя, график и ссылку, но не автоматические
уведомления из Cloud Functions. Временная локальная копия токена удалена после
проверки; секрет остаётся в Lockbox.

## Remaining blockers

1. Создание асинхронной версии с отдельным invoker возвращает PermissionDenied
   через Terraform и REST. Временная роль `functions.viewer` на каталог была
   отдельно разрешена владельцем, проверена после распространения IAM и не
   помогла; binding удалён, возврат к узким правам подтверждён API.
   `functions.functionInvoker` на весь каталог не выдавался.
   Последний request ID: `bcb13877-57c6-46f9-862f-85ef8fe6bab3`.
   Локальный план по-прежнему описывает желаемый async; успешный apply с warning
   не означает, что эта версия выпущена. Перед следующим apply перечитать версии.
2. Нужно восстановить HTTPS-доступ к официальному Telegram API из среды бота.
   Произвольные сторонние прокси и передача им токена не настраивались.
3. Канал Monium подготовлен в форме, но не сохранён и не присоединён к алертам.
   После устранения первых двух пунктов проверить реальную цепочку Monium →
   функция → Telegram и контролируемые Alarm/OK/No data.
4. Отказ ВМ/БД и независимый канал ошибки самого уведомителя ещё не проверены.
   Email-канал существует, получение письма владельцем пока не подтверждено.
5. Probe не подключён: DNS, HTTPS и рабочий `/readyz` ещё не готовы.

Задача 3.1 остаётся открытой. В поддержку сообщения не отправлялись.
