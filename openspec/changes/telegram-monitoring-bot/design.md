# Design

## Context

Основа: [проект бота](../deployment-and-store-release/design.md), пять живых
алертов и [панели](../../../infra/monitoring/README.md). Email ещё не прошёл
проверку доставки. Бот не заменяет независимый штатный канал мониторинга.
Пользователь 25.10.2026 разрешил код и документацию; токен/чат пока не заданы.

## Goals / Non-Goals

**Goals:** код, локальные интеграционные тесты, PNG, каталог метрик и воспроизводимый
архив функции, инструкция IAM/Lockbox/канала и отключения.

**Non-Goals:** команды Telegram, публичный webhook, пользовательские уведомления,
Grafana, реализация API-метрик, автоматическая покупка/создание бота в BotFather.
Backend/web/iOS/Android не меняются, клиентский UX/UI неприменим. Техническое
сообщение описано ниже и проверяется тестовым PNG.

## Decisions

- Самостоятельный Go-модуль `infra/telegram-bot`, а не область предметного backend:
  отказ VM/API/PG не должен остановить диагностику. Это эксплуатационный инструмент,
  не выделение продуктового микросервиса. `internal/notify` — проверка/оркестрация,
  `internal/cloud` — metadata/Lockbox/Monium, `internal/telegram` — отправка,
  `internal/chart` — PNG. `handler.go` связывает зависимости на каждый вызов.
- Runtime `golang123` по официальному каталогу Cloud Functions; module Go 1.23.0.
  Локальные инструменты Go 1.27.2 как в репозитории; совместимость проверяется
  также Go 1.23.12. Рисование стандартным image/png, шрифт Go Regular через
  golang.org/x/image v0.24.0, без браузера или внешнего renderer.
  Source ZIP содержит выбранные vendor-пакеты как локальные replacement-модули:
  облачный `go get` должен работать без внешнего proxy. Корневые `go`/`toolchain`
  удаляются только из архива по требованиям Yandex к версии плагина. Упаковка
  проверяет загрузку зависимостей с пустым кешем и отключённой сетью Go.
- Вход — документированный JSON Monium. Доверять только alert ID из локального
  каталога, известному статусу, пустому или совпадающему folderId; проверять
  host/environment при наличии. Не пересылать alertName/annotations/произвольные
  labels. Конфигурация задаёт folder, VM, production, chat, secret ID и панели.
- Фиксированные HTTPS endpoints, запрет редиректов, ограниченные размеры ответов
  и дедлайны; metadata только фиксированный link-local URL без proxy.
  IAM живёт в памяти, Lockbox current читается на каждом вызове: ротация токена
  не требует хранения его в исходниках или state. Ошибки не содержат URL/токен/body.
- История 60 мин, шаг 60 с, ровно один ряд, NULL без подстановки нуля;
  устаревшие данные >3 мин подписываются явно. Значение в подписи — последнее
  наблюдение со временем, не якобы значение срабатывания. Событие без доверенного
  timestamp подписывается временем получения в UTC; exactly-once нет.
- Сообщение: somewhere, статус, правило, узел, значение/время, Warning/Alarm,
  окно, время получения, alert ID, первое действие; кнопка на закрытую панель.
  PNG 1200×700 ≤1 МиБ, caption ≤900 UTF-16 единиц. Пропуски не соединять линией.
  При отсутствии/сбое истории или рендера — текст с безопасной причиной.
- Telegram: не более трёх попыток суммарно, общий дедлайн вызова 30 с;
  429 учитывает retry_after, ожидание >5 с отдаётся как ошибка для ограниченного
  async retry. При 5xx/сети ограниченный backoff. Не переключаться на текст после
  неоднозначной сетевой ошибки sendPhoto: фото могло быть доставлено.
- Параллелизм экземпляра 1, async retries 1; лимиты zone-instances/requests — 1
  на зону, provisioned instances — 0. Это не глобальный mutex: Telegram может
  вернуть 429, повтор ограничен кодом. Retention async-событий проверить при
  подключении; TTL 120 с не заявляется доступной настройкой CLI. Локальные
  20 конкурентных событий проверяют отсутствие гонок и ограничение попыток.
  Между успешными вызовами нет памяти дедупликации.
- В репозитории каталог запросов, конфиг-пример, fixture, сборка и CI. Операционная
  документация метрик — `infra/monitoring/metrics.md`; ещё не подключённые RPS/
  percentile/bot-классы помечены планом, не используются для ложных live-алертов.

## Risks / Trade-offs

- Cloud Functions и Monium в одном регионе: региональный отказ не покрывается.
- Telegram может принять запрос, но ответ потеряться: повтор может дублировать
  сообщение. Ограничение попыток важнее недостижимого exactly-once.
- Тесты с fake HTTP не доказывают живую доставку, IAM и совместимость payload
  текущего аккаунта. Эти проверки остаются отдельной задачей подключения.
- Счётчики результата handler/журнал и errors функции наблюдаются независимым
  каналом; не создавать рекурсивный алерт, отправляемый только этим ботом.
