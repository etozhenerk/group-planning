## Статус и границы

25.10.2026 пользователь согласовал весь итоговый дизайн-пакет («окаю все»),
включая карточки и календарь, чат, профиль, вайбы, форму обращения, футер,
читаемую подпись версии и проекты политики/cookie. Этот вариант — согласованный
эталон для реализации. Реквизиты и окончательные юридические условия документов
остаются отложенными по договорённости; одобрен их дизайн, не готовность к публикации.
Реализация API и трёх клиентов ведётся по этому пакету с отдельной проверкой
поведения и визуального совпадения. [Все макеты](assets/index.html), [требования](proposal.md),
[план реализации](tasks.md), [проверки](design-verification.md).

### Ревизия мобильных действий · 27.10.2026

Решение пользователя от 26.10 о нижних панелях перенесено в реальные
[HTML-макеты](assets/revisions/2026-10-27-chat-sheets/index.html),
а происхождение содержимого и значений записано в
[описании ревизии](assets/revisions/2026-10-27-chat-sheets/README.md).
Для покрытых форм эта ревизия заменяет мобильную полностраничную оболочку raw
`action-*.html`, `upload*.html`, `share*.html` и `meeting-details.html`.
На момент 1.2.0 desktop сохранял исходную композицию; в 2.0.0 она заменена модалками действий. Старые файлы и отчёты остаются историей.

Панели открываются поверх того же чата; заголовок и крестик доступны при
прокрутке содержимого. В сведениях нет сервисных пунктов. Возврат из приглашения
восстанавливает сведения, затем чат. Меню, альбом и просмотр фото сохраняют
прежние режимы. Упрощённый макет даты не заменяет полную форму нескольких дат.
Непокрытые макетом подробности задачи, настройки и список поставивших реакцию
явно перечислены в описании ревизии; их нельзя объявить принятыми по снимкам
текущей реализации. Они остаются в общей матрице проверки.

Лишняя помощь поверх мобильного онбординга — ошибка приложения против прежнего
эталона, поэтому его дизайн не меняется ради совпадения с ошибочной реализацией.

Дополнение сведений опубликовано после проверки 27.10.2026 в дизайн-системе
1.2.0: [организатор](assets/revisions/2026-10-27-chat-sheets/meeting-participants-organizer.html),
[участник](assets/revisions/2026-10-27-chat-sheets/meeting-participants-member.html).
Компактный состав раскрывается и сворачивается в прежней панели; настройки
и собственный ответ доступны независимо от раскрытия. Проверены обе роли,
четыре основные ширины и настоящий viewport 320/390 × 430, возврат фокуса,
переход в приглашение и сохранение черновика статичного макета. Результат —
[проверка эталонов](assets/revisions/2026-10-27-chat-sheets/render-participants/inspection.md);
это не приёмка живого приложения. Остальные отмеченные пробелы эталонов сохраняются.

### Пересмотр по примеру Telegram · 27.10.2026

Пользователь отклонил предложенные композиции настроек, подробностей задачи
и списка реакций в `extended-draft` как неудобные и попросил ориентироваться
на Telegram, особенно на работу с эмодзи. Эти черновики имеют статус REJECTED,
не включались в authority и не стали эталонами приложения. Их материалы
и прежние hashes сохранены для истории.

Пользователь одобрил финальный [интерактивный прототип](assets/revisions/2026-10-27-telegram-chat/index.html)
словами «Подходит, переносим» 27.10.2026 в ответ на перенос на mobile web, iOS
и Android. Ревизия **APPROVED**, опубликована в дизайн-системе **1.3.0**.
[Публикация и точные hashes](design-publication-2026-10-27-telegram-chat.md)
фиксируют исходники, переходы и область покрытия. Прежние REJECTED-черновики,
отчёты и их hashes сохранены; приложение по ним не принимается.

Приняты composer над emoji-доком без затемнения чата, быстрые/полные реакции
у сообщения, отдельная компактная панель людей, сгруппированные настройки,
подробности задачи с её названием в заголовке и компактные формы даты/места/задачи.
Это текущие мобильные эталоны вместо прежних композиций этих состояний.
Эта историческая публикация 1.3.0 сохраняла desktop-маршруты. Коррекция 2.0.0
заменяет страницы действий модалками; sidebar и основной чат остаются.

[Исследование Telegram](telegram-interactions-research.md) объясняет происхождение
принципов взаимодействия; код/ассеты/размеры Telegram не перенесены. Стикеры, GIF,
Premium и другие функции в объём не добавлены. Ограничения прототипа — неполный
Unicode-каталог, память вкладки, имитации Share/обложки/отправки — не ограничения
приложений. Системная клавиатура, picker, доступность, API, ошибки и повторы
проверяются в клиентах по прежним и уточнённым требованиям.

Мобильные bottom sheets, отсутствие нижнего таббара/футера в чате, права,
подтверждения и черновики остаются обязательными. Фаза — checkpoint;
UI-задачи открыты до независимых design-review/feature-test и актуальных gates.

## Навигация и переходы

| Откуда | Действие | Результат / возврат |
| --- | --- | --- |
| Список или календарь | Создать → подтверждение сервера | Сразу чат; Back возвращает исходный вид, а не форму |
| Новый чат | Пригласить друзей | Share/копирование; отмена оставляет чат |
| Основная навигация | Приглашения | Только сохранённые «Возможно»; карточка открывает приглашение |
| Приглашение до отсечки | Приду | После подтверждения открывается чат |
| Приглашение после отсечки | Просмотр | Детали и объяснение закрытия; вход недоступен |
| Карточка | Нажатие | Чат, явная стрелка назад в его шапке |
| Календарь | Выбрать дату / Сегодня | Встречи выбранного дня; Сегодня возвращает текущий месяц и день |
| Чат | Плюс | Компактное меню, затем bottom sheet на телефоне / модальное окно на desktop |
| Чат | Эмодзи | Вставка в черновик; отдельное действие отправки |
| Сообщение | Реакция | Быстрый набор или полный выбор; повтор снимает свою |
| Прошедшая встреча | Вайб встречи | Фотостопка; чат продолжает существовать |
| Вайб | Фото / Все фото / Добавить фото | Полный экран / сетка / системный выбор и предпросмотр |
| Полный экран | Закрыть, Escape, системный Back | Тот же снимок в вайбе |
| Основная навигация | Профиль | Просмотр данных владельца; редактирование отложено |
| Футер / помощь / профиль | Сообщить о проблеме | Форма → ошибки полей либо подтверждение приёма |
| Футер / профиль | О приложении / Документы | Версия и разработчик / публичные документы |

На широком экране встречи и приглашения стоят на одном уровне слева, профиль
находится внизу. На телефоне — округлая плавающая панель из трёх равных пунктов.
Иконки 19 px, подписи и внутренние отступы одинаковы. Компактное выделение
переезжает между пунктами за 260 ms, иконка мягко реагирует.

Уточнение пользователя от 26.10.2026: нижняя панель отображается **только**
на основном списке/календаре встреч (предстоящие и прошедшие), списке сохранённых
приглашений и основном экране профиля. На создании/редактировании, отдельном
приглашении, чате, Share, предпросмотре загрузок, альбоме/сетке/полном фото,
обращении, помощи, сведениях о приложении, документах и онбординге её нет.
Вложенные экраны возвращаются через явный Back и системную/браузерную историю;
возврат восстанавливает раздел и его состояние. Десктопная боковая навигация
следует прежнему макету. Безопасная область снизу учитывается на всех экранах;
там, где нижней панели нет, не остаётся резервного отступа под неё. На основных
экранах последний элемент контента можно прокрутить выше панели.

Старые HTML/PNG с нижней панелью на вложенных экранах сохраняются как исходный
дизайн. Это решение имеет приоритет при переносе и визуальной приёмке; макеты
не переписываются под реализацию. Футер отдельно ограничен десктопным
онбордингом — нижняя навигация и футер не являются одним компонентом.

## Список и календарь

[Список](assets/list.html), [история](assets/past.html),
[календарь](assets/calendar.html). Главная структура карточки:
дата на небольшом выступающем ярлыке, название и место слева, увеличенная
наклонённая обложка справа сверху, перекрывающиеся аватары справа снизу.
Высота определяется содержимым, базовый ориентир 145–146 px; фиксированное
ограничение высоты при длинном названии запрещено. Без обложки текст занимает
доступную ширину. Инициалы заменяют недоступный аватар. Несколько первых
участников и `+N` не показывают личные контакты. Имена доступны через подсказки,
доступное название и полный состав встречи.

Организатор обозначен небольшой короной около названия с доступной подписью
«Вы организатор», без отдельной строки. Выбран вариант A с перекрывающимися
аватарами; варианты с именными плашками остаются только исследованием в
`participants.html`, `list-avatars.html`, `list-names.html` и не являются эталоном.
Эталон — `list.html`, он же источник карточек календаря.

Будни используют сливовый цвет, суббота и воскресенье — серо-зелёный.
Расчёт основан на дате встречи в её часовом поясе. День недели обязательно
написан словами: цвет дополняет информацию. Произвольный выбор цвета оставлен
будущей итерации. Непонятный декоративный круг удалён. При наведении мышью
карточка поднимается на 3 px, обложка немного наклоняется и аватары раскрываются;
на тач-устройствах нет зависшего hover. Уменьшение движения отключает смещения.

Календарь сохраняет переключение периода, месяца, выбранного дня и «Сегодня».
Дни со встречами отмечены теми же двумя цветами и точкой. На широком экране
месяц и встречи стоят рядом; на узком — друг под другом. Карточки под датой
полностью совпадают со списком. Кнопка «Сегодня» не скрывается на телефоне.
При отсутствии встреч выбранного дня: «На этот день встреч нет». Возврат из
чата обязан восстановить выбранную дату, период, месяц и положение прокрутки.
В прототипе используется демонстрационное сегодня 25.10.2026; в продукте —
реальная дата по действующим правилам календаря.

## Приглашения и часовая отсечка

[Список](assets/invitations.html), [пустое состояние](assets/invitations-empty.html),
[приглашение](assets/invitation.html), [вход закрыт](assets/invitation-closed.html).
Постоянное описание:

> Здесь сохранены приглашения, на которые вы ответили «Возможно». Когда
> определитесь, откройте приглашение и измените ответ.

Этот текст остаётся при загрузке и ошибке, а пустое состояние его не повторяет.
За час до точного начала новые участники больше не присоединяются. Ровно на
границе вход уже закрыт. Ранее отказавшийся участник не получает исключения.
У текущих участников чат остаётся. Если есть только дата, часовая отсечка не
включается. После назначения/переноса времени состояние пересчитывается.
Состояние закрытия: «Присоединиться уже нельзя» и «Вход закрывается за час до
встречи. Начало в 18:00». При ожидании ответа сервера повторное нажатие заблокировано;
при сетевой ошибке сохраняется приглашение и доступен повтор, но не фиктивный вход.

## Создание и чат

[Создание](assets/create.html) → [новый чат](assets/created-chat.html).
Дополнение пользователя от 25.10.2026: существующий выбор обложки сохраняется
при создании в раскрываемом блоке «Обложка» после основных полей. Это явно
согласованное дополнение к create.html для всех трёх клиентов; остальные
композиция, порядок и оформление следуют эталону.
После подтверждения API промежуточный экран больше не нужен. В пустом чате
событие создания и «Позовём остальных?» с действием «Пригласить друзей».
С появлением переписки пустой блок исчезает; Share остаётся в шапке.
[Копирование/Share](assets/share.html), [результат](assets/share-copied.html).

Состав сведений о встрече задаёт [meeting-details.html](assets/meeting-details.html):
заголовок панели — название встречи, далее её данные, участники и действия.
Начальное состояние не содержит крупной обложки: три имени участников и «ещё N»
образуют компактный ряд из макета. Нажатие раскрывает полный состав с ответами
в этой же панели; отдельное действие сворачивает его. Это сохраняет требование
видимости состава/ответов из event-feed без длинного списка в начальном виде.
Настройки организатора и собственный RSVP сохраняют прежние права доступа.
«Пригласить друзей» использует тот же Share и те же права, что кнопка в шапке чата.
При открытии Share из сведений закрытие или Back возвращает в сведения, а их
закрытие — в чат. Одновременно открыта одна панель, включая переход между ними;
на время её закрытия следующая не перехватывает фокус. Это уточнение перехода
по утверждённым макетам не возвращает удалённые сервисные/футерные ссылки.

[Меню плюса](assets/chat-menu.html) содержит пять компактных строк: фото, файл,
предложить дату, предложить место, предложить задачу. Не показывать все формы
в одной модалке. Escape, повторный плюс, нажатие снаружи и системный Back
закрывают меню с сохранением текста. Формы используют существующие правила
голосования: [дата](assets/action-date.html), [место](assets/action-place.html),
[задача](assets/action-task.html). Права организатора не расширяются этим меню.
В карточке принятой задачи реальные имена подставляются в нейтральное
«Исполняет {имя}», сохраняя макетные размеры/отступы. Демонстрационное
«Миша принял задачу» не используется как шаблон с угадыванием пола по имени.
Строка создания использует «Новая задача · {имя}» по той же причине: не нужны
ни определение пола, ни автоматическое склонение имени.

[Фото](assets/upload.html), [файл](assets/upload-file.html),
[частичная ошибка](assets/upload-error.html). В web сначала форма, затем явный системный выбор по кнопке внутри неё;
предпросмотр, удаление выбранного, подтверждение, индивидуальный прогресс.
Ошибка одного файла не отменяет успешные. Подписи к фотографиям не добавляются;
при необходимости отдельный текст отправляется обычным сообщением.
Документ, в отличие от фото, сохраняет необязательное поле «Подпись» из
`upload-file.html` (до 2000 символов). При выборе нескольких документов подпись
принадлежит конкретному файлу. После начала отправки она фиксируется вместе
с ключом повтора; при ошибке остаётся видна. В чате видны подпись и имя файла.

## Эмодзи и реакции

Мобильный эталон — [принятая ревизия](assets/revisions/2026-10-27-telegram-chat/chat.html),
состояния `?view=emoji` и `?view=reactions`, плюс рабочие переходы внутри чата.
Старые [панель](assets/chat-emoji.html), [поиск](assets/chat-emoji-search.html),
[быстрые реакции](assets/chat-reactions.html) и [полный выбор](assets/chat-emoji-reaction.html)
сохраняются только как история; действующие gestures и поверхности задаёт 2.0.0.

Emoji-док расположен под composer; поле и отправка всегда вне сетки и над ней.
Чат виден без модального backdrop. Открытие не фокусирует поиск автоматически;
он доступен отдельным нажатием. Поиск по русским названиям, недавние и категории
доступны в прокручиваемой сетке. Выбор заменяет выделение/вставляет по курсору,
оставляет док открытым и не отправляет сообщение. Удаление работает по grapheme.
28.10.2026 пользователь уточнил desktop: удаление только клавиатурой в поле
сообщения; вариант с отдельной кнопкой в панели отклонён. Desktop-композиция
сохраняется. Backspace при фокусе поиска меняет запрос, не черновик. На мобильных
клиентах остаётся кнопка удаления в доке. Макеты и токены не меняются.
Иконка улыбки меняется на клавиатуру с доступным именем «Вернуться к клавиатуре»:
нажатие возвращает текстовый фокус и selection в composer. Escape/системный Back
закрывают док с фокусом на его кнопке, не вызывая клавиатуру. Черновик и положение
чата сохраняются; у нижней границы допустимо сохранить привязку к последнему сообщению.

Быстрые ❤️ 👍 😂 🔥 🎉 и «ещё» открываются удержанием сообщения; native использует
системный recognizer. Постоянных кнопок smile/add-reaction/people у сообщений нет.
Web использует контекстное меню/Enter/Space, native — custom accessibility actions.
Поверхность привязана к bubble; полная сетка сохраняет выделение и краткий контекст
сообщения. Она ограничена доступной областью разговора, не перекрывает composer
и отправку. При low-height/landscape скроллится сетка. Закрытие/выбор возвращает
фокус к этому сообщению и прежнюю прокрутку. Своя реакция различима
обводкой и отметкой, повтор снимает её; ошибка восстанавливает подтверждённое
состояние и предлагает повтор по прежним серверным правилам.

Удержание существующего чипа открывает «Кто отреагировал» сразу с выбранным
эмодзи, без изменения реакции. Короткое нажатие чипа переключает своё участие.
Удержание поглощает tap; прокрутка/cancel отменяют ещё не распознанный жест.
«Все»/эмодзи фильтруют людей; после redraw фокус остаётся на фильтре. Закрытие
возвращает фокус на чип (или bubble, если чип исчез). Имена без контактов.
Выделение сообщения заметно с начала удержания и сохраняется при picker;
вход/выход и pressed состояния следуют motion-контракту 2.0.0 с Reduce Motion.

## Обращения и помощь

[Форма](assets/report.html), [успех](assets/report-success.html),
[ошибка](assets/report-error.html), [помощь](assets/help.html).
Входы: профиль/помощь и футер десктопного онбординга. По последнему уточнению
пользователя в bottom sheet сведений о встрече нет пунктов сервиса/футера: помощь,
обратная связь, сведения о приложении и документы остаются в профиле. Переход «Предложить идею»
выбирает тему заранее. На телефоне форма занимает одну колонку; боковая
информация убирается, обязательные ограничения остаются рядом с полями.

Три темы: проблема, идея, вопрос. Описание обязательно (10–3000 символов),
экран выбирается из списка. Почта для ответа необязательна, не подставляется
из профиля. Один скриншот PNG/JPEG/WebP до 5 МБ выбирается явно; до отправки видны
миниатюра, имя и удаление. Сведения об устройстве включаются отдельным флажком,
по умолчанию он снят. Они ограничены версией клиента, браузером/ОС и размером
экрана. Переписка, контакты профиля, cookie и токены не прикладываются.

Под кнопкой только ссылка на политику. По прямому уточнению пользователя
форма не сообщает, кому и куда доставляется обращение. Информация о процессорах
и передаче данных относится к документам, а не к подсказке отправки.

Состояния реализации: отправка с защитой от повторного нажатия; ошибки полей
рядом с формой, перевод фокуса к первому ошибочному полю; подтверждение с реальным
номером только после приёма сервером; сетевой отказ с сохранением формы и повтором.
Уточнение про ответ показывается при введённой почте, срок ответа не обещается.
В прототипе работают только локальные проверки и предпросмотр: «Отправить»
открывает явно обозначенный пример успеха, без запроса, бота и сохранения данных.
Страница ошибки иллюстрирует будущий сценарий и не имитирует реальный сбой/черновик.

## Что действительно работает в прототипе

Переходы между HTML-состояниями, фотостопка и полный экран с жестами/клавишами,
анимация мобильной навигации, выбор дня/месяца/периода и «Сегодня». Формы, Share,
поиск эмодзи, авторизация и загрузки показывают подготовленные примеры результата:
они не отправляют сообщения или файлы и не сохраняют пользовательские данные.

## Уточнение форм действий — 26.10.2026

Последняя коррекция пользователя после паузы: на mobile web, iOS и Android
все голосования, задачи и другие действия из чата открываются в bottom sheet,
без отдельного экрана с «Назад». Чат остаётся контекстом под панелью. Нижняя
навигация и футер в панели отсутствуют. `action-date.html`, `action-place.html`,
`action-task.html` задают содержимое и стиль формы, но их полностраничная мобильная
оболочка отменена. На desktop с 2.0.0 открывается модальное окно поверх чата. Текущая реализация
полноэкранных мобильных форм заменяется при возобновлении реализации.
Существующие бизнес-поля и ограничения сохраняются (в опросе даты минимум два
варианта). У места textarea «Почему здесь» необязательна, до 2000 символов;
содержимое сохраняется с предложением и показывается участникам в карточке.
Поле и ключ повторной попытки фиксируются при неопределённом результате отправки;
Back сохраняет несданный черновик формы в памяти текущей встречи; повторное
открытие восстанавливает поля и ключ неопределённой отправки. Успех, смена
встречи, logout или отзыв доступа очищают черновик. Новое дисковое хранение
не требуется; повтор не создаёт второй опрос.

## Состав панели сведений о встрече — уточнение после паузы

В панели остаются только сведения и действия по текущей встрече. Пункты
«Помощь», «Сообщить о проблеме», «Предложить идею», «О приложении», версия,
конфиденциальность и cookie из неё убираются; доступ к ним — через профиль.
Правило футера десктопного онбординга сохраняется.

## Мобильный онбординг — исправление 27.10.2026

На iOS и Android нет дополнительного входа в помощь или документы поверх
онбординга либо под ним. Знак вопроса поверх «Пропустить» — ошибка реализации,
не элемент утверждённого дизайна. Состав слайдов и их навигация сохраняются по
[мобильному онбордингу](../../../docs/design/mobile-onboarding.md).
Проверяется весь экран с общей оболочкой приложения: отсутствие сервисных
кнопок, доступность пропуска, первый/последний слайд и крупный текст.

## Приёмка после возобновления — 26.10.2026

Опубликованные роли и адаптации — [design-system](../../../design-system/README.md),
оболочка действий — [chat-actions](../../../docs/design/components/chat-actions.md).
[Манифест](design-manifest.json) разделяет web 320/390/768/1440, нативные клиенты,
каждую форму и её состояния. Исторический [отчёт](design-review.json) сохранён
как предварительное наблюдение; новая live-приёмка записывается отдельно.
Открываемые формы, подробности задачи, редактирование и предпросмотр отправки
из чата используют нижние панели. Уже видимые inline-действия карточек опросов
и задач, компактное меню плюса и быстрые реакции сохраняют свои макеты.
Просмотр альбома и полноэкранное фото остаются отдельными режимами просмотра.
На телефоне крестик закрытия доступен наряду со свайпом и системным Back;

## Коррекция web-медиа от 28.10.2026 · 3.0.0

По найденным пользователем ошибкам отменён прежний web-путь «сначала системный
выбор». Пункт фото/файла в плюсе открывает пустую форму: desktop — компактная
модалка по общему chatActionDialog, mobile web — bottom sheet. Системный выбор
открывается только кнопкой внутри. Первая и повторные отмены сохраняют форму,
выбранные файлы и черновик чата. Фокус обводит видимую кнопку целиком.

«Добавить фото» в баннере пустого вайба ведёт прямо в форму добавления, без
промежуточного альбома. В desktop это та же компактная модалка над альбомом,
не отдельная растянутая страница. Полный просмотр всегда вмещает весь снимок
в доступную область под шапкой, без crop и дополнительного скролла.

Эталон пустой и заполненной формы: [web media flow](assets/revisions/2026-10-28-media-flow/index.html),
варианты `?kind=photo` и `?kind=file`. Макет использует прежние токены;
новых цветов, размеров или текста не вводится. Эта публикация меняет только
web-путь; native требует отдельной сверки, его приёмка не объявляется.


## Уточнения native и общих поверхностей · 28.10.2026

Прямые решения пользователя после проверки установленного iPhone:

- iOS/Android: пункт фото/файла сразу открывает системный picker, без промежуточной нижней панели. Только непустой выбор открывает панель предпросмотра/отправки; отмена picker сохраняет чат/черновик и не показывает пустую панель. Web сохраняет отдельный путь: сначала форма.
- Native «Поделиться» сразу открывает системный share с готовой ссылкой; собственная промежуточная панель остаётся только в web.
- В пустом чате центральное приглашение — заметная primary-кнопка. Пока показано это пустое состояние, иконки Share в шапке нет. Системные записи не считаются пользовательскими сообщениями.
- Свайп фотостопки не открывает полный просмотр: его открывает только tap без drag. Фото альбома заранее загружаются с ограниченной параллельностью; при перелистывании уже полученные данные/декодированные изображения повторно не заменяются placeholder.
- Предпросмотр выбранных фото на всех клиентах — горизонтальная карусель. Удаление — доступный крестик поверх правого верхнего угла фотографии. Статус отправки общий на весь пакет, без прогресса/успеха у каждого снимка; успешный пакет автоматически закрывает панель. Частичный отказ сохраняет неуспешный выбор и повторяет только его, успешные файлы не дублируются.
- Аватар принятого исходящего сообщения сохраняется при переходе pending→accepted, без промежуточного инициала. PDF должен пройти весь реальный pipeline; ошибка не должна терять возможность повтора.
- В iOS системный свайп от левого края вправо возвращает из чата в прежний список/календарь с тем же периодом, сохраняя черновик.
- На всех поверхностях быстрые загрузки не показывают мелькающий skeleton; при обновлении уже показанные данные сохраняются. Отдельная проверка — смена дня календаря, cache hit, первый вход и медленный ответ.
- Переходы из профиля в помощь/документы возвращаются назад в предыдущий экран. «Выйти» находится в самом низу профиля. Вход в удаление аккаунта пока скрыт; серверный API не удаляется. Версия остаётся только в «О приложении»; видимое название приложения там не повторяется в нескольких блоках.
- В создании встречи загрузка обложки переносится перед остальными полями и получает заметную кнопку с иконкой изображения.
- FAQ требует отдельной проверенной ревизии стрелки/раскрытия; до её готовности новая композиция не считается принятой. Open Graph приглашения проверяется отдельным серверным запросом без JS и cookies.

Эти уточнения являются частью незавершённой публикации3.0.0. Значения существующих токенов сохраняются; новая приёмка обязательна. Прежние отчёты неизменны.

### Нижние вкладки · дополнительное решение 28.10.2026

Выбранная подложка плавно перемещается между нижними вкладками, не мигает
при смене экрана; подписи и иконки меняют цвет синхронно. Используются прежние
композиция/токены и motion.navigation, Reduce Motion — мгновенное переключение.

### FAQ — решение по макету 28.10.2026

Пользователь подтвердил [плюс/минус с плавным раскрытием](assets/revisions/2026-10-28-help-disclosure/index.html)
для всех трёх клиентов. Это заменяет прежнюю стрелку. [Контракт](../../../docs/design/components/help-disclosure.md)
задаёт роли и motion; прежняя отметка «требует отдельной ревизии» закрыта этим
решением, функциональная и дизайн-приёмка реализации остаются открыты.
