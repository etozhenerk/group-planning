# Проверка общего API и локальных медиа

26.10.2026. Группы 2–3 и серверная часть 8.1–8.3 реализованы; это не отчёт о готовности интерфейсов
или облачном выпуске. Авторизация в тестах использует только тестовых провайдеров.

## Реализованное поведение

- Личный профиль с необязательными проверенными полями Яндекс ID; повторный вход
  не стирает отсутствующие данные. Логин, имя/фамилия, дата рождения, пол и контакты
  не входят в публичные DTO. Web использует зарегистрированные права Яндекса без
  сужения scope; native SDK уже работают так. Проверены полная/частичная дата,
  явное null-очищение, сохранение пропущенных полей и некорректные значения.
- Общие summary/detail содержат сохранённый `period`, организатора, до трёх
  текущих участников, количество/превью фотографий альбома. Профили читаются
  пакетом для страницы; аватар ленты тоже загружается без запроса на сообщение.
- Атомарная отсечка нового «Приду» при `now >= starts_at - 1h`: управляемые часы,
  до/ровно/после границы, конкуренция, повтор и возвращение после отказа,
  перенос времени и дата без точного часа. Старый прямой RSVP получает обычный
  409 `join_closed`, анонимное приглашение не раскрывает закрытые данные.
- Реакции setter-операцией с идемпотентностью: повтор не удваивает реакцию и не
  возвращает позже снятую. Текущие участники читаются одним batch-запросом.
  Каталог — общий Unicode 17/CLDR 48, 3944 fully-qualified эмодзи; варианты
  с пропущенным variation selector приводятся к общей форме.
- Резервирование/загрузка/публикация вложения разделены, публикация ленты
  атомарна. Повтор, частичный успех, подмена формата и отзыв доступа во время
  I/O проверены; обычный текущий участник публикует наравне с организатором.
- Подпись документа из `upload-file.html` передаётся в существующем тексте
  сообщения вместе с вложением. Проверены предел 2000 Unicode-символов,
  отсутствие подписи у фото, нормализация пробелов, конкурентная публикация,
  неизменность текста при повторе с прежним и новым ключом, строгий JSON.
- Пояснение места из `action-place.html` сохраняется с опросом: trim, 2000
  Unicode-символов, приватность, повтор/конфликт, сохранение после завершения.
  Прежний hash без explanation совместим; null/нестроковый ввод дают 422.
- JPEG/PNG/WebP декодируются с ограничениями, EXIF orientation 1–8 применяется
  до удаления метаданных. Реальный WebP проверяется отдельным тестовым файлом.
- Альбом сохраняет отдельное назначение фотографий и пагинацию, не переводит
  встречу в `past`. Проверены пустой/одиночный/многостраничный альбом,
  приватные ссылки и очистка незавершённых загрузок.
- Временный файловый адаптер имеет права 0700/0600 и не принимает пути клиента.
  Очистка сохраняет живые файлы и обновлённые повтором загрузки; память и
  PostgreSQL используют тот же порт immutable content.

## Границы проверки

PostgreSQL-адаптер и миграция 003 подготовлены в коде. Облачные интеграционные
тесты не запускались; обычный `go test` пропускает их без отдельного DSN.
Сохранность, восстановление и откат после миграции ещё не подтверждены.
Production-миниатюры и проверка нагрузки относятся к группе 7.2.
Никаких миграций на действующей базе, деплоя или публикации сборок не выполнялось.

Обращения: публичный приём, неизменный номер после потери ответа, конфликт
содержимого, rate limit, закрытый список полей, очистка скриншота, rollback/
копии и конкурентные leases проверены. Telegram-адаптер проверен только
моками: временный отказ, частичное подтверждение, повтор без дублирования
подтверждённой части, запрет redirect, ограничение ответа и длинный Unicode.
Предел 12 автоматических попыток сохраняет запись для операторского повтора;
повтор проверен без потери номера обращения и подтверждений частей.
Тексты/контакты/ключи не попадают в логи. Реальный бот не подключался.
При PostgreSQL-режиме приём выключен до постоянного адаптера пункта 8.9;
memory-очередь теряется при перезапуске. [Ограничения](../../../backend/docs/support.md).

Готовность web/iOS/Android оценивается отдельно по их проверкам и
обязательному визуальному совпадению с утверждённым дизайном.
