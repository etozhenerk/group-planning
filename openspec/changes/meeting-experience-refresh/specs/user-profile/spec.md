# Spec Delta

## Purpose

Позволяет владельцу просматривать свой профиль и полученные из Яндекс ID данные,
отделяя имя и аватар для участников встреч от личных контактных сведений.

## ADDED Requirements

### Requirement: Просмотр собственного профиля

Клиенты SHALL открывать профиль из общей навигации и показывать имя, аватар,
связь с Яндекс ID, логин, имя, фамилию, дату рождения, пол и доступные контакты. Отсутствие аватара SHALL заменяться
инициалами, отсутствие контакта — честной подписью. Редактирование имени,
аватара и контактов не входит в этот этап.

#### Scenario: Профиль без телефона
- **WHEN** Яндекс не передал телефон
- **THEN** в поле видно «Не указан», а остальные сведения доступны

#### Scenario: Не удалось загрузить профиль
- **WHEN** запрос профиля завершился ошибкой
- **THEN** показаны ошибка и повтор, отсутствие ответа не выдаётся за пустые поля

### Requirement: Приватность контактов

Логин, имя/фамилия отдельными полями, дата рождения, пол, почта и телефон SHALL
возвращаться только владельцу профиля. Участники встречи
SHALL получать лишь публичное представление: ID, имя и аватар. Обновление
авторизации SHALL NOT перезаписывать известный контакт отсутствующим полем
из-за недостаточных разрешений нового токена.

#### Scenario: Просмотр участника
- **WHEN** другой участник получает состав встречи или авторов сообщений
- **THEN** личные поля отсутствуют в ответе API и в интерфейсе

#### Scenario: Недостаточно прав Яндекс ID
- **WHEN** действующий токен не предоставляет контакты
- **THEN** вход остаётся возможным, клиент показывает доступные данные
- **AND** дополнительное разрешение не считается уже предоставленным

### Requirement: Синхронизация данных Яндекс ID

Авторизация SHALL запрашивать права, выбранные владельцем приложения в Яндекс
OAuth. Сервер SHALL проверять токен и получать данные непосредственно у Яндекса.
Пропущенное поле SHALL сохранять прежнее значение, явно пустое личное поле —
очищать его. Неизвестные части даты SHALL NOT дополняться. Старые сессии SHALL
оставаться действительными, новые данные обновляются при следующем входе.

#### Scenario: Все права и полные данные
- **WHEN** новый вход возвращает все выбранные поля Яндекс ID
- **THEN** собственный профиль показывает данные, полученные сервером, на всех трёх клиентах
- **AND** клиент не подменяет отсутствующие значения демонстрационными

#### Scenario: Неполная дата и неизвестный пол
- **WHEN** Яндекс возвращает birthday 0000-12-23 и sex null
- **THEN** интерфейс показывает «23 декабря» и «Не указано»
- **AND** не придумывает год, возраст или пол по имени/аватару

#### Scenario: Явное очищение и частичные права
- **WHEN** повторный вход содержит birthday null, но не содержит first_name
- **THEN** дата рождения очищается, известное имя сохраняется
- **AND** отсутствие дополнительного поля не блокирует вход

### Requirement: Упрощённые действия профиля
Клиенты SHALL показывать выход последним действием профиля, скрывать вход в удаление аккаунта и не дублировать версию. API удаления сохраняется.

#### Scenario: Выход расположен последним
- **WHEN** Открыть профиль, прокрутить весь экран и прочитать доступные действия.
- **THEN** Выход ниже сервисных ссылок, входа в удаление аккаунта и версии нет.
