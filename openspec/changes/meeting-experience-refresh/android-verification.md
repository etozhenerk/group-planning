# Проверка Android — meeting-experience-refresh

## Область

Нативная реализация Kotlin/Compose, API и приватное состояние Android. Изменены
навигация, карточки/календарь, вход в чат, отсечка вступления, меню, emoji,
реакции, выбор/отправка файлов, профиль, альбом, помощь, обращения и документы.
Публикация и деплой не выполняются. Этот отчёт относится только к Android.

## Принятые уточнения

- Футера в Android нет. В профиле остаётся обычный список переходов к помощи,
  обращениям, сведениям о приложении и документам.
- Нижняя навигация есть только в списке/календаре встреч, списке приглашений и
  основном профиле. В создании, чате, отправке, альбоме и служебных страницах её нет;
  это новое прямое решение пользователя имеет приоритет над историческими HTML/PNG.
- Раскрываемая «Обложка» при создании сохранена по прямому решению пользователя.
  Необязательность даты/времени и существующие правила timezone сохранены.
- Версия берётся целиком из `BuildConfig.VERSION_NAME`; отдельная строка сборки —
  `BuildConfig.VERSION_CODE`. Данные о юридическом операторе не выдумываются;
  документы явно обозначены проектами.
- Альбом определяется серверным `period=past`, а не часами телефона.

## Профиль и формы действий

Приватный `GET /me/profile` декодирует необязательные nullable `login`, `first_name`,
`last_name`, `birthday`, `sex`. Они показаны в панели «Личные данные» до контактов;
публичный `UserProfile` этих полей не содержит. Нулевые компоненты даты рождения
не заменяются вымышленными значениями. Для старого API используются пустые состояния.

Android использует SDK Яндекса 3.1.3 с `YandexAuthLoginOptions()`; согласно
[официальному справочнику](https://yandex.ru/dev/id/doc/ru/mobileauthsdk/android/3.1.3/sdk-android-methods)
его параметр — `loginType`. Ограничивающего `scope` в Android нет; фиктивные
параметры и принудительный выход не добавлялись. Ранее выданный токен не получает
новые разрешения без повторного входа.

На момент checkpoint формы даты, места и задачи используют полноценную страницу
из `action-*.html`. **Последнее прямое решение пользователя на паузе отменяет эту
композицию:** при следующем возобновлении все действия из mobile-чата нужно
перевести в bottom sheets без отдельного экрана с Back. Приложение на паузе
не менялось; текущие action fullscreens подлежат переделке первым приоритетом.
Сохраняются бизнес-правила: у опроса даты минимум два варианта, прежняя семантика
пяти настроек и разрешение неоднозначного времени при DST. Пояснение «Почему здесь»
необязательно, ограничено 2000 Unicode codepoints, сохраняется в замороженном
запросе повтора и показывается в карточке опроса. Динамические имена используют
нейтральные строки «Новая задача · {имя}» и «Исполняет {имя}».

## Надёжность и приватность

UI использует существующие владельцы состояния и repository. Binary API идёт
через проверенный origin и session lease; 401/403, выход и смена generation
не возвращают ранее очищенные приватные данные. Аватары загружаются отдельно
по HTTPS без API Bearer. Очередь выбранных файлов, байты, ключи подготовки и
публикации сохраняются с Android Keystore в `noBackupFilesDir`; повтор использует
те же ключи. Необязательная подпись документа сохраняется с очередью и фиксируется
до первого запроса отправки; фотографии публикуются без подписи. Ошибка одного файла не удаляет успешно опубликованный соседний.
HEIC декодируется системным ImageDecoder и преобразуется в JPEG; EXIF не копируется.

Реакции загружаются для видимых сообщений, в том числе сразу при появлении;
отправляется явное desired state с устойчивым ключом повтора. Ошибка откатывает
подтверждённое состояние. Версия мутаций не даёт запоздавшему GET затереть
подтверждённый PUT; ответы параллельных GET применяются по порядку запросов. Поиск emoji работает по полному локальному Unicode17 /
CLDR48 каталогу (3944 записи), включая русские названия и ключевые слова.
Gradle `prepareEmojiAssets` является зависимостью `preBuild`, поэтому каталог и
лицензия действительно попадают в APK.

Обращение сохраняет форму при пересоздании Activity. Замороженный запрос и
выбранный снимок зашифрованы; подтверждение показывает номер только после
серверного `accepted`. Почта не подставляется из профиля, диагностика выключена
по умолчанию. Нет автоматического прикладывания переписки, контактов и токенов.

## Проверки на момент паузы — 26.10.2026

Работа остановлена по прямому запросу пользователя. Это сохранённый промежуточный
результат, **не финальная приёмка Android**. Публикации/деплоя не было.

Окружение: JDK 17, SDK 36 / Build Tools 36.0.0, Gradle wrapper 8.14.3;
один существующий Somewhere_API_36, Android 16, 720×1600 px / 360×800 dp.
Gradle ограничен двумя workers, проверки не запускаются параллельно с iOS/web.

Подтверждённые результаты:

  отдельные QA app/test APK. Локальный журнал: `/tmp/android-final-check6.log`.
  В JVM вошли поздний GET после подтверждённой реакции, неполная дата рождения,
  отсутствие новых полей в публичном профиле и совместимость со старым ответом.

## Оставшаяся минимальная последовательность

Первый приоритет возобновления — новое решение пользователя: голосования, задачи
и остальные действия из mobile-чата должны быть bottom sheets, а не отдельными
экранами с Back. Сначала обновить Android-композицию и проверки под это решение,
сохранив API, черновики, ключи повтора и очистку приватного состояния.

После этой правки, последовательно, с `--max-workers=2`:

1. `formatApply`, затем актуальные Debug/Release, Lint обоих вариантов,
   JVM и instrumentation/QA compilation. Чистый check уже выполнялся выше,
   но его результат не покрывает перечисленные поздние правки.
2. `sh scripts/test-device.sh` — повтор 13 device-проверок, включая исправление
   receipt; Keystore, зашифрованные файлы/ключи, потерянный publish, частичный успех.
3. `sh scripts/test-ui.sh all` — регрессия прежних сценариев и реальный
   process-death для черновика/неподтверждённого сообщения.
4. `sh scripts/test-ui.sh experience` — пять расширенных сценариев и финальные
   снимки. Новый положительный системный Photo Picker пока не запускался.
5. Общий `CrossPlatformUiTests` под управлением основного агента: web-файл с
   подписью и фото, iOS ❤️, Android 👍/сообщение, общий альбом/fullscreen.
6. Сохранить актуальные пары native/reference, сверить лично и завершить отчёт;
   затем `agent:check`/`git diff --check`.

Проверки TalkBack пока ограничены доступными именами/ролями и подготовленным
вызовом CustomAccessibilityAction; отдельный ручной проход с озвучиванием
TalkBack не выполнен. Изменения системных настроек в UI-тесте восстанавливаются
через `finally`.

## Найденные остатки до финальной приёмки

- Порядок фото design fixture: сервер выдавал `boardgame.png` первым,
  эталон начинает с `friends.png`. Основному агенту передано предложение
  изменить только порядок seed; на паузе fixture оставлена без правки.
- CTA «Мои встречи» после принятого обращения сейчас закрывает `ServiceDialog`.
  При входе из профиля это возвращает в профиль, а не выбирает вкладку встреч.
  Найдено перед паузой, **не исправлено**.
- Локальный выбор поля фокуса при ошибке SupportForm ещё использует UTF-16
  `length`, тогда как валидация ViewModel уже считает Unicode codepoints.
- Полноэкранный просмотр фото из сообщения и состояния ошибок/загрузки вложений
  требуют отдельной финальной визуальной сверки; сборка её не заменяет.
- Юридические реквизиты остаются отложенными; документы обозначены проектами.

## Визуальная проверка

Эталон — исходные HTML и окончательный каскад `assets/styles.css`, без изменения
эталона под реализацию. Подготовлен браузерный viewport 360×708 — область приложения
после вычета системных областей из экрана 360×800. Нативные снимки включают
системные области Android; нормализация — crop 720×1416 px с y=136 px и масштаб
2:1 до 360×708. Полный исходный снимок должен сохраняться рядом. Фото, сообщения
и профиль берутся из изолированной QA design fixture, не пользовательского аккаунта.

Эталоны сохранены в
[assets/verification/android/reference](assets/verification/android/reference).
На исторических HTML ещё видны footer/bottom bar; для реализации приоритет имеет
прямое решение пользователя об их области показа. Минимум два варианта даты и
сохранённая «Обложка» — согласованные функциональные дополнения.

**Актуальные финальные native-пары не сохранены.** Предыдущие снимки были
промежуточными, а clean-сборка очищает `app/build/outputs`. Нельзя считать этот
отчёт подтверждением полного визуального совпадения.
