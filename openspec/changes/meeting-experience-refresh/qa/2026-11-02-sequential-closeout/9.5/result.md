# 9.5 · пакет фото и приватная предзагрузка

Проверено основным агентом последовательно, без сабагентов по прямому
поручению пользователя. Chromium, настоящий локальный Go API/memory,
два независимых аккаунта. Изменений приложения для этого пункта не потребовалось.

- Три выбранных снимка в одной горизонтальной карусели; удаление среднего
  overlay-крестиком с областью не менее44. Во время задержки — один busy у
  общей кнопки, без progress/status у отдельных фото.
- Первый файл опубликован, второй получил503. Форма сохранила только второй;
  повтор завершился автоматическим закрытием. Всего2reservation/3PUT;
  оба участника видят ровно2разных фото, удалённого выбора нет.
- Четыре задержанных фото декодированы заранее, пик параллельности3,
  всего4GET. Переключение вперёд/назад, fullscreen/закрытие и drag не добавили
  запросов/загрузчиков; drag не открыл fullscreen.
- У другого альбома удержан уже авторизованный ответ. После реального
  отказа от участия сервер вернул403; возврат в альбом показал закрытый
  доступ, поздний ответ не восстановил изображения. Logout отозвал все
  созданные blob URL. Новый аккаунт получил4заново декодированных URL.

`results-r2.json`: batch и preload PASS; `results.json`: уточнённый preload
с проверкой полной загрузки нового аккаунта PASS. Реальные PNG просмотрены.
Первый запуск сохранил ошибки постановки проверки: параллельные PUT ошибочно
считались последовательными, а Back выполнялся без ожидания ухода в список.
Оба ожидания исправлены; поведение приложения не менялось.

Общая независимая/design/release-ready приёмка этим проходом не объявляется.
Системный файловый picker/Cancel и настоящий мобильный IME здесь не проверяются.
