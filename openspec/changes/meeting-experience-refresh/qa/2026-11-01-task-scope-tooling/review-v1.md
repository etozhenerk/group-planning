Положительный независимый контроль: настоящий unrelated failed check остаётся в outsideScope, scoped ready=true, wholeReady=false. Проверка required cases/platforms/environments и всех expected modes в taskChecks выглядит полной для валидного однозначного mapping. inspectRun продолжает валидировать evidence/hash/timestamp и passed executor даже вне scope, source/catalog/plan и commandHash; missing/failed/false-pass обычных required suites не ослаблены. Release-purpose scope отвергается; receipt для task scope запрещён; global ready без scope сохранён.

Дополнительное усиление для нового CLI: сейчас он читает произвольный supplied manifest, проверяя только совпадение plan/run paths. Проверка принадлежности зарегистрированному canonical testing manifest не видна. Старый или временный mapping с тем же change/plan/run может дать misleading task-ready; checkManifests позже проверяет зарегистрированную версию отдельно. Рекомендуется привязать CLI к registry path либо явно ограничить такую команду advisory-снимком. Это замечание о provenance, не пятый воспроизведённый RED.

Будущий optional task.acceptance/platform binding сюда не включён: его root готовит после этого snapshot. Требуется отдельный exact diff/hash review и негативы: undeclared/duplicate platform; missing case/environment/mode; не тот plan/run; stale source/catalog; required suite fail; inherited fallback; одновременные завершённые backend/iOS задачи без взаимного удаления результатов. Исходные v1 результаты должны остаться неизменными.
