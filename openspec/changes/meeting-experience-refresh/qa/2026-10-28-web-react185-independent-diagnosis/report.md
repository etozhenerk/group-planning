# Независимая диагностика React185 в rc10

## Вердикт

`web/v0.1.0-rc.10`, commit `bcd0778a74c9aebcdb994d707588a581f9f3cffb`,
не готов к выпуску. Независимый повтор исходного WebKit сценария 45 на
844×390 дал **2 PASS / 10 FAIL**; каждый сбой сопровождался React185.
Серверные PUT реакций проходили, падало представление клиента.

Это диагностический отчёт, а не полный feature/design/release pass.
Проверялось headless приложение с реальным изолированным Go API и синтетическим
OAuth на loopback8488. Mac заблокирован, ручной проход и визуальная приёмка
не выполнялись. Production, Telegram и физические устройства не затронуты.

## Причина

В `useFeedTimeline` набор `rendered` зависит от размеров виртуальных строк.
`useReactions` включает весь `entries.join(',')` в query key и на новый набор
не сохраняет прежние подтверждённые данные. Поэтому даже реакция уже видимого
сообщения исчезает, когда на краю виртуального диапазона появляется другая строка.

Доказанная последовательность из инструментированной временной копии:

1. При scrollTop=0 и постоянном scrollMargin=16 строка с реакцией имеет134.5px;
   виртуализатор показывает индексы0…12.
2. Переключение query key обнуляет reactions.data, реакция исчезает. Высота84.5px;
   в диапазон попадает индекс13.
3. Прежние данные снова появляются для другого набора. Высота134.5px, индекс13
   размонтируется. Цикл повторяется примерно каждые16ms.
4. Каждое новое появление граничного сообщения создаёт новый ReactionPopover
   и новый registeredAnchor. Вызов setReference из layout effect приводит
   к ещё одному синхронному state update. React останавливает цепь по лимиту.

Таким образом, setDomReference — наблюдаемое место ошибки, но guard внутри
одного экземпляра hook не устраняет цикл изменения диапазона и высоты.
В диагностике зарегистрированы43 разных экземпляра/DOM-элемента при15 исходных
строках; последние повторения относятся к одному граничному сообщению.
`geometry-cycle.json` содержит компактную последовательность измерений без
содержимого сообщений, токенов или серверных данных.

Новый Error.stack записан в независимом runtime. Source map проверен на
побайтно том же JS и указывает на `useReactionPopover.ts:79` →
`@floating-ui/react` setDomReference, не на старую версию rc9.
См. `mapped-stack.json` и `provenance.json`.

## Причинный эксперимент

В отдельной временной копии immutable rc10 изменён только query option
`useReactions`: scoped placeholderData сохраняет прошлые подтверждённые данные,
если privateKey(user, meeting, access epoch, reactions) совпадает.
Остальные JS, сценарий и backend fixture остаются прежними.

Те же12 повторов дали **12 PASS / 0 FAIL**. Продуктовые исходники и тестовые
ожидания не менялись. Этот эксперимент подтверждает причину; он не является
новым кандидатом и не может быть выложен как релиз.

## Рекомендация исполнителю

Сохранять подтверждённые реакции для пересекающихся entry_id при смене
виртуального диапазона в пределах того же пользователя, встречи и access epoch.
При denied/смене любого приватного scope возвращать undefined. Не использовать
безусловный keepPreviousData между разными аккаунтами или встречами.

Аналогичную зависимость набора rendered и высоты проверить у read receipts;
она не была причиной измеренного50px переключения реакций, но имеет тот же риск.
Для receipts дополнительно учитывать stream epoch и сброс приватных данных.

После исходников нужны scoped QueryObserver tests (смена диапазона, revoked
access, другой user/meeting/epoch), повтор исходного45 сценария и проверки
history/retained rows на новом точном artifact. Старый pass не переносится.
