# Один недоступный снимок: native UI · 04.11.2026

Недостающий третий шаг TC-VIBE-NATIVE-PRELOAD проверяется отдельно от уже
пройденного альбома103. Только loopback QA API, три различимые фотографии,
собственный синтетический аккаунт. Системная сеть Mac и обычное приложение
не меняются. Проверяет основной агент по прямому поручению пользователя.

## iOS — исправлено и пройдено

iPhone18Pro simulator 31262733-50DC-46A5-938E-4C462D70F109, iOS27.0,
Xcode27.1, ru_RU, размер L, обычные анимации. Действия и provenance в
`ios/fixed/test.log` и capture JSON рядом с реальными PNG.

1. Отказ503 для фото2 до открытия альбома; фото1 и3 подготавливаются.
2. Свайп к фото2 оставляет фото1, счётчик1/3 и видимую ошибку с повтором.
3. Запрет всех content-запросов; ранее не открывавшееся фото3 открывается
   полноэкранно из кеша. Новых content-запросов к доступным фото1/3 нет.
   Повторные попытки недоступного фото2 при создании grid допустимы и учтены
   отдельно; первоначальная проверка общего количества была уточнена.
4. Возврат в стопку, цикл3→1 и повтор ошибки; после восстановления транспорта
   «Попробовать ещё раз» показывает настоящее фото2, а не просто счётчик2/3.
5. Удаление только этого тестового аккаунта и возврат закрывают альбом,
   фотографии и действие сохранения; виден онбординг.

Обнаружен реальный дефект: подготовщик успешно восстанавливал общий кеш,
но ранее созданный PrivatePhotoView сохранял свою ошибку. Начальный тест
со счётчиком прошёл, однако просмотр actual показал бежевую заглушку
(`ios/initial/preload-failed-photo-retried.png`); этот результат не принят.
MemoryPhotoStack теперь обновляет зависимые представления после успешной
подготовки; MediaContentOwner сбрасывает failed при попадании в кеш.

Новый UI-тест дополнительно оценивает цветные пиксели середины карточки
синтетического фото: доля0.985 при пороге0.2; исходная заглушка однотонная.
Финальный PNG просмотрен основным агентом: видна фотография пиццы.
UI PASS29.165с. Регрессия восстановления владельца из чужой подготовки
прошла; весь обязательный unit-прогон после этой правки:218/0fail.
Чистая Release-сборка и analyze PASS. Это проверки новой правки, прежние
web/native общие пользовательские сценарии повторно не запускались.

## Android

На отдельном emulator-5554/API36 воспроизведён сбой цикла3→1:
подготовленная первая фотография блокировалась ошибкой соседнего снимка2.
Исходный провал и actual сохранены в android/initial/. Исправление использует
уже подготовленные соседние изображения при сборке стопки; недоступный сосед
не отменяет переход к готовому первому фото. Адресный тест прошёл:11.599с, один тест,0ошибок.
Фото3 из кеша и настоящее фото2 после повтора подтверждены bitmap-узлами
и просмотром actual; отзыв сессии закрывает альбом и возвращает онбординг.
Действия, исходная ошибка и новые кадры с metadata сохранены раздельно
в android/initial/ и android/fixed/.

Обязательный Android check.sh после правки: format, чистые Debug/Release,
оба Lint,199 unit без ошибок/пропусков, Debug/QA instrumentation APK — PASS.
QA tooling:23 теста PASS; qa:check по-прежнему отвергает общий устаревший
каталог. Подтверждение не подменяется успешными сборками.
