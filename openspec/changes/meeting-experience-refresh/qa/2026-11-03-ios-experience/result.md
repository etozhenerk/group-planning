# iOS: профиль и вайбы, 03.11.2026

Проверка основным агентом на iPhone 18 Pro / iOS 27.0, без физического устройства.
5.4: четыре уникальных XCUITest-сценария PASS в адресных запусках.
Профиль: три UI-входа с синтетическими SDK-ответами — полные, неполные и очищенные
поля при Accessibility XXXL. 23 декабря не получает выдуманного года; отсутствующий
телефон обозначен явно. Поля read-only, строки доступны после прокрутки.
Настоящий VoiceOver прочитал название/значение даты, пола, почты и телефона;
транскрипт `profile-voiceover.txt`. Ошибка GET /me/profile не маскируется отсутствием
данных; после «Попробовать ещё раз» профиль восстанавливается.

Вайб-баннер открывает альбом без шапки списка. Реальный системный Reduce Motion
включён через Settings, подтверждён UIAccessibility в приложении и восстановлен.
При XXXL оба направления свайпа дают 1→2→3→1 без fullscreen; landscape и VoiceOver
проверены. Сетка, отдельный tap/fullscreen и сохранение индекса — свежий album-download
03.11 и закрытый 12.1; production media-код с тех прогонов не менялся.
После реального DELETE /me во временном API повторное открытие cached-альбома
получает отказ сессии: показан онбординг, фото и скачивание недоступны. Это проверка
отзыва сессии после серверного отказа, не замер мгновенного push-отзыва членства.
Actual просмотрены в `actual/`; VoiceOver выключен и ориентация возвращена.

QA-селекторы исправлены: реальный ID design-альбома, endpoint профиля и онбординг
после отзыва. Неуспешные промежуточные запуски не объявлены PASS; recovery-прогон
остановлен после успешной проверки профиля и неверного ожидания кнопки входа.
Последний revocation-only PASS. Product-код не менялся. Общий независимый gate
не объявлен успешным; основной агент проверяет по прямому поручению пользователя.
