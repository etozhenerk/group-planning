# Открытое наблюдение: клавиатура формы задачи

Статус: BLOCKED для приёмки экранной клавиатуры в текущем окружении.
Повторяемый FAIL теста сохранён; продуктовый дефект не доказан.
Полный feature/design pass не выставлен.

## Воспроизведение

- QA iPhone 18 Pro, iOS 27.0, viewport 402×874, стандартный размер текста.
- Открыть встречу «Настолки у Саши», плюс → «Предложить задачу».
- Нажать поле «Что сделать».
- AX сообщает Keyboard frame `(0, 918, 402, 226)`, находящийся вне экрана.
  Видна клавиатурная панель «Готово»; настоящая клавиатура на снимке отсутствует.
- Frame не становится видимым за 5 секунд. Повтор воспроизводится до ввода текста.
  В первоначальном тесте текст через XCUITest вводился, но это не доказывает
  доступность клавиатуры пользователю.

## Проверки

- Общий `sheet-gestures`: date/place прошли, task упал.
- `sheet-task` отдельно: тот же результат.
- Ожидание видимой геометрии перед assertion: timeout, условие не ослаблялось.
- Диагностическое удаление новой `.frame(maxHeight: nil)` обёртки generic sheet
  не изменило результат. Refactor полностью возвращён; в продукт он не внесён.
- Проверка сразу после tap, до typeText: тот же результат.

Evidence: iteration-5 — общий прогон; iteration-6 — отдельный task;
iteration-7 — ожидание геометрии; iteration-8 — временный layout diagnostic;
iteration-9 — клавиатура до ввода. Логи сжаты без изменения содержимого,
скриншоты и capture context сохранены. Для диагностических итераций 6–9
полный исторический source manifest не заявлен; layout patch итерации 8 сохранён.
Финальный source-hashes.json относится только к финальному кандидату.

В предыдущем `ios-media-polish-author/report.md` также был frame y918 при
поддержке, но там ожидание видимой геометрии помогло. Это не основание объявить
нынешнее воспроизведение случайным. Версия Simulator/OS могла повлиять; проверки
на физическом iPhone нет по решению пользователя.

Возможное продолжение: сравнить короткий custom detent с поведением системного
large detent при фокусе, сохраняя размер после скрытия клавиатуры. Это гипотеза,
в текущем кандидате такое изменение не сделано.

## Контроль окружения и контрфактическая проверка

Временный patch только формы задачи переводил панель в системный `.large`
при фокусе поля. На скриншоте панель действительно стала полной высоты,
но клавиатура осталась за экраном. Patch полностью удалён; readers и другие
панели не менялись. Evidence — `keyboard-large-diagnostic/`.

Отдельный ранее существовавший `SupportFormUITests` также завершился timeout
видимой геометрии настоящей клавиатуры в полноэкранной форме. Evidence —
`keyboard-support-control/`. Следовательно, наблюдение не ограничено task sheet.

В `chat-reliability-and-sync/qa/2026-10-28-simulator-settings-restored/report.md`
зафиксировано возвращение Software Keyboard в off на этом же UDID. Текущие
кадры согласуются с этим состоянием: есть accessory «Готово», нет клавиш.
Mac заблокирован, CUA не даёт подтвердить или изменить scoped-настройку.
Поддерживаемого отдельного API переключения в этой сессии нет; глобальные
настройки не менялись, обход UI и повторный запрос разрешения не применялись.

Следующий шаг: по уже данному разрешению включить Software Keyboard только
тестового iPhone штатным управлением, повторить `sheet-task`/`sheet-gestures`
и вернуть исходное состояние после QA. До этого keyboard-case не получает pass.
