# Предварительный просмотр новой композиции чата

Проверяющий: `/root/feature_acceptance`. Дата подготовки: 27.10.2026.

Объект — неподтверждённый
[Telegram-inspired прототип](../../assets/revisions/2026-10-27-telegram-chat/index.html),
а не приложение somewhere. Это ограниченный независимый просмотр по поручению
координатора, не feature-run, не `design:ready` и не `exploratory-test`.
Старый feature-plan не запускается; результатов приёмки нет.

Прочитаны README и публичное исследование ревизии, chat-composition,
chat-reactions, preparation-tasks, соответствующие разделы UX и правила
`product-copy-editor`. Источники Telegram используются в пределах описанного
исследования, не как проверка живой актуальной версии Telegram. Личные чаты
не открываются.

До отдельного GO выполнено только чтение. Браузер, сервер, устройства и сборки
не запускались; автор продолжает подготовку ревизии. Перед живым проходом
будут зафиксированы hash входов и наблюдаемая среда. Изменение файлов во время
прохода будет отмечено, а результаты разных ревизий не объединятся.

## План связной цепочки

| Переход | Что наблюдать |
| --- | --- |
| Черновик → выделение → эмодзи | Вставка в середину и замена выделения без отправки; остальной текст, курсор и контекст разговора |
| Поиск → результат/пустой поиск → клавиатура | Русский запрос, очистка только поиска, последовательная вставка, возврат к текстовому вводу |
| Быстрая реакция → полный выбор → повтор | Видна связь с конкретным сообщением, выбор не меняет черновик, собственная реакция снимается повтором |
| Счётчик/люди → фильтр → закрытие | Имена без контактов, просмотр не снимает реакцию, возврат к тому же сообщению |
| Сведения → настройки → закрытие | Компактные поля, доступные действия и возврат к сведениям/тому же чату без второй активной поверхности |
| Карточка задачи → подробности → действие/закрытие | Предложение отличается от принятия и выполнения; видны допустимые по роли действия; подтверждение отказа/отмены; нет повторного объяснения тех же фактов |

Основной проход — 390 × 844. Через реальные controls workbench повторяются
ключевые переходы на 320 × 760 и 390 × 430. В журнале будут записаны точные
действия, наблюдения и целевые screenshots, а не только итоговые картинки.
Используется один браузерный worker и отдельный QA-каталог; исходники,
эталоны, токены, кейсы и checkbox проверяющий не меняет.

## Границы

Макет хранит вымышленные данные в памяти вкладки. Реальные API, сохранение,
авторизация, идемпотентность, загрузки, конфликты и отзыв доступа здесь
не проверяются. Компьютерная эмуляция размеров не проверяет native IME,
VoiceOver/TalkBack, безопасные области или жесты физического телефона.
Системная кнопка клавиатуры в макете подтверждает только доступный браузерный
фокус. Отдельное дизайн-решение пользователя и последующая публикация/перенос
в клиенты остаются необходимыми.
