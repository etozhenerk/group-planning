# Подготовка живой iOS QA-сессии

Это подготовка окружения для отдельного ревьюера, не результат приёмки.
27.10.2026 после отдельного GO fixture запущен:
`https://127.0.0.1:65056`, GET `/api/v1/me` подтвердил HTTP 200.
Безопасные идентификаторы и время истечения сессии — в `live-receipt.json`.
Статус процесса проверяется перед приёмкой; наличие этого отчёта само по себе
не подтверждает, что сервер всё ещё работает.

## Артефакт и сценарий

- Устройство: существующий iPhone 18 Pro / iOS 27.0,
  `31262733-50DC-46A5-938E-4C462D70F109`; без wipe и создания устройств.
- Bundle: только `dev.groupplanning.ios.uitesthost` (somewhere QA).
- Артефакт: сохранённый run04, DS 1.4.1,
  `.cache/qa/2026-10-27-telegram-chat/ios-implementation/run04/SomewhereUITestHost.app`.
- SHA-256 набора 12 файлов:
  `840e376778f1048deb9f6a326142e39531bd7eedb6c691215f11d5e85a3cdbd7`.
  Алгоритм: SHA-256 UTF-8 строк `relativePath + NUL + fileSHA256 + LF`,
  в порядке `run04/artifacts.json`.
- Имя сценария запуска — **`design`**, не `chat-sheet`:
  `SIMCTL_CHILD_SOMEWHERE_UI_SCENARIO=design` перед `xcrun simctl launch`.
- Fixture scope — `accessibility`: реальный API на отдельном memory.Store;
  строгие завершающие assertions других тестовых наборов не запускаются.
- Проверяемая встреча: `deb00000-0000-4000-8000-000000000002`, «Настолки у Саши».
  Аккаунт — Саша, организатор; заготовлены сообщения, реакции и принятая Мишей задача.
- У того же аккаунта роль участника во встречах «Ужин в пятницу» и
  «Воскресенье без планов». Для отдельных поведенческих fixtures существуют
  `task-owner`, `task-recipient`, `task-decline`, `task-cancel`, `poll-owner`,
  `place-owner`; переход к ним требует перезапуска только QA app с другим
  значением переменной сценария, сервер менять не требуется.

## Запуск и границы

Подготовленный локальный launcher (в игнорируемом каталоге):
`.cache/qa/2026-10-27-telegram-chat/ios-implementation/live/start.sh`.
Перед запуском он проверяет все хэши app, использует общий simulator lock,
компилирует opt-in `TestIOSFixture` в отдельный бинарник и запускает TLS на
`127.0.0.1:0`. После появления конфигурации устанавливает сохранённый QA app
без удаления контейнера, копирует private config с правами 0600 и запускает
сценарий `design` с русской локалью и стандартным размером текста.
Обычный bundle `dev.groupplanning.ios` не устанавливается и не завершается.

Настройки и тестовые credentials находятся только в игнорируемом
`.cache/qa/2026-10-27-telegram-chat/ios-implementation/live/config.json`
и в `tmp/ui-fixture.json` контейнера QA. Содержимое этих файлов не печатается
и не включается в evidence. `receipt.json` содержит только реальный origin,
PID, безопасную идентичность артефакта, сценарий и результат GET `/api/v1/me`.
Проверка HTTPS использует сертификат fixture, без отключения TLS-validation.

Launcher остаётся живым до остановки fixture. В отдельной review-сессии
действия с продуктом выполняет независимый агент. Подготовка не делает кликов,
не открывает панели и не проходит сценарии вместо него. По сигналу основного
агента завершить записанный PID fixture через SIGTERM: launcher освободит lock.
После остановки API сохранённое приложение само по себе не считается работающим
окружением приёмки.

## Инженерная проверка run05

Штатная команда из `frontend/ios`: `sh scripts/build.sh Debug all`.
Она выполняет `clean build analyze` для `generic/platform=iOS Simulator`,
две задачи Xcode, без установки приложения и подписи production-артефакта.
Unit137 и UI3 не повторяются при неизменных исходниках после run04;
результат build/analyze будет сохранён отдельно от этих проверок.
