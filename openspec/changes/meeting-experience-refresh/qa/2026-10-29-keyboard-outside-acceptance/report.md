# Скрытие клавиатуры вне сообщения · 29.10.2026

Реализация добавлена в web, iOS и Android. Короткое нажатие вне поля сообщения снимает его фокус; native скрывает экранную клавиатуру. Черновик и выделение сохраняются. Send, плюс, emoji и шапка продолжают работать первым нажатием; фокус другого поля, прокрутка и long press не перехватываются. Push-уведомления отложены по решению владельца до активной программы Apple Developer.

## Реализация

Web слушает завершённый click, не pointerdown: это не сдвигает кнопку до регистрации нажатия при скрытии mobile keyboard. Клавиатурные события с detail=0 пропускаются. iOS использует наблюдающий UITapGestureRecognizer без отмены касаний; Android наблюдает завершённый tap после дочерних обработчиков, не потребляя pointer events. На обеих native платформах снимается только фокус composer.

Выпущен контракт дизайн-системы5.0.0 без изменения значений токенов или композиции. UI-копирайт не изменялся. Добавлены TC-CHAT-OUTSIDE-KEYBOARD и адресные regression tests.

## Проверено

- Web: types/style/FSD,211 unit, сборка и6 Chromium/WebKit сценариев на1440/390/320px. Независимый живой browser-проход на1280/390/320px подтвердил фокус, выделение, первые действия, другие поля и отсутствие самопроизвольного возврата фокуса.
- iOS: чистая simulator-сборка/analyze,202 unit passed,1 предусмотренный skip теста защиты файлов на физическом устройстве. Три новых XCUITest прошли у автора; независимый проверяющий прошёл3+1 теста на том же артефакте с видимой экранной IME. Временная настройка минимизации клавиатуры восстановлена в true, Reduce Motion остался false.
- Android: Debug/Release, Lint,188 unit и6 адресных UI tests. Независимый ADB-проход на Android16/API36 прошёл7 состояний; проверена одна серверная запись после первого Send. QA-приложение остановлено, временный reverse удалён.

## Границы приёмки

Это проверка конкретного исправления, а не полного приложения или релизного кандидата. На физический iPhone новая сборка не установлена; настоящая mobile web IME и touch long press не проверены. У iOS нет отдельного actual кадра после возврата из формы, хотя XCUITest утверждение прошло. В iOS логе сохранён прежний warning Invalid frame dimension, наблюдаемого нового дефекта на проверенных состояниях нет.

Независимый web review нашёл прежний дефект P2-WEB-COMPOSER-GROW: многострочное поле не увеличивает высоту, часть черновика скрыта. Это не изменение нового outside-focus обработчика; TSX и CSS поля совпадают с базовой ревизией678cff24. [Описание и evidence](../2026-10-29-keyboard-outside-web-independent/defect.md). Исправление роста поля остаётся отдельным follow-up.

Объединённый design report содержит19 pass,3 needs-fixes,2 blocked только для новых24 состояний. Остальные состояния общего manifest не переоценивались; design:ready не пройден. Задачи17.1–17.4 остаются открытыми до полного требуемого gate, несмотря на реализованное поведение.

План plan.json создан как актуальный checkpoint оставшегося формального прохода после адресных проверок. Их прежние timestamps и результаты не перенесены задним числом в run.json. qa:ready не пройден: в формальном плане нет завершённых checks и полных suites. Уже выполненные адресные проверки и сборки сохранены выше; повторять их ради заполнения отчёта не стали. Receipt релизной готовности не создавался.

Production не менялся этим исправлением: web остаётся rc.14, backend rc.6. CI/workflows и автоматический деплой не изменены. Публикация нового релиза и установка на физический телефон этим checkpoint не подтверждаются.
