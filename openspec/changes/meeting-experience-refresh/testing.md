## Основные риски и уровни проверки

| Риск | Минимальный достоверный уровень | Клиентский проход |
| --- | --- | --- |
| Отсечка RSVP, точная граница, конкурентный перенос | Unit доменных правил и integration HTTP с управляемыми часами | Закрытое приглашение, foreground, повтор и сохранение действующего доступа |
| Личные поля и частичные права Яндекс ID | Identity/HTTP integration, сравнение всех публичных ответов | Собственный профиль с полными/неполными данными, чужой состав без контактов |
| Повтор после сохранения без ответа | Unit владельца запроса, integration fault после commit | Закрыть/открыть форму, повторить прежние тело/ключ, увидеть единственный объект |
| Жизненный цикл опций даты | Unit: стабильные ID, удаление первой/средней строки, поздний callback после очистки | Один основной путь создания опроса, без дублирования всех комбинаций в E2E |
| Панель, история, фокус и черновик | Тест состояния формы/навигации | Открытие поверх того же чата, закрытие X/Back/Escape/жестом, возврат, клавиатура и крупный текст |
| Выделение, Unicode и возврат к вводу | Unit: диапазон выделения, повторная вставка, grapheme boundaries; integration владельца input/focus | Один связный путь русский поиск → замена → повтор → keyboard return; отдельный Escape/Back без IME |
| Anchored reactions и список людей | Unit: message ID, фильтрация/selected state; integration focus и переключения поверхностей | Quick → full → выбор/закрытие и emoji → quick → people → фильтры; низкая высота, landscape, скролл и возврат |
| Медиа: ограничения, публикация, отзыв доступа | Integration API/bytes, частичный сбой и идемпотентность | Системный picker/отмена, превью, подпись документа, повтор только неуспешного файла |
| Реакции и альбом | Integration прав/повторов/пагинации | Установка/снятие, имена без контактов, жесты/сетка/полное фото и восстановление индекса |
| Обращения | Integration принятия, валидации, очереди, приватности | Форма без контакта, ошибка/повтор, явный скриншот и выключенная по умолчанию диагностика |

AGENTS.md и `testing/config.json`. Инженерные проверки не заменяются ручным
проходом, а наличие тестового файла не даёт `automated`.

### Данные и связные проходы

- Emoji: черновик `До XX после`, выделение `XX`, русский запрос «пицца», затем
  «сердце»; ожидается `До 🍕❤️ после`. Составные примеры `👨‍👩‍👧‍👦`, `👍🏽`,
  `🇷🇺` удаляются одним действием. Соседние символы и позиция проверяются точно.
- Реакции: два обычных сообщения с разными ID, одно с вложением, системное
  событие; у выбранного сообщения несколько людей/эмодзи. Просмотр и фильтрация
  людей не являются toggle. Для ошибки/потери ответа/отзыва доступа — управляемый
  fault fixture; результат перечитывается другой синтетической сессией.
- Состав: организатор Саша; Лена/Тимофей/Маша — «Приду»; Оля — «Возможно»,
  Дима — «Не смогу». Компактно 4 текущих, три имени/+1; раскрыто 6 ответов.
  Изменение RSVP одного «Приду» даёт 3 текущих без +1, поэтому demo-константа
  не удовлетворяет кейсу. После expand фокус на видимой кнопке сворачивания,
  после collapse — на кратком составе.
- Панели: история длиннее viewport, исходный участок выше конца, черновик
  сообщения и формы. Проверяются возврат родителя, фон, footer/bottom bar,
  отсутствие пустого резерва после закрытия и прежние error/retry semantics.
  Настройки — под организатором и обычным участником; задачи — под автором,
  организатором, адресатом/исполнителем и посторонним текущим участником.

Desktop не объявляется мобильным клиентом: общие emoji/reaction операции
проверяются в широком web; действия «+» используют модалки поверх чата, sidebar
сохраняется. Mobile web проверяется на 320/390, low-height 390 × 430 и landscape
844 × 390; 768/1440 остаются в общей responsive-матрице по опубликованному
breakpoint. CSS-scale workbench не доказывает mobile IME или touch target.
iOS/Android требуют собственного работающего клиента и действительных доступных
клавиатуры, ориентации, safe area и увеличения текста; недоступное — blocked.

## Web no-zoom · дополнение 1.4.1

Перед обновлением кейсов полностью прочитаны изменённый requirement
«Управление панелями на телефоне» и все его сценарии, включая новый «Фокус поля
на мобильном web». Он фиксирует уже обязательное [правило от 25.10](../gathering-activity-feed/mobile-scroll.md),
не выводит ожидание из текущего кода. Все фокусируемые текстовые поля телефона
(composer, поиск, input/textarea/select форм и readonly Share) имеют минимум 16 px;
пользовательский zoom не запрещён. Native сохраняет прежнюю типографику 15
и платформенное масштабирование.

`TC-CHAT-F00844F6` и `TC-CHAT-8FCD1231` пересмотрены в части web-полей и источников;
их ID, уровень, три платформы, automation/health и прежние шаги сохранены.
Добавлен только web-кейс `TC-CHAT-WEB-NO-ZOOM` (`e2e`, `planned/unknown`),
с предусловиями, шагами фокуса/клавиатуры/zoom, expected и cleanup. Он связан
с web-задачами 4.5/4.9. Общая 0.1 сохраняет прежние platform/case пары, включая
два уточнённых кейса; web-only кейс не создаёт фиктивные native-обязательства.
`testing/config.json` уже регистрирует chat-composition spec, новый UX-файл
не добавляется как самостоятельная OpenSpec capability.

Минимальный автоматический слой — browser integration для computed font-size
и viewport meta на 320/390 и WebKit 402×874; основной связный E2E путь —
composer → emoji search → поле панели → закрытие IME/возврат. Реальный Safari
на доступном iPhone отдельно подтверждает отсутствие случайного focus zoom,
доступность пользовательского pinch zoom и восстановление после клавиатуры.
Resize/VisualViewport эмуляция и CSS-scale workbench не доказывают системную IME.
Недоступный Safari/физический ввод фиксируется blocked; вычисленные 16 px сами
по себе не дают полного pass. Наличие текущего test-файла не меняет automation.

Новые plan/run paths выделены в `qa/2026-10-27-telegram-chat-1.4.1/`; прежние
планы, результаты и evidence не переписываются. Phase checkpoint; новые
passed/automated не добавлялись, product gates остаются открыты.

## Окружения и ограничения

1. Feature использует отдельный работающий Go memory fixture с синтетическими
   профилями и явными часами. Backend integration не требует UI-клиента.
   Проверка строки прежнего API-запроса не является запуском старого бинарника.
2. Web: реально собранные production/demo, desktop и mobile профили, widths
   320/390/768/1440. Низкий viewport и масштаб CSS не подменяют настоящую IME,
   browser zoom или системную отмену выбора файла. TLS/доступ к origin сначала
   проверяется тем же инструментом независимого QA.
3. iOS: отдельное QA-приложение и выбранный существующий симулятор; не удалять
   обычную сборку/данные. Реальный VoiceOver требует доступного устройства;
   AX или screenshot без действий не равны такому проходу. Старый Photos
   picker с `PUPickerUnavailableView` сохранён как failed. Диагностический повтор
   27.10 прошёл 2/2 без изменения кода/assertions; причина прежнего зависания
   пока не установлена, результат не переносится на новые сборки.
4. Android: только согласованное QA-устройство `emulator-5554`, когда оно доступно;
   пользовательский `emulator-5556` не трогать. Не сбрасывать и не клонировать AVD.
   Крупный текст, IME, orientation и animation scales восстанавливаются после теста.
5. Известные фото/синтетический PDF; в evidence не копируются неизвестные личные
   Photos-grid, токены, cookie и реальные контакты. Обращения/уведомления —
   только мок или изолированный тестовый канал без реальных получателей.
6. Облачные `7.2`, `8.9`, юридические входы `8.8` и релиз `7.3` не запускаются
   ради закрытия feature-плана. Отсутствующие утверждения/доступ дают blocked;

   должны быть названы и реально запущены, иначе совместимость остаётся blocked.

Тяжёлые сборки, эмуляторы и браузерные прогоны выполняются последовательно.
Отдельные source-only правки не разрешают соседний тяжёлый прогон.

## Независимая приёмка

После стабилизации исходников/сборок создать feature-план через `qa:plan` с
фактическими окружениями backend/web/iOS/Android и кейсами manifest. Для
поэтапной проверки допустимы отдельные диагностические прогоны; они не дают
закрыть общий task без всех его case/platform пар в актуальном принятом плане.

Для feature-плана используется `web-responsive`: управляемый браузер на Mac
с режимами и viewport, выбранными по условиям каждого кейса. В журнале каждого
прохода фиксируются реальные размеры, touch/desktop mode и выполненные действия.
Кейсы, требующие 320/390/768/1440, проходят все четыре ширины; desktop-only
проверяются в широком режиме, touch landscape — в соответствующем контексте.
Это 302 case/environment пары (16 backend, 98 web, 94 iOS, 94 Android),
все 116 уникальных кейсов включены, в том числе все прежние 100. Профили выпуска `web-desktop`/`web-mobile`
и полная дизайн-матрица не меняются. Эмуляция viewport/touch не подтверждает
физический телефон, системную клавиатуру или picker: недоступные действия
остаются blocked. Профиль не используется для исключения неудобных предусловий.

Независимому `feature-test` передаются requirements, case IDs, fixture, сборки,
план и отдельные пути отчёта/evidence, без ожидаемого вердикта. Проверяющий
проходит действия, проверяет сохранение/второй профиль и очистку, фиксирует
actual/defect; недоступное — blocked. Автотесты сохраняют исходные raw/log,
ручной проход — interaction log и UI evidence. Полный продуктовый проход
ещё не выполнен; `qa:check`/`qa:test` проверяют каталог/инструменты.

До checkbox обязательны актуальные `qa:ready` и для UI `design:ready` после
отдельного `design-review`. Ни количество тестов, ни компиляция, ни старый
hash/скриншот не заменяют их. Все старые отчёты сохраняются без переписывания.

## Уточнение iOS 3.0.1 · 28.10.2026

Прямые исправления пользователя после установки на iPhone: экран вайба имеет только иконку «Назад» без общего бренда и подписи «Прошедшие встречи». Название самой встречи и счётчик сохраняются. Возврат сохраняет прежний контекст списка/календаря. На iOS направления не замыкаются: влево — следующий снимок, вправо — предыдущий; на краях снимок возвращается на место. Геометрия и EXIF-ориентация принадлежат текущему photoID и не наследуются от предыдущего кадра.

Предпросмотр фото в нижней панели iOS: карточка 176×132, зазор12, видимый край следующей карточки. Крестик24 на круглом фоне выступает за верхний правый угол на6; невидимая область нажатия44, отступы карусели сохраняют её доступность. Один общий статус отправки прежний. ## Превью ссылок, 28.10.2026

TC-INV-B9E5EC51, TC-SHARE-COVER, TC-SHARE-HOME: серверный HTML без JavaScript/сессии, безопасный trusted origin, GET/HEAD изображения, замена и удаление обложки. Go проверяет приватность/escaping/fallback; web E2E — настоящий HTML и пиксели. Проход с Telegram отдельно: запрос с его User-Agent не доказывает, что Telegram получил и показал превью. Текущий production invitation возвращает HTTP200 и прежние OG; пользовательская проблемная ссылка пока ожидается. Миграций и изменения API нет, прежние мобильные клиенты совместимы.
