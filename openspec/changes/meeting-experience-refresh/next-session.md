## 1. Сначала привести релизы к утверждённому процессу через теги

Последние выпуски доставлялись прямым установщиком на ВМ, без запуска
release workflow опубликованным тегом. Это отклонение от принятого процесса.
На момент паузы в origin есть только web rc1/rc2 и backend rc1/rc2/rc3;
поздние локальные теги не опубликованы. Сегодня их не отправляли, чтобы
пуш сохранённой работы не запустил неожиданную выкладку.

Прочитать docs/releases.md и текущие release workflows; сверить production
build-info, исходные commit и SHA артефактов с тегами. Настроить/проверить путь
«новый неизменяемый тег → CI и сборка → проверенный артефакт → деплой → smoke».
Не переназначать существующие теги и не заявлять старые ручные выпуски
успешными workflow. После проверки использовать этот процесс для новых выпусков.
