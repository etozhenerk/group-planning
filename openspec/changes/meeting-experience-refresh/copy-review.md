# Редакторская проверка макетов

Применён проектный навык `product-copy-editor`. Сначала проверены назначение
блоков и повторы, затем формулировки и состояния. Технический дизайн не
используется как текст интерфейса.

| Блок | Задача текста | Решение |
| --- | --- | --- |
| Приглашения | Объяснить состав списка и следующий шаг | Постоянное описание «Возможно», без повторения в пустом состоянии |
| Карточка | Позволить узнать встречу | Название, дата, место; роль организатора заменена символом с доступным названием |
| Календарь | Вернуться к текущему дню | Короткая кнопка «Сегодня» на всех ширинах |
| Новый чат | Пригласить остальных | «Позовём остальных?» и одно действие; удалён лишний экран успеха |
| Плюс | Выбрать действие | Пять коротких пунктов, без объяснений устройства опросов |
| Профиль | Узнать свои данные | Ясные подписи полей, «Не указан»; нет обещаний будущего редактирования |
| Прошедший чат | Заметить и открыть вайб | «Как всё прошло?» до фото, «Вайб встречи» после появления фото |
| Вайб | Смотреть и добавлять фото | Нет технических текстов, пользовательских подписей и подсказок о свайпе в видимой области |
| Закрытый вход | Понять причину отказа | «Присоединиться уже нельзя» + правило часа и время начала |
| Ошибка отправки | Восстановить действие | Повтор для конкретного неуспешного файла, успешные не отправляются заново |

Точное описание приглашений:
«Здесь сохранены приглашения, на которые вы ответили „Возможно“. Когда
определитесь, откройте приглашение и измените ответ».

Слова «свайп», API, кеш, версии и разрешения токена оставлены в документации,
а не в альбоме. Названия/alt фотографий в демонстрационных файлах служат
доступности, не являются пользовательскими подписями. Технические пояснения
допустимы в индексе макетов как инструкции к демонстрации.

Перед выпуском проверить локализованные системные picker/Share, формат дат,
недоступные контакты и озвучивание динамического счётчика на трёх платформах.
Это последующая проверка реализации, а не уже пройденные нативные тесты.
