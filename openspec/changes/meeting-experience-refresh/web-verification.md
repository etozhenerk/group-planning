# Проверка web: meeting-experience-refresh

## Область реализации

Изменены только web-клиент и его проверки. Серверные функции используют общий
API из implementation-api.md. Приложение не содержит демонстрационных встреч,
фиктивных контактов, результатов отправки или локального обхода прав доступа.
Тестовые данные находятся в Go fixture и browser-сценариях.

- Навигация, карточки, календарь и приглашения перенесены на новые композицию,
  размеры, цвета даты, обложки, превью участников и корону организатора.
  Создание сразу открывает чат; старый адрес подтверждения переводит туда же.
- Меню чата содержит пять действий; эмодзи вставляются в позицию курсора без
  отправки, черновик сохраняется при переходах. Каталог — 3944 эмодзи
  Unicode 17.0 / CLDR 48 с русскими названиями и поиском.
- Сообщения имеют отдельный вариант аватара, метаданные, скругления и ширину
  из макета. Карточка задачи раскрывает действия, не растягивая закрытое состояние.
  Строки «Новая задача · имя» и «Исполняет имя» не предполагают пол пользователя.
- Реакции читаются пачками; повтор и снятие подтверждаются API. Ошибка возвращает
  подтверждённое состояние, повтор сохраняет ключ операции. Список людей
  не содержит контактов и открывается из панели реакций.
- Выбор фото/документа открывает отдельный `/meetings/:id/upload`.
  Отдельные прогресс, отмена выбора и повтор сохраняют успешные файлы без дублей.
  У документа есть подпись; у фото/альбома её нет. Выбор очищается при уходе,
  а черновик сообщения сохраняется. Перезагрузка требует выбрать файл заново.
- Вайб-баннер, стопка, сетка и полный экран работают с серверным `period`.
  Фото альбома не создаёт сообщения. Индекс сохраняется при переходах и Back;
  предусмотрены короткий drag, свайп, клавиатура, Escape и reduced motion.
- Профиль показывает только свои данные, отдельно обрабатывает недостающие
  контакты и ошибку загрузки. Панель «Личные данные» содержит логин, имя,
  фамилию, дату рождения и пол. Nullable/optional поля совместимы со старым API;
  неизвестные части даты не подставляются. Сохранены выход и удаление аккаунта.
- Предложение даты/места/задачи — полноценные страницы `?action=date|place|task`
  с Back/Escape и историей браузера. Скрытые формы сохраняют черновики и ключи
  неопределённой отправки в памяти. Пояснение «Почему здесь» реально отправляется
  в API и показывается в карточке опроса; фотографии/альбом пояснений не получают.
- Обращение отправляется в публичный API, необязательные поля не дополняются
  автоматически. Успех требует серверный номер. Есть повтор потерянного ответа
  с прежним ключом, ошибки полей и сохранение формы.
- Help, About, проекты Privacy/Cookies используют согласованные тексты.
  Версия берётся из build identity соседнего release-изменения.

## Последние решения пользователя и границы макетов

1. Футер только на desktop onboarding: `/`, ширина от 740 px и основной
   указатель hover/fine. На всех внутренних страницах и мобильном web, включая
   горизонтальный телефон 844×390, футера нет. Старый дублирующий футер удалён.
2. Нижняя панель только на списке/календаре встреч, списке приглашений и основном
   профиле. На создании, чате, share/upload, альбоме, сервисных страницах и
   онбординге её нет. Desktop sidebar сохранён. Резерв под отсутствующую панель
   убран. Эталонные HTML/PNG с прежним футером/панелью не изменены.
3. Блок «Обложка» при создании сохранён по прямому ответу пользователя.
   Это раскрываемое дополнение после основных полей; его нет в create.html.
   Существующие timezone/date-only/DST и удаление аккаунта также сохранены.
4. На мобильном экране дата — компактная кнопка 13 px (12 px на 320), полный
   год виден; календарь, ввод и очистка находятся в доступном Popup. Редактируемые
   поля, включая время и support, имеют минимум 16 px против автоматического
   масштабирования Safari. Это обусловленное платформой отличие от мелкого
   текста input в статическом HTML. Иконки даты и времени справа.
5. «Кто отреагировал» добавлено под быстрым рядом в открытом popover:
   эталон показывает реакции, но не задаёт переход к обязательному списку людей.
   В закрытой ленте дополнительная текстовая кнопка отсутствует.
6. Проекты Privacy/Cookies явно обозначены как проекты. Данные оператора
   отложены владельцем; они не выдуманы. Это не готовая юридическая публикация.

## Визуальные материалы

Пары сохранены в [галерее](assets/verification/web/README.md).
Основные экраны проверяются на 320, 390, 768 и 1440 px; заполненный чат,
реакции, upload, сетка и полноэкранное фото дополнительно на 390/1440 px.

У actual есть только тестовая плашка «Демостенд» высотой 32 px; в release её нет.
Она сдвигает верхнюю координату приложения и сокращает фиксированную высоту чата.
В обычном fixture данные отличаются от макета (даты, названия, число участников,
номер обращения и версия). Это не скрытое изменение макета. Для заполненного
чата используется общий native design fixture с одинаковыми тремя сообщениями,
шестью участниками, задачей и реакцией ❤️ 2. У системной строки задачи и статуса
используются согласованные нейтральные формулировки.

## Что осталось после паузы

1. Финальная визуальная приёмка координатором новых profile/action/upload-file
   пар. Небольшое различие margin заголовка личных данных записано выше.
   В select задачи остаётся прежнее «Любой участник», в reference —
   «Любому участнику». После команды паузы это намеренно не исправлялось.
2. Формы сохраняют существующие правила: минимум две даты, срок опроса,
   timezone/DST. Поэтому форма даты шире по набору полей, чем статический
   переходный action-date.html с одной датой. Мобильные input16px и область
   checkbox44px — адаптация для ввода/доступности.
3. Общая проверка web/iOS/Android. Web-only этап уже реально отправил через UI
   rules.txt с подписью, фото в чат и фото общего альбома и дошёл до ожидания iOS.
   После этого исправлены два селектора harness: доступная метка короны в
   карточке и ожидание URL перед чтением albumId. Повтор до окончательного
   marker `{id, invitation, albumId}` на свежем fixture **не выполнен** из-за паузы.
   Полный межклиентский сценарий не считается пройденным.
4. `agent:check` после обновления отчёта/галереи и итоговая проверка diff
   перед коммитом выполняются координатором. Коммиты/push агент web не делал.

## Остановка и ограничения

Последняя последовательная команда завершилась до паузы. Отдельный cross fixture
и его Playwright ранее остановлены; сессия финального visual завершена с кодом0.
На порту8444 слушатель не обнаружен. Общее перечисление процессов через pgrep
в этой среде недоступно; чужие процессы не завершались.

Playwright проверяет Chromium и мобильный WebKit; это не проверка системной
клавиатуры, панели выбора файла и реального Safari на физическом iPhone.
Юридические реквизиты и деплой не выполнялись. Изменения release tooling другого
агента сохранены и не относятся к реализации этого пакета.
