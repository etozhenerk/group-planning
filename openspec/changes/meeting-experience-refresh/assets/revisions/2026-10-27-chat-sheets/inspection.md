# Проверка исходных макетов — 27.10.2026

Проверил исполнитель `/root/web_continue`. Это проверка нового **источника
дизайна**, а не независимая приёмка приложения. Ревизия остаётся неопубликованной
до обновления authority/manifest координатором. Старые HTML и исторические
evidence не изменены.

## Финальный проход

- Chromium 156.0.8078.4, Node 22.22.3, macOS 27.0.1 (26A434).
- Один браузер, локальный HTTP `127.0.0.1:8784`; сервер и браузер остановлены
  после проверки, порт свободен. 8782 и 8444 не менялись.
- Locale ru-RU, Europe/Moscow, DPR 1, text scale 1, reduced motion.
- 320×844, 390×844, 768×1024, 1440×1000. По 10 состояний на ширину: 40 PNG.
- Шрифт — исходный web stack `Inter, -apple-system, BlinkMacSystemFont,
"Segoe UI", sans-serif`, без загрузки/подмены шрифта. Записан вычисленный stack;
  фактическое fallback-семейство через CDP не измерялось.

Машинные результаты, исходные hash и геометрия каждого состояния:

Проверки выполняются воспроизводимым [verify.ts](verify.ts).

## Живые проверки

Все следующие проверки прошли на четырёх ширинах:

1. Черновик чата → плюс → форма места → ввод → X/desktop Back → чат.
   Черновик чата сохранён.
2. Browser Forward возвращает ту же форму и её введённое пояснение.
   Escape закрывает действие и возвращает чат.
3. Сведения → «Пригласить друзей» → Close/Back → сведения → browser Back → чат.
   Одновременно ровно один открытый `dialog`, на mobile — один `dialog:modal`.
4. Горизонтального overflow у страницы и панели нет на всех 40 состояниях.
   Нижняя навигация, футер и review-подписи отсутствуют. Сервисных ссылок
   внутри активной панели нет.

На 320/390 выполнен дополнительный stress: доступная высота панели 430 px,
CSS font-size тела формы 200%, прокрутка к концу. X остаётся в viewport,
доступен для нажатия и закрывает панель. Снимки:
[320](render-final/action-date-constrained-320.png),
[390](render-final/action-date-constrained-390.png).
Это синтетическая ограниченная область и увеличение текста части содержимого,
**не** проверка настоящей экранной клавиатуры, browser zoom, Dynamic Type
или крупного текста всей native-платформы.

Отдельно выполнена проверка **настоящего viewport 320×430 и 390×430** через
`page.setViewportSize`, без CSS-подмены доступной высоты. Длинная форма прокручена
к CTA; заголовок и X остались на месте, CTA виден целиком. Крестик закрывает
панель с первого нажатия. Горизонтального overflow нет. Верх панели — 48 px,
низ — 430 px; прокрутка тела составляет 207/165 px соответственно.
Оба снимка просмотрены исполнителем:
[320×430](render-compact/action-date-320x430.png),
[390×430](render-compact/action-date-390x430.png).
Результаты и hash — [render-compact/checks.json](render-compact/checks.json),
воспроизведение — [verify-compact.ts](verify-compact.ts).
Это проверка низкого окна браузера; реальный IME и browser zoom по-прежнему
остаются отдельными проверками. Исходные 40 PNG не перезаписывались.

## История исправлений этого черновика

Первый вспомогательный тест останавливался из-за неоднозначного селектора
«Добавить к встрече» (меню и ссылка). Селектор ограничен ссылкой; поведенческие
ожидания не ослаблялись.

Промежуточные [render-check](render-check/) сохранены отдельно с исходными
`capture-inputs.json`; они не являются финальными снимками и содержат старые
служебные review-подписи в desktop upload. После просмотра исправлен генератор
удаления подписи и выполнен полный финальный проход. Затемнение/blur переведены
на смысловые роли из DS с теми же исходными значениями.

`agent:check`, форматирование и strict TypeScript для трёх авторских TS-файлов
прошли. При standalone tsc явно указаны `--types node`, ES2022/ESNext/Bundler,
DOM/ES2023; первый запуск без Node types не являлся подходящей конфигурацией.

## Ограничения

Границы coverage из README сохраняются: нет нового эталона настроек, подробностей
задачи, reaction people и полной multi-date формы. Упрощённая `action-date` —
только демонстрация принятой оболочки. Backend, Clipboard API, настоящий picker,
network retry, экранный диктор, IME, native-рендер и native-взаимодействия этим
статичным прототипом не проверяются. Переносить результаты этой проверки в pass
приложения нельзя.
