# Предварительное независимое web-ревью

Production build собран после pre-run context `8fbeb74a18c7b2144ccb475179e259c39842e165ae41d50e9303054de1999d48`.
QA-исходники в это время дорабатываются, поэтому это предварительная серия для
поиска расхождений, не финальный pass. `source-context.json`, `build-dist.json`
и `run.json` фиксируют источник и сборку. Browser Chromium 156.0.8078.4,
Darwin 27.0.0, ru-RU, Europe/Moscow, scale 1, viewport 320/390/768/1440 × 1000.
Системные `.SF NS` fonts измерены CDP на первых 70 текстовых UI-узлах; это
выборка фактически отрисованных шрифтов, не только CSS stack. Sidecar у каждого
снимка содержит результаты. Input даты raw HTML отображает нативный формат
браузера, actual использует локализованный компонент: это не pixel comparison.

## Выполнено и просмотрено

Все 40 PNG верхнего уровня лично просмотрены: actual/reference списка, меню,
форм даты, места и задачи на каждой из четырёх ширин. Хеши — `viewed-images.json`.
Выполнены вход через изолированный fake-provider той же fixture, переход из
списка в чат, плюс, выбор трёх форм, ввод задачи/места/пояснения, закрытие,
повторное открытие с сохранением введённых значений. Меню закрыто Escape с
возвратом фокуса на «Добавить к встрече». Журнал — `interactions.json`.

На mobile формы — нижние панели над затемнённым/размытым чатом, крестик видим;
основной навигации/футера нет. На desktop геометрия колонки, отступы и иерархия
заголовков согласованы с raw и опубликованными action-токенами. Два варианта
даты и раздельный ввод даты/времени — действующее поведение, не расхождение с
устаревшей одновариантной HTML-формой. Фокус после fill виден. На всех кадрах
нет горизонтального переполнения. Это не подтверждает real mobile IME,
увеличенный текст, ошибки, отзыв доступа, pending retry и reduced motion.

## Наблюдаемые расхождения

1. **Текст CTA предложения места.** Actual `action-place-{width}.png`: «Создать
   опрос». Reference `action-place-{width}-reference.png`: «Предложить место».
   `docs/design/content.md` закрепляет «Предложить место» как запуск опроса;
   iOS использует опубликованную подпись. Расхождение содержимого, не ошибка API.
2. **Дополнительные короны в стеках аватаров.** Actual `list-{width}.png`
   показывает корону над аватаром организатора на каждой карточке. На своей
   встрече получается ещё одна корона рядом с названием. Raw `list.html`
   показывает стеки без корон; `meeting-card.md` описывает корону возле названия
   как собственную роль «Вы организатор». Наблюдение передано исполнителю как
   композиционное отличие.
3. **Обрезанный header на 320.** Actual `menu-320.png`: «Настолки у Са…»,
   «6 участников · 31 октя…». Reference `menu-320-reference.png` переносит
   обычное название и дату, оставляя их полностью видимыми. На 390 проблема
   не проявляется. Это header чата; action-sheet заголовки на 320 переносятся
   корректно. Явного исключения для single-line ellipsis в контракте нет.

## Первая попытка harness

`attempt1/` сохранён отдельно. После reopen формы Escape был отправлен ещё
во время `data-motion=opening`; следующий click упёрся в оставшийся dialog.
Второй прогон явно ждёт стабильную панель и её скрытие и завершился. Это
не объявлено дефектом продукта и не выдано за проверку Escape формы.

Общий report не финализирован. Pixel regression не запускалась. Финальная
приёмка потребует общей заморозки и свежей проверки оставшейся матрицы.
