# Удаление аккаунта — текущий UX

## Действующая коррекция 28.10.2026

Пользователь скрыл вход в удаление на web, iOS и Android. В профиле нет
кнопки или пункта удаления, в том числе в дереве доступности; просмотр и
возврат во встречи не вызывают DELETE /me и сохраняют профиль/сессию/встречи.
Подтверждение удаления из исторического UX v1 ниже не показывается.

Композиция профиля следует опубликованному
[макету](../meeting-experience-refresh/assets/profile.html),
[актуальным уточнениям](../meeting-experience-refresh/ux.md) и контракту
[навигации](../../../docs/design/components/navigation.md): выход внизу,
без удаления и номера версии в профиле; сведения о сервисе открываются из
профиля и возвращают на предыдущую поверхность. Более поздние уточнения
владельца имеют приоритет над историческим HTML.

Для этого изменения отдельно принимаются текущий профиль, доступные действия,
увеличенный текст и корректный возврат; на web также клавиатурный фокус.
Полный редизайн FAQ/About, вайбов и чата остаётся в meeting-experience-refresh,
его состояния этим узким профилем не принимаются. Операция API, атомарность,
преемник и cleanup ранее начатого удаления остаются прежними.

## Исторический UX v1 · точка входа скрыта


## Сценарий и переходы

Меню профиля → «Удалить аккаунт» → подтверждение → отправка → завершение.
До подтверждения «Отмена», Escape/назад и закрытие сохраняют аккаунт.
Во время отправки повторное нажатие, выход из аккаунта и закрытие подтверждения
недоступны. Системное завершение приложения не считается успешным удалением:
при следующем запуске сохранённый ключ позволяет повторить тот же запрос.

## Макет подтверждения

```text
┌──────────────────────────────────────────┐
│ Удалить аккаунт?                         │
│                                          │
│ Профиль и доступ к нему будут удалены.    │
│ Сообщения в общих встречах останутся      │
│ с подписью «Удалённый аккаунт».           │
│                                          │
│ Организатором станет первый вступивший   │
│ из оставшихся участников «Приду».         │
│ Встречи без таких участников удалятся.   │
│                                          │
│ Отменить удаление после подтверждения    │
│ не получится.                           │
│                                          │
│ [ Отмена ]       [ Удалить аккаунт ]      │
└──────────────────────────────────────────┘
```

На узком экране кнопки располагаются вертикально; содержимое прокручивается
при большом системном тексте. Опасное действие использует существующий
destructive-стиль. Не вводим подтверждение паролем Яндекса или набор слова
«удалить»: подтверждение уже отдельное и описывает последствия.

## Состояния

| Состояние | Отображение и действие |
| --- | --- |
| Подтверждение | Текст последствий, «Отмена», «Удалить аккаунт» |
| Отправка | Спиннер внутри кнопки вместо текста; доступная подпись «Удаление аккаунта»; остальные действия заблокированы |
| Неизвестный результат / сеть / 5xx | «Не удалось подтвердить удаление. Проверьте подключение и повторите.»; кнопка «Повторить» использует прежний ключ |
| 401 до удаления | «Сессия закончилась. Войдите снова, чтобы удалить аккаунт.»; не сообщать, что аккаунт удалён |
| 403 | «Не удалось подтвердить запрос. Откройте страницу заново.»; без ложного успеха |
| Подтверждённые 204 | Очистить приватные данные клиента, открыть публичный экран с сообщением «Аккаунт удалён» |
| Перезапуск с незавершённым запросом | Отдельное состояние повтора до показа приватных данных; тот же ключ и те же последствия, без нового подтверждения уже отправленного действия |

Последующие обычные 401 на других устройствах завершают их сессии прежним
путём. Новый вход через тот же Яндекс ID создаёт новый пустой профиль;
встречи и голоса не восстанавливаются.

## Общая история и задачи

Подпись старых сообщений и авторства опросов/задач — «Удалённый аккаунт».
Текст сообщений и пользовательские названия не переписываются: в них могут
быть личные сведения, поэтому подтверждение обещает удаление профиля, а не
автоматическую очистку всех написанных текстов. Закрытые результаты опросов
сохраняются, имена голосовавших обезличиваются. Из открытых опросов голос
удаляется и состав пересчитывается по текущим правилам.

Предложенная лично удаляемому человеку или принятая им задача отменяется.
Задачи другим людям и общие предложения сохраняются; ответственность никому
автоматически не назначается. Завершённые задачи остаются в истории.

## Платформы и существующие компоненты

- Web: действие в блоке профиля `Navigation`, существующий `Dialog` и кнопки приложения;
  фокус внутри диалога, возвращение на вызвавшую кнопку после отмены.
  Новая feature `delete-account`, состояние запроса вне TSX. При незавершённом
  запросе восстановление выше `SessionGate`, чтобы 401 не уничтожил ключ повтора.
- iOS: действие в `MeetingHomeHeader`, отдельный SwiftUI sheet со своим
  владельцем состояния и действием SessionStore; spinner, VoiceOver,
  Dynamic Type и запрет интерактивного закрытия во время запроса.
- Android: действие в `MeetingsHeader`, отдельный Compose диалог с состоянием
  ViewModel/repository; TalkBack, системный Back, увеличение текста.

## Редакторская проверка

Три блока решают разные задачи: что удаляется, что произойдёт с компанией,
можно ли отменить. Имя сервиса и объяснение Яндекс ID не повторяются.
Успех показывается только после ответа сервера; ошибка не утверждает ни
успешное удаление, ни гарантированную сохранность аккаунта при потере ответа.
