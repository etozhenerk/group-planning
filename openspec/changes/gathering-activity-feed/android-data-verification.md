# Проверка Android: данные и состояние · 7.2

Дата: 2026-10-21. Область: только задача 7.2 изменения gathering-activity-feed.
Экраны не менялись; UI, реальный вход и весь MVP этим отчётом не принимаются.

## Результат

| Проверка | Результат |
| --- | --- |
| `sh scripts/check.sh` | Успешно: clean, ktlint, Debug/Release APK, Android Lint, JVM и instrumentation APK |
| `:app:testDebugUnitTest` | 35 тестов, 0 ошибок, 0 пропусков |
| `sh scripts/test-device.sh` | 5 тестов Android Keystore, 0 ошибок, 0 пропусков |
| Debug/Release Lint | Нет ошибок или предупреждений кода; только разрешённые Hint о версиях |

Среда: macOS arm64, Temurin 17.0.20.1, Gradle 8.14.3, SDK 36 / Build Tools 36.0.0.
Чистая проверка завершилась за 55 секунд. Instrumentation — 32 секунды на
единственном уже запущенном Pixel_XL_API_36 / Android 16 (emulator-5554).
Новые эмуляторы не запускались. Основные Go/web demo-сервисы не перезапускались.

Первый прогон завершился внутренним падением JIT старой Java 17.0.6 из Android
Studio (`assembler_aarch64.hpp`, C1, Kotlin UAST). Повтор на Temurin 17 прошёл.
JDK загружена во временную папку с проверкой официального SHA-256; настройки
системной Java и ограничения Gradle по CPU/памяти не менялись.

## Соответствие задаче

- `data/api` — OkHttp, сериализуемые DTO и запросы существующего API.
  Общие contracts/fixtures подключены как test resources без дублирования.
  Проверены все 13 fixture cases, nullable/отсутствующие поля, UUID, RFC3339
  с offset/nanos, строковые счётчики выше 2^53, неизвестные kind/version.
- HTTPS MockWebServer проверяет настоящий transport: redirects и cookies
  отключены, `503 Retry-After: 0` не вызывает повтор, отмена coroutine отменяет
  OkHttp Call. Bearer и Idempotency-Key проверены отдельными тестами.
  `401/403` сохраняют статус даже при слишком большом или оборванном теле.
- `SessionRepository` / `SessionGate` — восстановление /me, проверка срока,
  отказ хранилища, 401, выход при сетевой ошибке, очистка профиля и кеша.
  403 чтения отзывает одну встречу; 403 настроек организатора сохраняет чат.
- Проверены поздний ответ после выхода, замена сессии во время /me,
  отмена восстановления и запросов, отзыв доступа во время загрузки списка.
  Старые операции не восстанавливают отозванные приватные данные.
- `MeetingRepository` — список/детали/состав/лента, состояния пусто/ошибка/
  повтор, последняя загрузка побеждает. `MeetingListViewModel` повторно
  получается из одного ViewModelStore и отменяет запрос при его clear.
  Это проверка владельца состояния, а не UI-тест поворота Activity.
- `AndroidKeystoreTests` используют настоящий Android Keystore: сохранение
  и повторное чтение новым экземпляром, свежий IV, неэкспортируемый ключ,
  отсутствие открытого токена в файле, повреждение и потеря ключа,
  привязка ciphertext к origin, прерванная AtomicFile-запись,
  ограничение размера и удаление файла.

Тестовые ключи и файлы изолированы случайными именами и удаляются после тестов.
JVM fake transport/storage находятся только в test source set.
ClientRuntime принимает явный HTTPS origin; подставного пользователя нет.

## Ограничения и следующие этапы

- Корневой Compose-экран ещё не подключён к ClientRuntime. 7.4–7.6 добавят
  онбординг, список/создание, приглашение/ответ и чат по согласованному дизайну.
- Сборка не содержит действующего production origin и не имитирует вход.
  Реальная авторизация Яндекс ID / Custom Tabs (7.3) отложена пользователем.
- Пагинация, отправка и периодическое обновление ленты не принимаются в 7.2.
- На физическом Android и API 26 проверки не запускались; аппаратная защита
  конкретного устройства и TalkBack не проверены. Эмулятор подтверждает
  работу Android Keystore API, а не свойства аппаратного secure element.
- CI собирает instrumentation APK и выполняет JVM-набор без эмулятора.
  Результат удалённого GitHub Actions здесь не подтверждён.
