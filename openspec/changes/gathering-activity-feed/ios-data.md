# iOS: данные, сессия и состояния · задача 6.2

Затронуты iOS и его CI. Контракт, Go, web и Android не меняются.
Реальный Яндекс ID остаётся заключительным этапом; готовятся только модели
и transport существующих операций, без тестового входа в runtime.

## Компоненты

- `Data/API`: Codable-модели, строковый ServerCounter без потери точности,
  APIInstant с исходным RFC3339, неизвестный payload как данные. Неизвестный
  kind/версия не становится сообщением или исполняемым интерфейсом.
- APIClient и URLSessionTransport: только настроенный HTTPS origin,
  явный Bearer, отключённые cookies/URL cache, запрет автоматических redirects,
  обычная системная TLS-проверка и отмена дочернего запроса вместе с владельцем.
  HTTP-статус сохраняется даже при некорректном теле ошибки.
- KeychainCredentialStorage: generic-password с отдельным service/account
  для origin, `WhenUnlockedThisDeviceOnly`, без синхронизации и plaintext fallback.
  CredentialStore выполняет синхронный Security I/O вне MainActor и отвергает
  записи старого поколения после logout/нового входа.
- SessionStore на MainActor: восстановление и проверка `/me`, истечение,
  logout, смена профиля; профиль не восстанавливается из доверенного имени клиента.
  401 очищает Keychain и приватные данные, старый ответ не меняет новую сессию.
- PrivateData и MeetingRepository: наблюдаемые снимки списка/деталей/состава/ленты,
  загрузка, ошибка, отмена и повтор. 403 на чтение/сообщение закрывает только
  соответствующую встречу и отменяет её запросы; 403 на настройки из-за роли
  не отзывают доступ к самому разговору. Поколение доступа отсекает поздние ответы.

## Проверка

Добавляется unit-test target на Swift Testing. Общие `cases.json` включаются
в тестовый bundle напрямую из contracts, без поддерживаемой копии.
Проверяются fixtures, nullable-поля, неизвестный kind, строковые счётчики,
ошибки и patch null/unchanged, Bearer/ключи запросов, отмена URLSession,
Keychain, поколения, 401/403 и очистка состояния.
Симулятор тестов создаётся отдельно и удаляется скриптом; открытый симулятор
пользователя и процесс web demo не используются.

## UI и следующие задачи

Новых пользовательских сценариев в 6.2 нет: сети и состояния ещё не привязаны
к экранам. Авторизация относится к 6.3, онбординг/список/создание — к 6.4,
RSVP — к 6.5, polling/история/отправка и жизненный цикл — к 6.6.
Неприменимы новые переходы и макеты состояний для transport.
Отдельная правка уже существующего стартового экрана выполняет решение пользователя:
текущий статический знак слева и `somewhere` строчными. Анимация пока в будущем,
как записано в [брендинге](../../../docs/design/branding.md).
