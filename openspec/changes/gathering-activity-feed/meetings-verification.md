# Проверка серверного среза встреч

20 октября 2026 года. Группа 4 изменения `gathering-activity-feed`;
это проверка Go API с memory.Store, без клиентских приложений и реального Яндекс ID.

## Реализовано

- Создание с назначенным временем: встреча, ссылка, первое событие и receipt
  сохраняются одной транзакцией. UTC instant проверяется вместе с IANA zone
  и переданным смещением, включая границы DST.
- Личный список созданных/принятых встреч с курсором, приватные детали,
  повторная выдача прежней ссылки организатору.
- Публичное приглашение с собственным RSVP при действительной сессии;
  вход не сохраняет ответ и не открывает чат. Организатор не получает
  второго участия при открытии своей ссылки.
- Три ответа и оба пути их изменения, ревизии, актуальный состав и события.
  Maybe/not_going закрывают детали, состав, чтение и отправку в ленту.
- Настройки организатора, явное очищение необязательных полей, отказ при
  устаревшей ревизии. Попытка передать чужой user ID отклоняется декодером.
- Страницы ленты по sequence, исходная последняя страница, история до курсора
  и новые записи после него. Метаданные и записи берутся из одного snapshot.
- Текстовые сообщения с постоянным client_request_id, проверки повторов
  после TTL, права на каждый запрос и атомарное упорядочивание с выходом из чата.

## Выполненные проверки

Из `backend/` с Go 1.27.2:

```sh
go test -race ./...
go vet ./...
go build ./...
gofmt -l .
go run ./cmd/storage-demo
```

Все команды завершились успешно; gofmt не вывел файлов. Демонстрация:
`Вечер с друзьями: ответов — 1, событий — 2`.

Из корня с Node.js 22.22.3 и установленными зависимостями:

```sh
npm run api:test
npm run agent:check
```

OpenAPI прошёл Redocly; Ajv проверил 28 схем и 13 fixtures.
С контрактом совпали 106 реальных HTTP-ответов: статусы, JSON, no-store
и сгенерированные request ID. Включены ответы OAuth и empty 303/204.
Проверки обвязки и ссылок выполнены после обновления документов/задач.

HTTP-сценарий поднимает временный TLS-сервер с отдельными cookie-jar организатора,
гостя и постороннего. Provider выдаёт только тестовые профили и определён
в `_test.go`; запуск сервера через env его не включает. Проверены создание,
повтор после потери ответа, собственная ссылка, вход гостя без RSVP, принятие,
состав, настройки, чат, смена ответа, закрытие чтения/отправки и старый повтор
«Приду». Проверен тот же профиль с native Bearer и истёкшая сессия.
Публичный ответ и логи не содержат приватных данных.

Прикладные тесты проверяют все переходы ответов, no-op без лишнего события,
конкурентные повторы, исходную идентичность создания после изменения настроек
и TTL, сообщение после TTL, конфликт ключа с другим телом. Параллельные записи
и чтение страниц не теряют sequence; гонка сообщения и снятия going допускает
сообщение только до события выхода. Ошибка сохранения receipt откатывает
встречу, ответ, настройки и сообщение вместе с событием. Отдельно проверены
очистка receipts на границе TTL, откат, read-only и закрытая транзакция.

Для повторения первого серверного сценария отдельно:

```sh
cd backend
go test -count=1 -run '^TestMeetingOpenAPIResponses$' -v ./internal/httpapi
```

## Ограничения и следующий этап

Реальное подключение и проверка Яндекс ID отложены пользователем до конца
разработки. Автоматизированный провайдер не подтверждает работоспособность
реального OAuth-приложения. По умолчанию runtime auth выключен;
приватные маршруты отвечают 401. Подставной пользователь не принимается.

Веб, iOS и Android ещё не реализованы; проверок UI и устройств не было.
Следующий этап — веб по v0.7, с fixtures для разработки до реального входа.
Пути web `/auth/return` и `/invitations/{token}` пока не обслуживаются клиентом.
Календарь, выбор даты, голосования, задачи подготовки и обложки остаются
в MVP следующих групп и не считаются выполненными.

Memory.Store хранит состояние одного процесса: перезапуск теряет встречи,
профили, сессии и receipts. PostgreSQL, Docker и миграции не добавлены.
Сохранность на диске, нагрузка и работа нескольких экземпляров не проверены.
Группа 4 не завершает изменение и не является основанием для его архивации.
