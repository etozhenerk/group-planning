# Проверка мобильного входа через Яндекс

Дата: 24 октября 2026 года. Области: Go API, iOS, Android, локальная обвязка.

## Реальный вход

Пользователь подтвердил успешный вход в обычных локальных сборках на iOS и Android
через официальный Yandex LoginSDK. Проверен вход с онбординга и возврат в приложение.
Сервер работает через ngrok; собственный домен или деплой для этой проверки не нужен.
OAuth secret остаётся в игнорируемом серверном окружении.

Первую попытку iOS не удалось завершить, когда локальный API и туннель уже были
остановлены. После запуска серверной обвязки отдельным фоновым процессом новый вход
успешен. Старая попытка после перезапуска memory.Store непригодна для обмена.
На Android отдельно появлялась системная форма Google; обычный LoginSDK затем
открыл `passport.yandex.com`, пользователь завершил вход через Яндекс.

## Реализация

- iOS: LoginSDK 3.2.0 через Swift Package Manager; callback по `yx<client_id>`,
  обработка Universal Links, состояние попытки в Keychain.
- Android: LoginSDK 3.1.3 через Maven Central; Activity Result, сохранение попытки
  с AES-GCM/Android Keystore, ожидание восстановления сессии перед обработкой результата.
- Сервер: `POST /api/v1/auth/mobile/sdk/exchange` проверяет одноразовую попытку,
  app verifier, профиль и client ID у Яндекса, затем выдаёт собственную сессию.
  Прежний callback/handoff сохранён для совместимости клиентов.
- Сессия сохраняется до загрузки `/me`; сбой сети позволяет повторить проверку
  профиля без повторного OAuth. Приглашение сохраняется, RSVP автоматически не отправляется.
- Кнопки показывают только индикатор, блокируют повторные нажатия и возвращаются
  в доступное состояние после ошибки/отмены. Ошибка доступна и поверх приглашения.

## Проверки

- Go: полный `go test -race ./...`, vet, проверка зависимостей и build прошли.
  После изменения fixture runner повторно прошли тесты httpapi и identity.
- API-контракт: `npm run api:test` — 186 HTTP-ответов, 40 схем, 19 fixtures.
- Android: Debug и Release собраны, R8 прошёл; Lint Debug/Release без ошибок
  и предупреждений. Шесть тестов авторизации прошли. Полный JVM-набор — 83/84:
  прежний `ContractTests.allSharedFixturesDecode` ожидает 16 fixtures вместо 19.
- Android UI: `sh scripts/test-ui.sh auth` — 2/2; ошибка входа, повторная доступность
  кнопки, сохранение приглашения после пересоздания и перезапуска приложения.
- iOS: swift-format, чистая simulator-сборка и анализ; подписанная сборка для
  физического iPhone с Personal Team. Четыре теста авторизации прошли.
  Полный unit-набор — 80/81: прежний `ContractTests.allSharedFixturesDecode`
  не декодирует fixture с `starts_at: null`.
- iOS UI: `sh scripts/test-ui.sh auth` — 2/2; ошибка входа с онбординга и
  приглашения, повторная доступность кнопки и восстановление приглашения.
- OpenSpec и `npm run agent:check` проверяют структуру; реальный вход подтверждён
  отдельно пользователем, а не выведен из успешной сборки.

## Окружение и границы

Android проверялся на одном ARM64 AVD Android 36, 720×1600, 2 ГБ RAM и GPU host.
Образ Android 37 принудительно выбирал программный рендеринг; прежний Pixel 10a
сохранён выключенным. Данные нового устройства не сбрасывались.

Personal Team не поддерживает Associated Domains: для физического iPhone локальная
настройка отключает этот entitlement и включает штатный `webOnly` SDK. Сборка
с такой подписью прошла; реальный вход подтверждён на симуляторе. Установка и
вход на физическом iPhone остаются отдельной проверкой.

Реальный вход из приглашения, повторный вход после logout, восстановление уже
выданной сессии после завершения процесса и переход через установленное приложение
Яндекса ещё не проверялись вручную. Восстановление сохранённой попытки проверено
на уровне наших владельцев состояния с тестовым SDK; это не доказывает способность
самого LoginSDK продолжить OAuth после уничтожения процесса. В iOS 3.2.0 SDK хранит
`latestClientID` в памяти; холодный callback может потребовать повторного входа.
Контекст приглашения при этом сохраняется. Поэтому задачи 6.3/7.3 целиком не закрыты.
