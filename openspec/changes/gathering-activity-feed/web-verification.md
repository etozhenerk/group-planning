# Проверка первого веб-среза

20 октября 2026 года. React-клиент работает с настоящим Go API и memory.Store;
внешний OAuth-provider подменён только в тестовом процессе. Это проверка веба,
а не приёмка всего первого среза или полного MVP. Реальный Яндекс ID отложен.

## Что реализовано

- Онбординг v0.7 с примерами; будущие функции помечены «Следующий этап».
- Личный список, пустое состояние, создание с черновиком и предупреждением
  при выходе, подтверждение и передача ссылки.
- Публичное приглашение, вход без автоматического RSVP, три ответа и их смена.
- Лента и переписка после «Приду», история, периодическая догрузка,
  локальная отправка/повтор с постоянным ID, закрытие после снятия участия.
- Информация об участниках и настройка встречи организатором с ревизией.
- Отдельные состояния загрузки/ошибки/пустоты, отмена входа, отзыв сессии,
  очистка приватного кеша и защита от поздних ответов старого доступа.

Компоненты, хуки и остальные функции объявлены через `const` со стрелочной
функцией. TSX-файл содержит только импорты, один компонент и собственный Props.
ESLint проверяет скобки и пустые строки, Prettier — отступы и переносы,
PostCSS AST — разделение CSS-блоков. Go оформлен через gofumpt и wsl;
инструменты находятся в отдельном `backend/tools` без runtime-зависимостей.

## Проверки

Среда: macOS arm64, Node.js 22.22.3, Go 1.27.2, Chromium из Playwright 1.64.1.

| Проверка | Результат |
| --- | --- |
| `npm run web:check` | Типы, ESLint, CSS, FSD/AST, Prettier и 16 модульных тестов |
| `npm run web:build` | Обычная production-сборка Vite, отдельные чанки маршрутов |
| `npm run web:test:e2e` | 13 сценариев Chromium с новым Go-процессом, без БД |
| `npm run api:test` | 28 схем, 13 fixtures, 106 настоящих HTTP-ответов |
| `go test -race ./...`, `go vet ./...`, `go build ./...` | Пройдены в backend |
| `sh scripts/format.sh --check`, `gofmt -l .` | Нет замечаний оформления |
| `go run ./cmd/storage-demo` | Одна встреча, один RSVP, две записи ленты |

Чистая копия исходников без `node_modules`, `dist` и локального кеша
прошла `npm ci`, `web:check`, `web:build` и `agent:check`. Установка по lockfile
не обнаружила уязвимостей npm.

Сценарии браузера находятся в `frontend/web/tests/`:

1. Два профиля: пустой список, потеря ответа создания и безопасный повтор,
   приглашение без приватных полей, вход без RSVP, принятие и сообщения,
   «Возможно»/«Не смогу», отказ старому повтору «Приду», повторное принятие.
2. Черновик/выход/возврат, ручное копирование при отказе Clipboard,
   закрытие диалога Escape и возвращение фокуса к кнопке.
3. Потеря подтверждения сообщения и повтор с тем же ID без дубля.
4. Догрузка 58 сообщений и конфликт устаревшей формы без потери её текста.
5. Отзыв серверной сессии: приватный UI исчезает, вход возвращает к приглашению.
6. Отмена входа без изменения ответа.
7. Онбординг/лента при ширинах 320, 390, 768 и 1440 CSS px:
   отсутствие горизонтального переполнения, skip link, кнопка отправки ≥44×44,
   диалог подробностей, Escape и восстановление фокуса.
8. Отключение сети: текст остаётся в локальной отправке и уходит после повтора.
9. Запоздалое подтверждение не открывает ленту после серверного 403.
10. Изменение описания сохраняет секунды/доли секунды и выбранный момент
    в повторяющийся час при переводе часов.

Модульные тесты дополнительно проверяют null/неизвестные типы ленты,
большие sequence, слияние без дублей, поколения доступа, очистку сессии,
несуществующее/повторяющееся местное время и отрицательные примеры FSD/TSX.
HTTP-проверки отклоняют изменение настроек обычным участником;
скрытие кнопки на клиенте не является единственной защитой.

## Сопоставление с UX

Снимки текущего интерфейса — в [assets/web-v1/](assets/web-v1/).
`onboarding-*` и `meeting-*` покрывают четыре ширины; `flow-desktop.png`
и `flow-mobile.png` показывают настоящую переписку двух тестовых профилей.
На снимках раскладки виден фокус клавиатуры — он проверяется намеренно.
Сохранены графитовая основа, светлые собственные сообщения, компактные события,
адаптивные детали и отдельные формы. Новым встречам не назначается фото из макета.

Основные цветовые пары проверены расчётом относительной яркости sRGB:
основной текст/фон — 13.91:1; вторичный текст/сообщение — 6.37:1;
своё сообщение — 11.21:1; основная кнопка — 13.39:1;
текст ошибки/фон — 9.29:1; фокус/фон — 10.41:1.
Это проверка выбранных токенов, а не полный аудит доступности всех сочетаний.

Тексты проверены по `product-copy-editor`: онбординг объясняет назначение
и добавляет примеры, приглашение оставляет контекст и ответ, подтверждение
указывает следующий шаг, состояния форм называют ошибку и доступное действие.
Карта текстов: `pages/landing` — назначение/механизм; `pages/meetings` — пустота
и создание; `pages/meeting-create`/`meeting-created` — ввод/передача ссылки;
`pages/invitation` — контекст/ответ/доступ; `widgets/conversation`,
`features/send-message` — история/отправка/повтор; `features/sign-in`,
`shared/api/errors` — вход и безопасные ошибки; `features/edit-meeting` —
сохранение и конфликт. В интерфейсе нет ложного подтверждения серверной операции.

## Ограничения и следующие этапы

Демо запускается командой `npm run web:demo` на loopback TLS: профиль выбирается
у test-only provider, данные/сессии исчезают после перезапуска. Обычный сервер
не содержит dev-user/bypass; обычная сборка отвергает тестовый URL провайдера.
Реальный цикл Яндекс ID в задаче 5.3 не проверен и остаётся открытым вместе
с общей приёмкой 8.1. CI настроен на те же команды; результат удалённого запуска
проверяется отдельно после push.

iOS/Android, Safari, физические телефоны, системное Share, VoiceOver/TalkBack
и production HTTPS окружение здесь не проверены. Календарь/история,
голосования, задачи и обложки сохраняются в MVP, их реализация ещё впереди.
Постоянного хранения нет. Полный первый срез и изменение OpenSpec не завершены.
