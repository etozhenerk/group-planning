# Android: проверка ленты и настроек

21 октября 2026 года. Задача 7.6; [решение и состояния](android-feed.md).
Согласованный вид сохранён: сообщения владельца справа с аватаром,
сообщения друзей слева, системные события по центру; детали встречи только в информации.

## Среда

JDK 17, Android SDK / Build Tools 36, Kotlin и Compose из закреплённого каталога.
Использован только прежний `Pixel_XL_API_36`, `emulator-5554`, Android 16.
Новые устройства не создавались. Параллельных запусков тестов на нём не было.
Go API — отдельная HTTPS-фикстура; пользовательские web/Go процессы не перезапускались.

## Проверено

- Debug и Release, Android Lint, JVM-тесты и сборка instrumentation APK.
- 66 JVM-тестов: курсор новых записей не перескакивает после POST; дочитывание
  `has_more`, история, дедупликация, фон/возврат, backoff, поздний ответ после
  отзыва доступа, ручной повтор с прежним UUID, 403 и выход с удалением черновиков.
- Ошибка записи на диск сохраняет текст в поле и не отправляет POST. После
  восстановления хранилища отправка завершается без старого сообщения об ошибке.
- Настройки: PATCH только изменённых полей, явные null, исходный момент времени
  при правке текста, 409 без перезаписи чужих изменений, сохранение формы при
  неудачном перечитывании, 403 редактирования без закрытия чата.
- 7 device-тестов: настоящий Android Keystore, atomic write, изоляция origin,
  шифрование, восстановление черновика и UUID в новом экземпляре хранилища.

- 13 UI-сценариев прошли на одном устройстве: создание, приглашения, Share,
  ответы, история, отправка, повтор, настройки и крупный текст.
- Две отдельные instrumentation-сессии с `force-stop` между ними подтвердили
  восстановление черновика и ключа отправки после завершения процесса.
  Go-фикстура проверила два POST с одним UUID и одним ID сообщения.
- Существующие Go-проверки: `go test -race ./...`, `go vet ./...`, `go build ./...`, gofmt.

## Исправления по результатам проверки

При открытии настоящей клавиатуры Android сдвигал всё окно, хотя Compose уже
учитывал IME. Для Activity задан `adjustResize`: шапка остаётся видна, поле ввода
расположено сразу над клавиатурой. UI-тест проверяет видимость шапки и геометрию
кнопки отправки относительно IME, а не только наличие компонента в дереве.

Один промежуточный прогон был испорчен ANR `com.android.systemui`:
системное окно перехватывало Back и закрывало приложение. После перезагрузки
того же эмулятора без сброса данных все 13 сценариев и две стадии восстановления
прошли. Проверки приложения не ослаблялись.

Восстановленный отклонённый текст объединяется с новым черновиком без потери
данных. Если сумма превышает лимит, пользователь может постепенно сокращать
текст; отправка остаётся недоступна до соблюдения лимита. Это проверено JVM-тестом.

## Ограничения

Реальный OAuth и база остаются отложенными. TalkBack, физическое устройство,
другие размеры/версии Android и выпуск в магазин не проверялись. Полный аудит
доступности относится к 7.7; сценарий крупного текста его не заменяет.
Настройки переживают пересоздание Activity; после смерти процесса перечитываются
с сервера. Черновик сообщения и неподтверждённая отправка восстанавливаются с диска.
