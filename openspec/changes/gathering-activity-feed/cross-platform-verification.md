# Общая встреча: веб, iOS и Android

Проверка 21 октября 2026 года. Один процесс Go с `memory.Store`, три тестовых
профиля, одна встреча. Реальный Яндекс ID не использовался.

## Среда

- Веб: Chromium / Playwright, существующая demo-сборка, профиль Саши.
- iOS: уже открытый iPhone 17 / iOS 26.0, отдельный UI-test host, профиль Лены.
  Две стадии XCUITest выполнены последовательно на одном устройстве.
- Android: уже открытый Pixel XL API 36 / Android 16, установленный QA APK,
  профиль Миши. Действия выполнены через ADB по элементам UIAutomator;
  результаты проверены в дереве интерфейса и открытом веб-клиенте.
- API: отдельный loopback HTTPS-порт; тестовый сертификат закреплён в native
  QA-клиентах. Тестовые credentials находятся во временных файлах вне Git.

Устройства не создавались и не сбрасывались. Пользовательское демо не
перезапускалось. Production-вход, TLS и интерфейсы приложений не менялись.

## Результаты

| Действие | Наблюдение |
| --- | --- |

| Саша отправляет `Hello from web` | Сообщение видно в вебе, затем на обеих мобильных платформах |

| Миша открывает ту же ссылку на Android и отвечает «Приду» | Видны сообщения Саши и Лены; веб обновил состав до трёх участников |

Веб-сценарий прошёл за 2,9 минуты, включая ожидание мобильных действий.
Обе стадии XCUITest завершились успешно. Исправлений продуктового кода
по результатам этого прогона не потребовалось.

## Повторение

Тестовый сервер: `backend/internal/httpapi/cross_platform_fixture_test.go`.
Он пропускается обычным `go test`. Для отдельного запуска нужны
`SOMEWHERE_CROSS_FIXTURE=1`, `SOMEWHERE_CROSS_CONFIG` — путь нового приватного
JSON-файла и `SOMEWHERE_BROWSER_DIST` — абсолютный путь demo-сборки веба.
Запуск из `backend`: `go test -count=1 -timeout=0 -run '^TestCrossPlatformFixture$' -v ./internal/httpapi`.
Без `SOMEWHERE_BROWSER_ADDR` выбирается свободный loopback-порт.

Веб-координатор запускается из `frontend/web`:
`npx --no-install playwright test --config playwright.cross.config.ts`.
Нужны тот же `SOMEWHERE_CROSS_CONFIG` и `SOMEWHERE_CROSS_PROGRESS` — путь нового
приватного файла. Координатор создаёт встречу, сохраняет её ID и приглашение
в этот файл и ждёт действий мобильных клиентов. Обычный E2E-прогон этот тест
пропускает. Это совместный сценарий с управлением устройствами, а не полностью
автономная команда CI.

JSON конфигурации копируется в `tmp/ui-fixture.json` контейнера iOS UI-test host
и `no_backup/ui-fixture.json` Android QA. Android подключается через `adb reverse`
к порту fixture. Сценарий iOS `invite-rsvp` использует Лену, Android `invite-error`
использует Мишу; в этом сервере инъекции сетевых ошибок нет.

После появления приглашения выполняется
`CrossPlatformUITests/testJoinAndSend`; токен ссылки передаётся в
`EnvironmentVariables.SOMEWHERE_CROSS_TOKEN` временной копии `.xctestrun`.
Затем на Android открывается `group-planning-android-qa://i/<token>` с QA-сценарием
`invite-error`, подтверждается «Приду» и отправляется `Hello from Android`.
После появления сообщения в вебе выполняется
`CrossPlatformUITests/testReceiveAndroidAndWithdraw` на том же iOS-устройстве.
Обе стадии запускаются с `-parallel-testing-enabled NO` и явным UDID уже открытого
симулятора. Без переменной токена они пропускаются стандартным UI-прогоном.

После проверки отдельный fixture останавливается; приватные config/progress
и временная `.xctestrun` удаляются. Их нельзя прикладывать к отчёту или коммиту.

## Проверки изменений

- `npm run web:check`: типы, ESLint, FSD/AST, стили, Prettier; 34 теста пройдены.

## Границы результата

Проверены три настоящих клиента через один API с разными тестовыми профилями.
Обновления без перезагрузки проверены в открытом веб-клиенте; на iOS сообщение
Android проверено после повторного открытия, на Android ответ Лены — после
открытия информации о встрече.

Задача 8.1 остаётся открытой: реальный Яндекс ID и единый профиль после входа
на разных платформах отложены. Сценарии двух устройств одного профиля из 8.2,
сброс после перезапуска из 8.3, полная сверка MVP и аудит доступности этим
прогоном не закрываются.
