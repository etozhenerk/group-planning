# Независимые сессии одного профиля

Проверено 24 октября 2026 года для задачи 8.2.

`TestTwoSessionsShareRSVPAndCannotRestoreRevokedAccess` использует две
независимые cookie-сессии одного профиля с разными CSRF-токенами. Смена ответа
во второй сессии закрывает доступ первой. Старый повтор «Приду» возвращает
текущее `maybe`, а повтор сообщения после отзыва получает 403. У организатора
остаётся ровно одно сообщение. Управляемые часы подтверждают 401 обеих сессий
после истечения срока и отсутствие собственного ответа в публичном preview.

`19-shared-session.spec.ts` повторяет сценарий в двух независимых Chromium
контекстах. Ответ уже сохранённого сообщения задерживается до смены RSVP
в другой сессии. Он не восстанавливает текст, композер или доступ; сервер
сохраняет одну запись. Выход из одной сессии не отзывает другую.

Go race-тесты и браузерный сценарий прошли. Использован тестовый OAuth-provider;
это проверка двух независимых клиентских сессий, а не двух физических телефонов
и не повторная проверка Яндекс ID.

Отдельный `TestNewMockServerLosesMeetingsAndSessions` подтверждает сброс данных
при создании нового экземпляра memory-сервера: старая сессия даёт 401,
приглашение — 404, после нового входа список пуст. Он не перезапускает OS-процесс,
поэтому сам по себе не закрывает задачу 8.3 и не доказывает сохранность данных.
