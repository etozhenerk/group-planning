## Проверенные состояния

- Публичное приглашение открывается по нативной ссылке, показывает описание,
  дату и место. Состав и текст сообщения не раскрываются до принятия.
- Вход пока явно отложен. Закрытие его уведомления не теряет приглашение.
  Перезапуск восстанавливает ссылку. Другая ссылка в уже открытой панели
  меняет встречу; недоступная ссылка скрывает прежние данные.
- «Приду», «Возможно» и «Не смогу» имеют разные подтверждения. После принятия
  видны два участника и настоящее сообщение из Go API. После снятия участия
  состав/сообщение исчезают. Повторное принятие возвращает доступ.
- Новый вход использует другой native Bearer, выданный тем же тестовым
  OAuth-provider для прежнего профиля. Сохранённый «Не смогу» остаётся прежним;
  вход не повторяет RSVP автоматически. Это не реальный цикл Яндекс ID.
- Изменение ответа через ID встречи закрывает переписку и удаляет карточку
  из личного списка. Начальный ответ сохраняется через токен приглашения.
- Потерянный ответ после commit не выдаётся за успех. Явный повтор отправляет
  прежние тело и ключ; Go fixture подтверждает один ключ для повторных PUT.
- 409 перечитывает актуальный ответ без автоматической перезаписи. 401,
  смена профиля, поздний ответ и отзыв доступа проверены в unit-тестах.
  Кэш деталей/состава/сообщений очищается; поздний приватный запрос его не возвращает.
- Организатор открывает системную панель Share и после создания, и при
  повторном открытии встречи. Передаётся исходная HTTPS-ссылка API.
  UI-проверка открывает панель, не отправляя сообщений кому-либо.

Обработчик ссылок проверяет точный HTTPS origin, два совместимых пути и
канонический короткий/старый base64url-токен. Чужие origin, параметры,
фрагменты, URL с учётными данными и OAuth callback не становятся приглашением.
Контекст хранится отдельно от сессии в защищённом файле без резервного копирования.
Новая ссылка/закрытие имеют версию, чтобы поздняя запись не вернула старый контекст.

Тестовый app target использует собственную URL-схему и отдельный TLS transport
с проверкой hostname/сертификата fixture. Обычные URLSession/Keychain и системное
доверие не ослаблялись. Сессии и тестовый вход не включаются в пользовательскую сборку.

## Ограничения и дальнейшая работа

Реальный Яндекс ID остаётся задачей 6.3 на конец разработки. Без настроенного
HTTPS API обычная сборка не получает данные встреч или тестовый профиль.
Автоматическое открытие публичной HTTPS-ссылки в приложении потребует домена,
AASA и entitlement Universal Links. Сейчас проверен нативный маршрут
`group-planning-ios://i/{token}`; обработчик HTTPS сам по себе не регистрирует домен.

Чтение последних сообщений добавлено для проверки доступа. Полная хронология,
отправка, история и настройки организатора — задача 6.6. Поддержка мобильных
голосований, задач и календарного вида не заявляется. Отдельный запуск на iOS 17,
реальном устройстве, полный VoiceOver/Dynamic Type аудит остаются в 6.7.
