# Проверка опросов даты в web · 23.10.2026

## Реализация

Web поддерживает обязательный день с необязательным временем, создание опроса
из чата, настройки, голосование и смену голоса, добавление даты, скрытые результаты,
выбор организатора при ничьей и отображение итогов. Сервер предоставляет операции
по контракту этапа 10.2.

## Исправления после проверки пользователем

- Собственные сообщения и опросы располагаются справа и используют светлый фон;
  карточка опроса имеет малый угол справа сверху. Чужие карточки остаются тёмными.
- Все уведомления опроса отображаются системными строками по центру, без имени
  и аватара бота, как и остальные события встречи. Старое поле отправителя
  в API не определяет оформление события.
- Дата и время расположены над системным сообщением: «Сегодня · 01:35»,
  «Вчера · 19:20» или «21 октября · 19:20» по локальному времени браузера.
  У обычных сообщений имя и время выровнены по центру строки.
- Форма «Когда встречаемся?» стала компактнее: убраны повторяющиеся подписи
  вариантов и вводный абзац. Все пять настроек видны сразу, без раскрывающегося блока.
- В вариантах даты нет второго крестика. Корзина появляется только при наличии
  более двух вариантов; у двух обязательных полей её нет.
- Пустые и повторяющиеся даты подсвечиваются рядом с полем; при отправке форма
  прокручивается к первой ошибке и фокусирует её. Общие ошибки видны над кнопкой.
- При открытии диалога прокрутка страницы и ленты заблокирована. Внутри формы
  прокручивается только тело, кнопка остаётся в отдельном нижнем блоке;
  при наличии содержимого ниже появляется тень.
- Диалог закрывается по фону и Escape, сохраняет черновик и возвращает фокус
  на кнопку открытия. Первый Escape при открытом календаре закрывает календарь.
- Поля срока имеют короткие подписи «Дата» и «Время», выровнены в строку;
  на 320 px располагаются друг под другом. Календарь не обрезается прокручиваемой
  областью формы и целиком помещается на узком экране.

## Выполненные проверки

- `npm run web:check`: типы, ESLint, оформление CSS/Prettier, FSD и состав
  компонентов; 17 файлов, 54 модульных теста.
- Сборка demo выполнена перед браузерными прогонами. Статические файлы локального
  стенда обновлены без перезапуска хранилища в памяти.
- `01-flow`, `03-layout`, `05-date-time`, `14-date-poll`: 14 целевых сценариев
  прошли на промежуточной версии правок, включая основной путь встречи,
  адаптивную раскладку, календарь, день без часа и голосования.
- После финальных правок карточки и системных строк отдельно прошли три сценария
  `14-date-poll`: создание и голосование двух участников с автоматическим переносом,
  скрытая анонимная ничья с выбором организатора и день без обязательного времени.
- После изменения позиционирования календаря прошли 8 сценариев `05-date-time`
  и `15-poll-modal`: 320/390/1440 px, локальное время и неоднозначный час при DST,
  прокрутка формы при высоте 600 px, тень нижнего блока, ошибки пустой/повторной
  даты, закрытие по фону/Escape и сохранение черновика.
- С новым заголовком повторно прошли все три сценария `15-poll-modal`.
  Снимки формы, ошибок и календаря просмотрены визуально.

## Границы проверки

Проверки выполнены в Chromium с тестовым OAuth-provider и хранилищем в памяти.
Реальная авторизация и постоянное хранилище остаются отложенными.
Safari, реальные телефоны и нативные клиенты этим отчётом не подтверждаются.
Для закрытия всей задачи 10.3 нужен оставшийся проход ошибок, потери доступа
и переходов времени в UI; серверные проверки этих правил не заменяют браузерную приёмку.
