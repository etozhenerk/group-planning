# Somewhere · UX/UI v0.7

Статус на 19 октября 2026 года: пользователь одобрил макеты и тексты v0.7,
включая наглядный онбординг. Применён проектный навык редактора ко всему пакету:
сокращены повторяющиеся блоки онбординга и уточнены тексты состояний.
По запросу пользователя добавлены изображения интерфейса с вариантами
голосования и задачи. Новый знак остаётся предложенным вариантом.
Это HTML/CSS-макеты; пользовательские функции ещё не реализованы.

## Знакомство и личные встречи

Общий вход начинается с [онбординга](assets/entry-landing.html): возможности
сервиса и «Попробовать», затем Яндекс ID и личные встречи. Встречи доступны
[списком](assets/hub-list.html) и [календарём](assets/hub-calendar.html),
с переключением между предстоящими и прошедшими. Все встречи выбранного дня
видны рядом с календарём; события без итоговой даты вынесены отдельно.
Состояния, ограничения макета и отличия платформ — в [entry-home.md](entry-home.md).
Уточнение от 21.10.2026: встреча становится прошедшей со следующего дня
по её часовому поясу; текущие действия и права сохраняются. В entry-home.md
дополнены переходы календаря, состояния и правило одной кнопки создания.

Прямое приглашение открывает свою встречу, без обязательного просмотра
онбординга. Правила доступа к переписке сохраняются.

## Полный путь до ленты

Создание, приглашение и ответы друга описаны в [journey.md](journey.md),
с матрицей покрытия и связанными экранами. Основной путь с назначенным временем
покрыт от первого входа до «Приду» или «Не смогу». Прежний эскиз создания
без даты заменён правилами 22.10.2026 ниже; новые макеты переноса даты
и все граничные состояния ещё предстоит подготовить.

## Состояния веб-входа · 24 октября 2026

Уточнение существующих кнопок входа и страницы возврата по запросу пользователя.
Затронут web; API и нативные экраны iOS/Android не меняются. Их системные
окна входа остаются в задачах 6.3 и 7.3. Основа — существующие `SignInButton`
и горизонтальная подпись `Brand`, графитовый фон и текущие токены.

```text
До нажатия                 Запрос и переход в Яндекс
[ Войти через Яндекс ID → ] [           ◌            ]
                           та же ширина, повтор заблокирован

Возврат из Яндекса          Ошибка загрузки профиля
┌──────────────────────┐   ┌──────────────────────────┐
│                      │   │      знак somewhere      │
│    знак somewhere    │   │    Не удалось войти      │
│        ━━━           │   │  [ Попробовать снова ]   │
│                      │   │      На главную          │
└──────────────────────┘   └──────────────────────────┘
```

- Подпись и стрелка визуально скрыты; один индикатор находится по центру кнопки.
  Загрузка непрерывна от нажатия до ухода со страницы, а не только до ответа API.
  При ошибке начала входа кнопка снова доступна, рядом одно сообщение об ошибке.
  Возврат браузером назад, включая восстановление из bfcache, снимает блокировку.
- Между возвратом и открытием личных встреч/приглашения — один нейтральный
  полноэкранный индикатор: знак и название, тонкая движущаяся линия. Нет заголовков
  про авторизацию и дублирующих сообщений. При загрузке данных приватной страницы используются её скелетоны
  из уточнения ниже.
  Появление мягкое с задержкой 120 мс, но успешный переход не задерживается.
- Для screen reader остаются «Загрузка», `aria-busy` и состояние кнопки.
  При `prefers-reduced-motion` движение отключено; состояние различимо статически.
  Компоновка центрирована на 320/390/768/1440 px и не меняет размер кнопки.
- Сетевой сбой проверки профиля: «Не удалось войти» и «Попробовать снова»;
  повтор проверяет уже полученную сессию. 401: «Войдите ещё раз» и кнопка
  Яндекс ID, сохраняющая исходное приглашение. Вторичная ссылка ведёт к
  приглашению или на главную. Отмена у Яндекса возвращает к исходной точке
  с существующим сообщением об отмене. Вход сам по себе не записывает RSVP.
- Карта текстов: подпись кнопки называет действие; сообщение ошибки помогает
  повторить; технические заголовки ожидания удалены, а не перефразированы.
  У пустого промежуточного состояния нет отдельного пользовательского смысла.

## Направление

Основной экран — разговор друзей с действиями внутри него. Ориентиры,
названные пользователем: Telegram, Instagram и Discord. Используются читаемые
сообщения, аватары участников, мягкие формы и общая хронология. Графитовая основа
сохраняется; рамки, технические подписи и отдельные панели статусов сокращены.

Общие значения и компоненты — в [основе дизайна](../../../docs/design/foundations.md).
Правила текстов — в [редакционных принципах](../../../docs/design/content.md),
процесс — в [навыке редактора](../../../.agents/skills/product-copy-editor/SKILL.md).
[Отчёт по редактуре](copy-review.md) перечисляет решения и охват экранов.
Новый знак и исходный промпт — в [описании варианта](assets/logo-prompt.md).
Фото с друзьями и пиццей — обложка конкретной встречи «Суббота без спешки»,
а не общий декор сервиса. Оно показывается в контексте её карточки, приглашения,
ленты и кратких деталей. На первом входе и в пустом списке этой фотографии нет.
Обложка необязательна; в форме показано отдельное поле и выбранный пример.
Без обложки приглашение сохраняет текстовые детали. Автоматически это фото
новым встречам не назначается.

Аватары относятся к профилям и не вырезаются из обложки. В прототипе используются
инициалы как вариант без фотографии профиля. Вымышленная обложка создана через
imagegen; [источник и промпт](assets/image-prompt.md). Настоящая загрузка и хранение
изображений здесь не реализованы.

## Уточнение формы даты и времени · 20 октября 2026

Пользователь уточнил календарь именно внутри формы создания/редактирования.
На вебе дата выбирается в календаре Gravity UI, отдельное соседнее поле — время.
Поле выбора часового пояса убрано. Эскиз уточняет существующую форму v0.7:

```text
Дата                         Время
[ ▦  24.10.2026        × ]    [ ◷  19:00              ]
Время встречи · Москва
```

Календарь открывается кликом на любую часть поля даты (включая текст и иконку)
или Alt+↓, позволяет менять месяц и выбирать
день, закрывается Escape с возвратом фокуса. Он сохраняет графитовую палитру
и используется также в мобильном браузере. На узком экране поля идут одно
под другим; всплывающий календарь помещается в ширину viewport.
Иконки даты и времени стоят слева в одинаковой области шириной 44 px;
текст полей начинается с одной линии. Очистка даты остаётся справа.
В первом срезе дата и время обязательны. Для этапа 10 по решению 22.10.2026
дата остаётся обязательной, а время можно не заполнять; см. уточнение ниже.
Ошибка не стирает поля. Неоднозначный час при переводе часов требует отдельного
выбора раннего/позднего варианта; несуществующее время даёт ошибку.

При создании используется IANA-пояс браузера; сохранённый черновик сохраняет
свой пояс. При редактировании используется пояс встречи, даже если браузер
находится в другом поясе. Небольшая подпись поясняет, к какому поясу относится
время. API по-прежнему получает UTC-согласованный instant и IANA timezone.

Текущая правка реализуется в web. API не меняется. Для будущих iOS/Android
сохраняются раздельные дата/время и автоматический пояс с контекстом встречи;
конкретные нативные элементы проверяются при реализации этих клиентов.
Календарь личного списка и загрузка обложки не входят в эту правку.

Реализация формы, проверки и снимки — в [отчёте](date-time-verification.md).

## Шапка встречи и появление панелей · 20 октября 2026

Название встречи и кнопки шапки выравниваются по общей
горизонтальной оси. Иконки действий имеют размер 20 px, области нажатия —
не меньше 44×44 px. Для приглашения используется знакомая стрелка вверх
из открытого лотка; подпись «Пригласить друзей» сохраняется на широком экране
и остаётся доступным именем кнопки на телефоне.

Одна панель содержит одно действие/набор деталей:

```text
Широкий экран                     Телефон
[фон мягко затемняется]            [фон мягко затемняется]
     ┌─────────────────┐          ┌─────────────────────┐
     │ заголовок     × │          │          ─          │
     │ содержимое      │          │ заголовок           │
     └─────────────────┘          │ содержимое          │
                                  └─────────────────────┘
                                  нижний край экрана
```

Уточнено 23.10.2026: на широком экране окно появляется за 280 мс с небольшим
подъёмом и проявлением; на телефоне шторка поднимается от нижнего края без
масштабирования. Закрытие занимает 220 мс, фон гаснет вместе с панелью.
До окончания выхода содержимое остаётся на месте, а фон не прокручивается.
После закрытия фокус возвращается на кнопку открытия. `prefers-reduced-motion`
отключает анимации.

Мобильную шторку можно потянуть вниз за всю верхнюю область с ручкой и заголовком,
включая отступ над ручкой и боковые поля:
панель следует за пальцем, короткий жест возвращает её на место, достаточное
смещение или быстрый свайп закрывает. Поля и область прокрутки сохраняют свои
жесты. В мобильной шторке крестика нет; закрытие доступно жестом, по фону
и через Escape. На десктопе сохраняется кнопка закрытия. Все способы
используют тот же анимированный выход.
Редактирование, приглашение, детали и опрос используют общий компонент.
Содержимое прокручивается, если не помещается по высоте; учитывается нижняя
безопасная область телефона.

## Один источник деталей и одно действие создания · 20 октября 2026

Шапка встречи содержит единственный заголовок с названием и действия.
Дата, место, описание и компания находятся в одном блоке деталей:
на экране от 1170 px — в правой панели, без кнопки `i`; ниже 1170 px —
по кнопке `i`, без правой панели. На телефоне этот блок открывается снизу.
При смене ширины используется соответствующий вариант; данные не выводятся
дополнительно в начале ленты. Лента содержит сообщения и события встречи.

На личной странице всегда одна точка создания:

| Состояние | Где действие «Создать встречу» |
| --- | --- |
| Успешно загруженный пустой список | В пустом состоянии, без действия в шапке |
| Есть встречи | В шапке списка |
| Загрузка или ошибка | В шапке; ошибка сохраняет отдельный повтор загрузки |

Боковая навигация ведёт к списку встреч и профилю, без второй кнопки создания.

Этот экран проверяет сборку; пользовательский путь онбординга, приглашения

## Запуск и выравнивание подписи · 21 октября 2026

По уточнению пользователя знак слева выравнивается по строчным буквам названия.
При холодном запуске показывается фирменный экран с движением знака минимум
1,2 с; если загрузка занимает больше времени, он остаётся до её окончания;
системный LaunchScreen остаётся статичным. Состав, движение и ограничения
зафиксированы в [брендинге](../../../docs/design/branding.md). Реализация — iOS,
общие правила сохранены для Android. API и основной вид экранов не меняются.

## Стороны сообщений · 20 октября 2026

В существующем `FeedRecord` свои сообщения и аватар находятся справа,
сообщения остальных и их аватары — слева. Подпись автора и время сохраняются;
у своего пузыря малое скругление находится у правого верхнего угла.
Обычные системные события остаются по центру без аватара и подписи.
Уведомления о голосовании также показываются системными строками по центру (23.10.2026).

Сообщение до подтверждения и при ошибке отправки также остаётся справа;
статус и повтор доступны рядом с текстом. Длинные строки переносятся внутри
пузыря и не расширяют страницу. Правило одинаково для широкого браузера
и телефона; порядок записей и позиция чтения сохраняются.

Это общее правило UX для web/iOS/Android. В этой правке реализуется только web,
нативные клиенты ещё не инициализированы; API и сервер не меняются.

Проверка web: два профиля на 320/390/1440 px, перенос текста и повтор после
потери ответа. Свой аватар находится у правого края ленты, чужой — у левого;
на телефоне нет горизонтальной прокрутки. 20 модульных и 23 браузерных сценария,
production-сборка, типы, линтинг, FSD и форматирование прошли.
Демо получило новый bundle без перезапуска Go и сброса встреч.

- [Телефон, профиль Лены](assets/chat-alignment/mobile.png).

Скриншоты из изолированного browser-теста: строка `<img ...>` — намеренная
проверка показа пользовательского HTML обычным текстом.

## Короткое приглашение и превью · 20 октября 2026

Организатор копирует адрес вида `/i/` + 22 случайных символа. Ссылки прежнего
формата продолжают открывать встречу. Приглашение до входа показывает также
полное описание: пользователь отдельно подтвердил его публичность по ссылке.
В форме возле описания указана эта видимость; переписка и ответы не раскрываются.

В превью мессенджера — название, описание встречи (при отсутствии — дата/место)
и фирменная картинка Somewhere. Загрузка обложек остаётся отдельным этапом.
Сервер отдаёт эти метаданные в исходном HTML, затем открывается обычное
React-приложение. На localhost внешний мессенджер проверить нельзя: проверяются
HTTP/HTML/PNG и работа без JavaScript; реальный показ — после публичного HTTPS.

## Путь участника

1. Инициатор создаёт встречу с деталями и делится ссылкой.
2. Друг открывает публичное приглашение с названием, датой и местом. Для ответа
   входит через Яндекс ID и возвращается к той же встрече. Экран выбора ответа
   ещё не открывает чат; переписка становится доступна после «Приду».
3. В ленте видны создание и настройки, принятие приглашений и сообщения.
   Текущие дата, место и состав компании доступны рядом с разговором.
4. Участник пишет сообщение либо открывает «+» и предлагает место или задачу.
5. Голосование показывает предложение. До закрытия опроса текущее место
   не меняется. После закрытия большинство проголосовавших определяет результат;
   при принятии новое место применяется автоматически и отражается в ленте.
6. Задача предлагается конкретному человеку. Он нажимает «Принять задачу»;
   карточка и хронология показывают принятие. Это не отметка о выполнении.

На телефоне кнопка деталей открывает краткую информацию и участников. Кнопка
назад в демонстрации возвращает к обзору макетов; в приложении возврат зависит
от точки входа — приглашение, список встреч или системная ссылка.

## Состав экрана и действия

| Блок | Данные | Действие и результат |
| --- | --- | --- |
| Краткие детали | Название, дата, место, участники | Открыть информацию о встрече |
| Системное уведомление | Время, изменение и автор исходного действия | Прочитать результат; подтверждение автопереноса не требуется |
| Сообщение | Автор, время, текст, состояние отправки | Повторить неудачную отправку |
| Опрос о месте | Предложение, автор, варианты, голоса, состояние | Проголосовать; после закрытия увидеть итог |
| Задача | Название, автор, адресат, принятие | Адресат принимает ответственность |
| Поле сообщения | Черновик, доступность отправки | Отправить текст или добавить действие |

Это смысловые блоки интерфейса; каждый клиент реализует их в своём коде.
Модели API и конкретные компоненты определяются в техническом решении.
Права и бизнес-решения проверяет сервер. При недоступном действии продуктовый
интерфейс должен объяснять причину; конкретные правила доступа и состояния
ошибок операций ещё требуют проработки.

## Три платформы

Общими остаются хронология, смысл действий и актуальные детали. Макеты задают
направление для web, iOS и Android; клиентские приложения здесь не реализованы.

- **Телефон:** одна колонка; верхняя панель и ввод отделены от прокручиваемой
  ленты. Обложка и описание уходят при прокрутке. Дополнительные действия
  открываются снизу; дата, место и компания доступны в информации о встрече.
- **Широкий браузер:** список встреч слева, разговор по центру, детали справа.
  Ниже 1170 px правая колонка скрывается, ниже 740 px остаётся одна колонка.
- **iOS:** будущее приложение должно учитывать safe area, системную клавиатуру,
  Dynamic Type, возврат из Яндекс ID и системную навигацию.
- **Android:** будущее приложение должно учитывать системные отступы, IME,
  масштаб шрифта, системный Back, возврат из авторизации и прямые ссылки.
- **Доступность:** имена и состояния не передаются только цветом; действия
  имеют текст/подпись, у иконок скрыт декоративный SVG. Для приложения нужны
  корректный фокус диалога, клавиатурное закрытие и возврат фокуса, доступные
  объявления отправки и результатов, проверка экранными дикторами.

Макеты проверялись в Chromium при ширинах 320–1440 px. Работа клавиатуры
на реальных устройствах, VoiceOver, TalkBack и нативный размер текста
пока не проверены. HTML-диалоги показывают внешний вид; полный цикл управления
фокусом здесь не реализован.

## Дата, время и опрос переноса · 22 октября 2026

Согласованные правила находятся в [MVP](../../../docs/product/mvp-gathering.md).
В форме создания дата обязательна, время необязательно. Опрос открывается
из чата любым пользователем с доступом к нему; форма содержит варианты дат,
настройки и срок окончания. Большинство от текущего состава с доступом к чату
сразу автоматически переносит дату. Двухчасовое ожидание и подтверждение
организатора отменены. Скрытые результаты и перенос ждут закрытия опроса.

Уведомления о голосовании — системные строки по центру без имени и аватара.
Они бесплатны и не требуют AI. Автор исходного действия остаётся в тексте;
автоперенос не приписывается человеку. Собственные сообщения и опросы — справа,
со светлым фоном и верхним правым углом 6 px, как у своих текстовых сообщений.

У вариантов показываем «1 голос», «3 голоса», «6 голосов», без повторения «из 6».
Это только способ отображения: большинство по-прежнему считается от текущего
состава с доступом к чату. Общий счётчик проголосовавших не добавлен.
Скрытый опрос не раскрывает числа до закрытия, анонимность сохраняется после него.

### Тексты уведомлений

| Ситуация | Системное сообщение |
| --- | --- |
| Большинство применено | «Встреча перенесена на 25 октября — эту дату выбрало большинство.» |
| Единогласный вариант применён | «25 октября подходит всем. Встреча перенесена на эту дату.» |
| Несколько единогласных вариантов | «Всем подходят 25 и 26 октября. Саша, какую дату выбираем?» |
| Опрос закрыт без большинства | «Ни один вариант не набрал большинства. Пока встречаемся 24 октября.» |

Дата и автор действия берутся из события, сообщение о переносе появляется
после его успешного применения. При равенстве лидеров с большинством выбирает организатор; без равенства
применяется максимум. Опрос после применения закрыт, новый перенос требует
нового опроса. Пуши остаются отдельным вопросом.

### Черновые макеты опроса даты · v1

[Каталог](assets/date-poll-v1/index.html) и
[мобильный предпросмотр](assets/date-poll-v1/preview-mobile.html) используют
согласованную графитовую палитру. На широком экране форма открывается по центру;
на телефоне — снизу с прокруткой полей и закреплённым действием.

[Автоперенос](assets/date-poll-v1/decision.html) заменил карточку подтверждения
организатором. Вариант с четырьмя голосами выделен, детали показывают 25 октября,
системное сообщение сообщает об изменении. Кнопок «Перенести»/«Оставить» нет. Старые адреса
applied.html и kept.html сохранены как копии актуальных состояний для ссылок;
они больше не описывают ручной выбор организатора.

Есть создание, открытый опрос без большинства, учтённый голос, скрытые итоги
до/после ответа, ошибка отправки, автоперенос, единогласный итог скрытого опроса
и завершение без большинства. Настройки переключаются, данные между страницами
не сохраняются. Голосование, таймер закрытия и сервер здесь не реализованы.

Показанные макеты одобрены пользователем. Жизненный цикл и границы результата
подтверждены отдельно: один активный опрос, закрытие после применения,
сохранение часа и RSVP, восстановление голоса при возврате, отмена при ручной
смене дня. До интерфейсной реализации нужно дополнить этот же дизайн состояниями
ничьей, отмены, конфликта и неоднозначного местного времени; они не считаются
проверенными по существующим статическим страницам. Полные нативные проверки
входят в 10.4–10.5.

### Приглашения с ответом «Возможно»

закрыты. «Приду» переводит встречу в личные, «Не смогу» убирает из вкладки.

### Проверка макетов · 22.10.2026

В первой проверке просмотрены форма, скрытый опрос и кадры 390 × 844/320 × 760,
переключение настроек и переход скрытого опроса после отправки. Итоги оставались

### Дополнение контракта для интерфейсов · 23.10.2026

- В закрытой карточке нельзя менять голоса или добавлять варианты. У неё
  сохраняются итоговые цифры, даже если кто-то позже покинет чат.
- При ничьей с большинством организатору доступны только лидирующие даты.
  Остальные участники видят «Выбор за организатором». Успешное применение
  обновляет карточку, детали встречи и календарь; ошибка сохраняет выбор.
- Ручная смена дня закрывает карточку с подписью «Опрос завершён»; системное сообщение
  объясняет причину. При отмене скрытого опроса цифры не раскрываются.
- Смена UTC-смещения может сделать прежний час отсутствующим или двусмысленным.
  В этом случае сообщение: «Дату выбрали. Из-за перевода часов нужно уточнить
  время встречи». Организатор явно выбирает допустимое время или оставляет
  его неуточнённым; до успешного сохранения прежняя дата не заменяется.
- `409` требует обновить снимок карточки; черновик выбора сохраняется, но
  закрытый опрос не предлагает повторную отправку голоса. Потеря доступа
  очищает приватную карточку и ведёт к собственному ответу на приглашение.
- У даты без часа подпись «Время пока не выбрано»; поля формы не подставляют
  00:00. Системное напоминание отдельно от события создания: «Осталось договориться,
  во сколько встречаемся». Если большинство выбрало прежний день, сообщение
  «Дату подтвердили: встречаемся 24 октября» заменяет сообщение о переносе.

Это перечень состояний для дополнения макетов, не отчёт о проверке интерфейсов.


### Дополнение опроса даты: границы результата

Макеты `date-poll-v1/tie.html`, `time.html`, `cancelled.html`, `conflict.html`
используют ту же карточку и системные сообщения. Ничья даёт организатору кнопки
дат-лидеров; остальные видят ожидание. При неоднозначном времени организатор
выбирает час и сторону перевода часов либо явно оставляет время неуточнённым.
Отмена оставляет карточку без действий; скрытые голоса при отмене не раскрываются.
Конфликт обновляет данные, сохраняя локальный ввод; завершённый опрос блокирует
действия. Ошибка сети оставляет кнопку повтора.

На web карточка встроена в ленту; создание открывается в существующем Dialog
(центр на широком экране, шторка на узком). iOS и Android используют те же
порядок полей, тексты и состояния в нативной шторке. Карточка не занимает больше
ширины сообщения, длинные даты и подписи переносятся. Контролы имеют доступные
подписи; скрытые результаты отсутствуют и в accessibility tree. Собственные
сообщения остаются справа, системные уведомления — по центру. Шторки следуют существующим
анимациям платформы и настройке уменьшения движения.

## Уточнение web-формы опроса · 23.10.2026

Заголовок — «Новая дата встречи». Варианты идут компактными полями без повторяющихся
подписей «Вариант N»; доступные имена сохраняются для скринридера. При двух датах
кнопок удаления нет; после добавления третьей у вариантов появляются кнопки
с корзиной. Очистки внутри этих полей нет. Все пять настроек видны сразу,
без раскрывающихся блоков и повторных пояснений. Под «Окончание опроса» —
«Дата» и «Время» на одной линии; на 320 px они идут друг под другом.

Прокручиваются только поля. Кнопка создания вынесена в отдельный нижний блок;
тень над ним видна, пока ниже есть содержимое. Фон заблокирован от прокрутки.
Клик по фону и Escape закрывают форму, сохраняя черновик. Открытый календарь
сначала закрывается по Escape; он не обрезается прокручиваемой областью.
Ошибки дат показываются у полей, фокус переводится к первой ошибке.
Ошибки отправки находятся над кнопкой. Уведомления об итогах теперь системные;
старые статические макеты с аватаром бота не описывают актуальный вид уведомлений.

Дата и время системного события стоят над текстом по центру. Для текущего дня
используется «Сегодня · 01:35», для предыдущего — «Вчера · 19:20»; для более
ранних событий — «21 октября · 19:20». День и время определяются по часовому
поясу устройства. В строке автора обычного сообщения имя и время выровнены
по центру общей строки.


## Скелетоны и выход · уточнение 24 октября 2026

Только web. На кнопке входа при загрузке скрыты текст и стрелка, один спиннер
располагается по центру всей кнопки. Скрытая подпись сохраняет геометрию;
доступное имя остаётся прежним. После ошибки или Back кнопка восстанавливается.

Начальные загрузки данных повторяют уже реализованную композицию:

- Список: строки с обложкой, названием и двумя строками метаданных; в календаре
  сохраняется сетка календаря и скелетоны только в загружаемой повестке.
- Встреча: навигация, заголовок, сообщения разной длины, поле ввода и правая
  панель на широком экране. На узком экране боковые панели скрываются как в UI.
- Приглашение/созданная встреча: заголовок, дата/место, описание и место действия.
- Участники: аватар и две строки; опрос: варианты; ссылка: поле и действие.
- Пока проверяется сессия на приватной странице, показана соответствующая
  оболочка со скелетонами без персональных данных. OAuth-return сохраняет
  согласованный фирменный экран: его конечная страница ещё определяется.

Скелетоны используют цвета поверхностей и радиусы текущего UI, мягкую пульсацию
без бегущих бликов. Они не фокусируются, скрыты от screen reader; контейнер
имеет одно доступное имя загрузки и aria-busy. Reduced motion отключает пульсацию.
При фоновом обновлении показанные данные сохраняются. Ошибки заменяют скелетоны
соответствующим состоянием повтора. Загрузки после действий не скрывают форму.

При выходе кнопка блокируется до завершения перехода. После подтверждения API
сессия и приватный кеш очищаются сразу; до завершения перехода на главную
SessionGate показывает загрузку страницы, а не предложение войти. При сетевой ошибке
пользователь остаётся на странице и может повторить выход.


## Мобильный Яндекс ID · 24 октября 2026

Пользователь запросил реальные локальные сборки iOS/Android. Используется
текущий HTTPS-origin ngrok и существующие onboarding/приглашение.

```text
Последний слайд / приглашение → [          ◌          ]
  → системное окно Яндекса → возврат → личные встречи / то же приглашение
  ← отмена: исходный экран, активная кнопка
  ← ошибка: краткое сообщение и возможность повторить вход
```

На iOS и Android используется официальный Yandex LoginSDK: сначала приложение
Яндекса с доступным аккаунтом, при его отсутствии — штатное окно веб-входа SDK.
Для локального физического iPhone с Personal Team используется режим SDK `webOnly`:
эта команда Apple не поддерживает Associated Domains. В симуляторе и сборках
с подходящим профилем остаётся стандартный выбор SDK.
Пароль вводится только в браузере Яндекса. Подпись кнопки скрывается на время
запроса/обмена, размер сохраняется; screen reader получает имя действия.
После отмены нет отдельного экрана ошибки. Ошибка показывает заголовок «Не удалось
войти» и предлагает повторить попытку; неверный/истёкший возврат также возвращает
к активной кнопке входа.
Технические state, code и verifier в интерфейсе не показываются.

Вход из приглашения сохраняет token, возвращает актуальную карточку и никогда
не выбирает RSVP за пользователя. При сворачивании сохраняется защищённая
попытка. Callback после пересоздания приложения проверяет сохранённую попытку;
если SDK не может продолжить вход после завершения процесса, приглашение остаётся
доступным для новой попытки. Истёкшая или уже использованная попытка не восстанавливает сессию. Закрытие
Custom Tab снимает ожидание; новый вход заменяет предыдущую попытку.

Полученная сессия сохраняется в Keychain / зашифрованном Keystore-хранилище
до запроса профиля, чтобы сетевой сбой проверки профиля не терял выданную сессию.
Доступ к приватным экранам появляется только после успешного /me. При 401
сессия очищается, приглашение остаётся доступным для нового входа.
