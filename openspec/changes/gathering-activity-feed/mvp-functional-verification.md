# Функциональная проверка MVP на временном хранилище

25 октября 2026 года. Проверка группы 13 и первого среза 8.3–8.4.
Применяется к Go API с memory.Store и моками очереди, web, iOS и Android.
Группа 13.6 и пункт 8.4 выполнены: полный повторный набор iOS и общий
межплатформенный прогон завершены без ошибок. Это функциональная проверка
текущих клиентов, а не окончательная приёмка всего MVP. Production уже использует PostgreSQL;
изолированные UI-стенды этого отчёта продолжают использовать memory.Store.

## Сброс после перезапуска

Команда из корня с Go 1.27.2 в PATH:

```sh
python3 scripts/test-mock-restart.py
```

Она собирает тестовый HTTP binary и последовательно запускает два отдельных
процесса с собственными memory.Store и тестовым OAuth-provider. В первом через
API создаётся встреча. После его остановки второй процесс возвращает 401
для старой Bearer-сессии, 404 для прежнего приглашения и встречи; новая сессия
имеет пустой личный список. Проверка прошла. Пользовательский API и его данные
не перезапускались. Конфигурация, credentials и временный бинарник удаляются
после проверки. PostgreSQL/Docker, хостинг и реальные OAuth-секреты не нужны.

| Клиент | Проверенная сборка и среда | Граница проверки |

| iOS | Те же UI-исходники в SomewhereUI, версия 0.1.0 (1); iPhone 18 Pro, iOS 27.0, Xcode/SDK 27.1 | Deployment target 17.0; отдельного запуска на iOS 17 и store-бинарников не было |
| Android | Те же UI-исходники в QA, Debug/Release APK; Somewhere_API_36, Android 16 / API 36 | minSdk 26; fallback обработки фото проверен отдельным вызовом, отдельного запуска Android 8 не было |

Между `90799e6` и началом повторного прогона на `ad61010` исходники клиентов
не менялись. Серверные изменения PostgreSQL сохраняют тот же HTTP-контракт.

Проверены текущие исходники всех трёх клиентов с одним OpenAPI. Существующие
поля не удалены и не переименованы. Новые DTO/события читаются с допуском
неизвестных полей, старый PATCH без `cover` сохраняет обложку, старый клиент
может продолжать создание без фотографии. `cover_url` остаётся nullable-строкой.
Новый клиент отличает отсутствие поля PATCH, удаление `null` и новое фото.
Хеш идемпотентности старых запросов без обложки сохранён через `omitempty`.

Android декодирует дату без обязательного `starts_at`; общий fixture с фото
обнаружил и закрепил этот случай. Нативные клиенты сохраняют готовые JPEG-данные
в черновике, а не временный URI библиотеки. API проверяет bytes/MIME/пиксели и
не скачивает внешние URL. Проверки сборок не заменяют проверку старых опубликованных
бинарников: их матрица и реальные store-релизы относятся к заключительной приёмке.

## Общий межплатформенный сценарий

25.10.2026, 12:32–12:34 МСК: `python3 scripts/test-cross-platform.py`
завершился успешно. Web — один Playwright-тест, 50,6 секунды; iOS —
два XCUITest без ошибок; Android — один instrumentation-тест без ошибок.

1. Организатор в web создал встречу с обложкой и отправил сообщение.
2. iOS открыл эту же ссылку, показал фото, вступил и отправил своё сообщение.
3. Android прочитал ту же обложку и оба сообщения, вступил и ответил.
4. Web без reload показал три сообщения и состав из трёх человек.
5. iOS прочитал сообщение Android и приватную обложку, изменил RSVP на
   «Не смогу». Переписка и отправка закрылись; прежняя сессия получила 403
   при запросе ленты. Web без reload показал новый ответ, сохранив историю.

Снимки Android: [общая обложка](assets/covers-verification/cross-android-cover.png),
[сообщения трёх платформ](assets/covers-verification/cross-android-messages.png).
Тест использует независимые тестовые профили и обычный HTTP-контракт;
production, реальные OAuth-реквизиты и пользовательские данные не затрагиваются.

Для повторения нужны Go/Node в PATH, `ANDROID_HOME`, `SOMEWHERE_SIMULATOR_ID`,
demo-сборка web, SomewhereUI build-for-testing, установленные Android QA/instrumentation APK
и один работающий эмулятор. Сначала завершить любые другие тесты на этих
устройствах. Диагностика runner сохраняется в `.cache/cross-platform-results/`.

## Границы результата

Реальный вход пользователь подтвердил для локальных трёх клиентов ранее.
В этом прогоне используются тестовые профили. Полный реальный OAuth-путь из
приглашения, повтор после уничтожения процесса, единая идентичность на платформах
и ручные VoiceOver/TalkBack остаются отдельно отмеченными незавершёнными проверками.

В изолированных стендах этого отчёта встречи, сессии, изображения, receipts
и очередь хранятся в памяти и теряются при перезапуске тестового API.
Это ограничение стенда, а не текущего production-хранилища.

PostgreSQL 16 и постоянные адаптеры подключены отдельным изменением.
[Отчёт PostgreSQL](../deployment-and-store-release/postgres-verification.md)
подтверждает миграции, транзакции/конкуренцию, сохранность после restart
API/БД и pg_dump/pg_restore на тестовой базе. Там же зафиксированы production
релизы backend/web RC.2, реальный Яндекс OAuth, создание встречи и сохранение
сессии/сообщения после restart API на https://smwhere.ru. Это результаты
отдельного прогона, они не доказывают готовность всех мобильных OAuth-путей.

Нагрузочные цели, расширенные сбои и внешняя резервная копия, реальные каналы
уведомлений, стоимость облака и окончательная приёмка остаются в группе 14.
Деплой в этой задаче не выполнялся; изменение OpenSpec не архивируется
до завершения всей согласованной приёмки.
