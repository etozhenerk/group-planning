# Android: проверка приглашений · 21 октября 2026

Задача 7.5 проверена локально на одном уже запущенном `Pixel_XL_API_36`
(`emulator-5554`, Android 16 / API 36). Дополнительные устройства не запускались.
Изолированный Go HTTPS fixture использует настоящий API и отдельные тестовые
сессии; живой сервер и его встречи не перезапускались.

55 JVM-тестов включают 9 новых: канонические и прежние ссылки, чужой origin,
auth callback, восстановление/очистку контекста, публичность без сессии,
повтор с тем же ключом/ревизией, 409 без автоматической записи, снятие доступа,
401 и обновление серверного ответа при несохранённом выборе.
Ранее существовавшие проверки сессии продолжают покрывать отмену и поздние ответы.

## Сценарии интерфейса

- Публичное приглашение: название, дата, место и описание; без профилей и переписки.
  Кнопка входа честно сообщает об отложенном OAuth. Пересоздание Activity и новый
  владелец экрана сохраняют приглашение; явное закрытие удаляет контекст.
- «Возможно» не открывает чат. «Приду» открывает разговор и состав из двух человек.
  «Не смогу» закрывает их, удаляет встречу из личного списка. Новая сессия того же
  профиля видит подтверждённый ответ; повторное принятие возвращает доступ.
  Переход «Приду → Возможно» также закрывает разговор и компанию.
- Потерянный ответ после commit: подтверждение не показывается преждевременно;
  пересоздание Activity сохраняет pending intent, повтор использует исходный ключ.
  Go fixture проверяет запросы и отсутствие дубля.
- Share открывает настоящее системное меню с исходным HTTPS URL. После возврата
  новая ссылка в работающем приложении открывает вторую встречу.
- При масштабе шрифта 1.8 текст прокручивается, кнопка ответа достижима.

В первом прогоне 10 из 11 UI-тестов прошли; завершение теста новой ссылки упало,
потому что ActivityScenario сопоставляет Activity с исходным Intent. Приложение
корректно обновляло Intent при `onNewIntent`. Тест восстанавливает только свою
идентификацию перед cleanup после проверки новой встречи; повторный полный прогон
из 11 тестов прошёл. Lint-замечание к data-тегам исправлено в manifest без подавления.

## Границы проверки

OAuth остаётся задачей 7.3. Android App Links по публичному HTTPS-домену потребует
`assetlinks.json`; custom scheme и точное сопоставление origin не заменяют эту
проверку. Реальный системный kill процесса в UI-прогоне не выполнялся: проверены
пересоздание Activity, новый ViewModel и чтение зашифрованного файла новым storage.
TalkBack/IME относятся к 7.7. В 7.5 разговор читает последние сообщения; полная
лента с событиями, отправкой, историей и настройками реализуется в 7.6.
