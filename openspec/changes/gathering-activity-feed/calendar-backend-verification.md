# Проверка серверного календаря и фонового перехода

Дата: 22.10.2026. Задачи 9.2, 9.2.1, 9.2.2.

## Реализованное поведение

- Встреча хранит статус, версию расписания и срок перехода. Создание и перенос
  атомарно сохраняют встречу и задачу в одном memory.Store. GET не меняет статус.
- Обработчик запускается вместе с сервером и сохраняет `past` со следующей
  локальной даты. Повтор не повышает ревизию второй раз; прежнее расписание
  и просроченный lease не позволяют изменить новую версию встречи.
- После временной ошибки действует backoff; после исчерпания попыток сохраняются
  окончательная ошибка и операционный сигнал. Управляемый повтор сохраняет
  общее число попыток, последнюю ошибку и число ручных повторов.
- Сверка запускается при старте и периодически, восстанавливает отсутствующую
  задачу ограниченными порциями. Она заново проверяет расписание и не сбрасывает
  попытки, lease, backoff и окончательные ошибки.
- Структурированная диагностика показывает очередь, повторы, зависшие задачи,
  просроченные встречи, задержку и время последней успешной сверки. Пороги
  настраиваются; ошибки и превышение порогов дают сигнал уровня ERROR.
- Календарь поддерживает три раздела, локальный диапазон до 42 дней,
  полные counts/days и страницы. Курсор изменившегося личного набора даёт
  `409 calendar_changed`; выбранные раздел, месяц и день должны сохраняться.
  Запрос без `period` сохраняет прежние форму ответа и курсоры.

## Выполненные проверки

| Проверка | Результат |
| --- | --- |
| `go test -race ./...` | Все пакеты проходят, гонок не обнаружено. |
| Дополнительные тесты одновременного захвата/отката подтверждения | Проходят под race detector. |
| `go vet ./...`, `go build ./...` | Успешно. |
| `go run ./cmd/check-dependencies` | Нарушений нет; HTTP не может собирать worker или использовать запись очереди. |
| `sh scripts/format.sh --check`, `gofmt -l .` | Замечаний нет. |
| `go run ./cmd/storage-demo` | Сценарий памяти проходит. |
| `npm run api:test` | OpenAPI валиден; 31 схема, 16 fixtures и 139 реальных HTTP-ответов проходят проверку. |

Проверены переход без HTTP-запросов в запущенном сервере, остановка обработчика,
повторный запуск с тем же Store, создание/перенос с ошибкой постановки, ошибка
подтверждения после записи статуса и атомарный откат, повтор после сохранения,
одновременный захват и гонка с переносом. Проверены полночь, дни смены UTC-смещения,
пропущенная полночь и пропущенная календарная дата в IANA-поясах.

Проверены потерянная задача, параллельные сверки, перенос между выборкой и записью,
активный lease, backoff, окончательная ошибка, сбой и устаревание сверки,
контролируемый повтор и отсутствие чувствительных данных в диагностике.

Календарные проверки включают 107 встреч с несколькими страницами, два дня,
события одного дня, пустой день, undated, порядок истории, локальную дату
другого пояса, снятие доступа, посторонние изменения, смену статуса между
страницами и прежний запрос/cursor. Частичный календарный ответ не проходит
через legacy-ветку схемы.

## Ограничения и продолжение

UI не менялся: web/iOS/Android реализуются в 9.3–9.5 по утверждённому дизайну.
Новые параметры опциональны, прежние ответы для существующих клиентов сохранены.
Симуляторы и эмуляторы не запускались; пользовательский mock-сервер не перезапускался.

Постоянная БД/очередь, сохранность после остановки процесса, облачные сигналы
и операторский интерфейс относятся к группе 14. Здесь проверен мок одного
процесса, который теряет встречи и задачи при остановке. Управляемый повтор —
прикладная операция без публичного HTTP-маршрута. Порции ограничивают число
операций, но memory-адаптер копирует весь снимок: производительность хранилища
на реальном объёме этими тестами не подтверждается.
