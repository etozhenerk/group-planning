# Android 7.4: проверка первых экранов

Дата: 21 октября 2026. Реализован срез [android-entry.md](android-entry.md).
Это готовность 7.4, а не всего MVP. Реальный вход Яндекс ID отложен.

## Среда и команды

JDK 17.0.20.1, Gradle 8.14.3, SDK 36, один уже запущенный Pixel_XL_API_36
(`emulator-5554`, Android 16). Новые AVD не создавались. iOS-симулятор, живые
Go/web процессы и их memory.Store не перезапускались.

- `sh scripts/check.sh`: чистые Debug/Release, ktlint, Android Lint, JVM,
  Debug instrumentation APK и отдельные QA/QAAndroidTest APK.
- `sh scripts/test-ui.sh`: 6 Compose UI-тестов с отдельным Go HTTPS API,
  6 пройдены, 0 ошибок и пропусков. Тестовый сервер завершился успешно.
- JVM: 46 тестов, 0 ошибок и пропусков. Новые проверки покрывают Unicode-лимиты,
  DST gap/overlap, черновик, потерянный ответ, двойное нажатие, запись до сети,
  401, пагинацию и конечный прогресс одного оборота.
- Go: `go test -race ./...`, `go vet ./...`, `go build ./...`,
  `sh scripts/format.sh --check` — без ошибок.
- `npm run api:test`: 106 HTTP-ответов соответствуют OpenAPI.
- `npm run agent:check` и `git diff --check` — без ошибок.

## Проверенные сценарии

1. Пять слайдов, системный Back, Пропустить, последний экран и сообщение
   о неподключённом входе. Пересоздание Activity сохраняет выбранный слайд.
2. Пустой список содержит одну кнопку создания. Ошибка списка даёт повтор;
   после восстановления API появляется настоящее пустое состояние.
3. Название сохраняется при выходе из формы и открытии новой Activity.
   Дата/время открываются по всей площади поля, выбор подтверждается отдельно.
4. Пустая форма не отправляется. После корректного заполнения сервер создаёт
   встречу, но первый ответ заменяется на 503. Форма замораживает запрос;
   после пересоздания Activity повтор открывает ту же встречу и один элемент
   списка. Сервер подтвердил два POST, один ключ и один meeting ID.
5. Шрифт 1,8: шапка адаптируется, подписи прокручиваются, последняя кнопка,
   календарь, ввод времени и отправка формы остаются доступны. Настройка
   эмулятора восстановлена после теста.
6. Заставка достигает конечного прогресса один раз. Пересоздание Activity
   и переход background/foreground сохраняют AppViewModel и завершённый
   прогресс; повторной заставки нет. Формула ограничена 360°, а при отключении
   анимации возвращает неподвижный знак. После 1,2 с кадровый цикл заканчивается.

## Ограничения

- Проверен эмулятор API 36. Runtime на API 26 и физическое устройство ещё
  не проверялись; minSdk 26 проверяется сборкой и Lint.
- Ручной TalkBack остаётся задачей 7.7. Крупный текст, подписи и навигация
  проверены, но не заменяют полный аудит экранным диктором.
- Обычная сборка показывает онбординг; тестовая авторизация и доверенный CA
  доступны только отдельному QA target. Реальный OAuth UI не проверялся.
- 7.5 — приглашение/Share/RSVP; 7.6 — полноценная лента. После создания сейчас
  открываются данные встречи и копирование ссылки. Календарь списка,
  опросы, задачи и обложка — следующие группы MVP.
- Данные тестового API живут в памяти. Сохранённый Android-черновик не является
  доказательством сохранности серверных встреч после перезапуска.
- CI на GitHub отдельно не подтверждён; отчёт относится к локальным командам.
