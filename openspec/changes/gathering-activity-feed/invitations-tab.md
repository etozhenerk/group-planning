# Приглашения с ответом «Возможно»

Уточнение этапа 10b. Затронуты общий API, web, iOS и Android.
Вкладка возвращает человека к сохранённому приглашению. Доступ к переписке,
составу и опросам по-прежнему требует «Приду» либо роли организатора.

## UX и переходы

В личном разделе под заголовком располагаются две вкладки: «Встречи» и
«Приглашения». Переключатель списка/календаря и фильтры дат относятся только
к «Встречам». Выбор месяца и дня сохраняется при переходе между вкладками.
У приглашений нет календаря, счётчика непрочитанного или отдельной кнопки
создания. Единственное действие создания остаётся в шапке раздела.

```text
Мои встречи                              + Создать
[ Встречи ]  [ Приглашения ]

Прогулка в парке                         →
25 октября · Время пока не выбрано
Парк Горького
Ваш ответ: Возможно

Ужин у Саши                             →
26 октября · 19:00
Ваш ответ: Возможно

                Показать ещё
```

Карточка показывает название, дату и час в поясе встречи (без подстановки
полуночи), место и сохранённый ответ. Открывается существующий экран
приглашения; там человек меняет ответ. Состав, число участников и сообщения в карточку не попадают.
Публичное описание остаётся на экране приглашения.

- «Возможно»: приглашение остаётся в списке, чат закрыт.
- Успешное «Приду»: приглашение исчезает, встреча появляется в личном разделе,
  открывается существующий путь к разговору.
- Успешное «Не смогу»: приглашение исчезает; экран подтверждает сохранённый
  ответ и позволяет вернуться к списку.
- «Приду → Возможно» из встречи: приватные данные очищаются существующим
  механизмом отзыва доступа, после возврата встреча доступна во вкладке приглашений.
- Ошибка отправки: сохраняются прежний ответ и положение встречи; повтор
  использует существующий ключ операции. Конфликт обновляет собственный ответ.
- Back возвращает к выбранной вкладке. Успешное сохранение обновляет обе
  выборки; ответ не меняется оптимистически.

## Состояния

| Состояние | Отображение и действие |
| --- | --- |
| Первый запрос | Скелетоны трёх карточек; заголовок и вкладки остаются доступны |
| Пусто | «Пока нет приглашений» и «Здесь будут встречи, на которые вы ответили „Возможно“.» |
| Ошибка без данных | «Не удалось загрузить приглашения» и «Повторить» |
| Обновление | Загруженные карточки сохраняются, нет повторного пустого экрана |
| Ошибка обновления | Карточки и сообщение ошибки с повтором |
| Догрузка | Список остаётся на месте; спиннер в кнопке, без повторного запроса |
| Выход или 401 | Приватная выборка очищается вместе с сессией |

Web использует отдельный маршрут `/invitations`, обычные ссылки вкладок с
`aria-current`, существующие скелетоны и карточки дизайн-системы. Back браузера
сохраняет маршрут и параметры календаря. На 320 px вкладки помещаются в строку,
текст карточек переносится. Выбор карточки доступен с клавиатуры.

iOS использует Picker с двумя сегментами и существующий NavigationStack;
Android — две Material-вкладки и текущую навигацию; при крупном системном
шрифте вкладки располагаются одна под другой, чтобы названия не разрывались. Выбранный раздел принадлежит
корневому экрану, отдельные состояния загрузки не заменяют календарь. Поддерживаются
системный Back, увеличение текста, VoiceOver/TalkBack и возврат на передний план.
Обновление выполняется при открытии вкладки, возвращении из приглашения и
возврате приложения на экран. Поздний ответ старой сессии не восстанавливает данные.

## API

`GET /api/v1/invitations?limit=50&cursor=<uuid>` — только для авторизованного
пользователя. `limit` от 1 до 100. Отдельный маршрут не меняет существующий
`GET /api/v1/meetings` и не расширяет права старых мобильных клиентов.

```json
{
  "invitations": [{
    "invitation_url": "https://example.test/i/opaque-token",
    "preview": {
      "meeting_id": "00000000-0000-4000-8000-000000000001",
      "title": "Прогулка",
      "description": null,
      "starts_on": "2026-10-25",
      "starts_at": null,
      "timezone": "Europe/Moscow",
      "place": null,
      "cover_url": null,
      "my_rsvp": "maybe",
      "my_rsvp_revision": "2"
    }
  }],
  "next_cursor": null
}
```

`preview` совпадает с публичным preview приглашения с собственным ответом. Ссылка нужна для существующего сценария
приглашения и возвращается только владельцу текущего `maybe`.
Организатор, `going`, `not_going` и отсутствие ответа исключены. Все записи
читаются одним согласованным снимком. Сортировка по неизменяемому ID встречи
по возрастанию, курсор — последний ID; он не даёт прав на чужие встречи.
При смене состава между страницами следующая страница проверяет текущие ответы;
полное обновление перечитывает список сначала. Клиент объединяет страницы по ID.
Ошибки: 401 без сессии; 422 для неверного cursor; 400 для неверного limit или лишнего query.
Кэш публичного preview не заменяет проверку сессии этого маршрута.

## Проверка

Сервер: изоляция двух пользователей, отсутствие неотвеченных/отказавшихся/
пришедших и организатора, пагинация, только публичные поля, переходы ответов,
403 на чат и опросы при `maybe`. Общий fixture декодируют все клиенты.
В каждом клиенте: пусто, ошибка/повтор, скелетон, Back, смена ответа с подтверждением
сервера и после ошибки, возврат из чата с `maybe`, очистка при выходе. Снимки
фиксируют 320/390/1440 px в web и по одному уже открытому нативному устройству.
