# UX: состояния и прокрутка чата, v1

25.10.2026. Техническое дополнение к согласованному
[дизайну встречи](../meeting-experience-refresh/ux.md), не его замена.
Сохраняются токены, пузырьки, карточки, шапка, плюс и composer из
[макетов](../meeting-experience-refresh/assets/chat-menu.html).
Ниже — эскизы новых состояний и переходы; это ещё не проверка приложений.
Пользователь подтвердил личные непрочитанные и список прочитавших.
Численные пороги прокрутки/видимости — предложение для проверки на устройствах.

## Путь пользователя

Список встреч со счётчиком → чат → прежняя видимая строка, если сохранена;
иначе первое непрочитанное, иначе хвост. Возврат сохраняет положение списка
встреч; повторный вход в чат сохраняет его якорь в пределах текущей сессии.
Если якорь удалён или недоступен, переходим к первому непрочитанному/хвосту.
Авторизация и права проверяются до показа приватных данных после холодного старта.

Внутри: прокрутка вверх догружает историю; новые сообщения показывают кнопку
перехода вниз, если человек читает прошлое. Отправка из истории добавляет
исходящее в хвост и показывает «К новым сообщениям», но сама не уводит читателя.
У хвоста исходящее сразу видно. Back сохраняет черновик и очередь отправки;
logout удаляет локальные данные этого аккаунта.

## Эскизы изменений

Узкий экран, чтение истории; рамки обозначают структуру, не новый стиль:

```text
┌──────────────────────────────────────┐
│ ← Встреча                        ⋯   │  шапка закреплена
├──────────────────────────────────────┤
│       [скелетон старых строк]         │  догрузка только у границы
│ Аня · 18:10                          │
│ Возьму термос.                       │  якорь + смещение сохраняются
│ ───── Непрочитанные ────────────────  │  позиция при открытии, без прыжка
│ Борис · 18:12                        │
│ Я возьму кружки.                     │
│                      [↓ 3 новых]     │  над composer, не поверх строки
├──────────────────────────────────────┤
│ +  Написать сообщение          [↑]   │  над клавиатурой / safe area
└──────────────────────────────────────┘
```

Состояния одной исходящей строки, без переноса в другой контейнер:

```text
Взял билеты.       18:14  ◷      → локально сохранено, отправляется
Взял билеты.       18:14         → сервер сохранил; без вспышки «Успешно»
Взял билеты.       18:14  !      → Не удалось отправить. [Повторить]
Взял билеты.       18:14         → [Прочитали 2] после серверного read state
```

Нет отдельного «Доставлено»: факт хранения на сервере и чтение различаются.
У неопределённого результата запроса подпись «Проверяем отправку» появляется
только после короткого ожидания; повтор сверяет прежний ID и не создаёт копию.

Список прочитавших: bottom sheet на телефоне, popover/диалог на широком web:

```text
┌──────────────────────────────────────┐
│ Прочитали                        ×   │
│ [аватар] Аня                         │
│ [аватар] Борис                       │
└──────────────────────────────────────┘
```

Для своего подтверждённого сообщения вход через «Прочитали N» или действие
«Кто прочитал» в меню. При нуле — «Пока никто не прочитал». Имена только текущих
участников, без почты/телефона и выдуманного времени чтения. После выхода
участника число может уменьшиться. Закрытие возвращает фокус к сообщению
и не меняет scroll. Длинный список прокручивается внутри sheet, страница — нет.

## Состояния и тексты

| Состояние | Вид и действие | Что сохраняем |
| --- | --- | --- |
| Первый вход, данных нет | Скелетоны пузырьков/карточек внутри ленты; одно доступное название «Загружаем сообщения» | Размер шапки и composer, без мигания пустого состояния |
| Чат пуст | Существующее событие создания и приглашение из согласованного дизайна | Не добавляем второй блок «Здесь будет чат» |
| Догрузка | 2–3 скелетона у верхней/нижней границы; без глобальной блокировки | Якорь, ввод, уже показанные строки |
| Догрузка не удалась | «Не удалось загрузить сообщения» + «Повторить» у той же границы | Показанные данные, корректный cursor |
| Переподключение короче 2 с | Без баннера | Лента и ввод доступны |
| Сеть недоступна дольше | Одна строка «Нет соединения»; после восстановления исчезает | Исходящие с часами; отправка после восстановления |
| Новые записи при чтении прошлого | «3 новых сообщения» с русским склонением; если только собственное — «К новым сообщениям» | Текущее место, фокус |
| Сохранение на устройстве не удалось | «Не удалось сохранить сообщение на устройстве» у composer, повтор сохранения | Текст остаётся в поле, POST ещё не отправлен |
| Ошибка конкретной отправки | Значок и «Повторить» у строки; окончательная ошибка позволяет вернуть текст в редактор | Прежний ID для повтора; новый черновик не перезаписываем без выбора |
| Загрузка прочитавших | Скелетоны имён в sheet; ошибка «Не удалось загрузить список» + «Повторить» | Положение чата |
| Доступ отозван | Закрыть чат, показать существующее состояние недоступности встречи | Приватные строки и исходящие этой встречи очищаются |

«Нет соединения» показывается при подтверждённой потере сети/соединения,
а не при любой серверной ошибке. Доступный HTTP при отказавшем WebSocket:
«Обновления задерживаются» только при длительном запасном режиме.
Технические названия WebSocket, cursor и retry в UI не показываются.

## Прокрутка и прочтение

- Только лента владеет вертикальной прокруткой чата; body и горизонтальный
  scroll отсутствуют на обычных ширинах. Длинные слова/ссылки переносятся.
- Режим следования включён, если нижний край не дальше 64 CSS px / pt / dp
  от хвоста. Ручной уход вверх его отключает. Кнопка вниз включает снова.
- Перед prepend, изменением высоты карточки, ACK, клавиатурой и поворотом
  сохраняем ID видимой строки и смещение; данные загружаются заранее примерно
  за два экрана до границы, одним запросом на направление.
- При первом открытии вокруг непрочитанных разделитель фиксируется на позиции
  начала сессии чтения, не бегает вслед за marker. Если всё прочитано до входа,
  разделителя нет. Счётчик списка отражает серверное состояние.
- Клиент отправляет read-through только в активном видимом чате, когда нижний
  край сообщения виден минимум 500 мс, не закрыт клавиатурой/модальным окном.
  Это правило работает и для сообщения выше экрана по высоте: нужен его конец.
- Позиция означает «прочитано до этой строки включительно», а не отдельное
  доказательство просмотра каждой строки. Получение данных и фон не читают чат.
  Явный переход к хвосту с просмотром его строк продвигает эту позицию.
- Открывшийся sheet прочитавших приостанавливает read-through под ним.
  Смена устройства не откатывает уже подтверждённую позицию.

## Платформы, компоненты, доступность

| Платформа | Компоненты и особенности |
| --- | --- |
| Web | `FeedTimeline`/`useViewport`, `SendMessage`, карточки встреч; адаптер виртуализации, flex/min-height и visualViewport. Клавиатура, IME, Escape и фокус сохраняются; loading не заменяет всю страницу. Контейнер ленты имеет доступное имя, новые строки не перехватывают фокус; aria-live сообщает только краткое количество. |
| iOS | `MeetingFeedScreen`, `FeedTimeline`, FeedOwner; scenePhase, safe area, нативная клавиатура и sheet, Dynamic Type/VoiceOver. Lazy-контейнер дополняется ограниченным окном данных; клавиатура не создаёт вторую вертикальную прокрутку. |
| Android | `FeedViewModel`, `FeedTimeline`/LazyColumn, MessageOutbox; lifecycle, IME insets, Back закрывает сначала sheet/клавиатуру. Font scale/TalkBack и stable keys проверяются вместе с reverse layout. |

Скелетоны не объявляют каждую строку screen reader. Reduce Motion отключает
анимацию скелетона/плавный автоскролл; контент остаётся доступен. Цвет не заменяет
иконку и доступное название ошибки/отправки. При виртуализации сфокусированная
строка не удаляется; переход к строке вне окна сначала загружает её.

DTO/операции — [protocol.md](protocol.md); все экраны имеют собственный клиентский
UI, сервер не присылает разметку. Визуальную проверку на телефоне и широком
экране выполняем при реализации по [validation-plan.md](validation-plan.md).
