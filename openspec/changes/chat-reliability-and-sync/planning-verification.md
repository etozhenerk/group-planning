# Проверка пакета планирования

Дата: 25.10.2026. Область: `chat-reliability-and-sync`, только документация.

## Проверено

- Исследование использует первичные русскоязычные статьи Avito/VK,
  зарубежные статьи Slack/Discord и документацию авторов технологий.
  Исторические статьи отделены от текущих API; их масштабы не выдаются
  за измерения somewhere. Все ссылки на источники находятся в research/security.
- Наблюдения кода отделены от воспроизведённых дефектов. Гонка 100/101/102
  описана как вывод статического анализа и имеет будущий regression test.
- Ответ пользователя о двух видах прочитанности отражён в proposal, UX,
  protocol, design, specs и задачах. Baseline не создаёт ложных read receipts.
- Курсоры истории, изменений, чтения и транспортного recovery различаются;
  потерянный ACK, commit→publish, snapshot→subscribe и rollback предусмотрены.
- Шифрование рассмотрено в двух моделях. Серверная модель рекомендована,
  но не названа утверждённым отказом пользователя от E2EE. Matrix — альтернатива,
  не уже подключённая инфраструктура. Защита backup не объявлена проверенной.
- UX содержит текстовые эскизы, переходы, ошибки, доступность и отличия
  трёх платформ; тексты проверены product-copy-editor. Согласованный соседний
  дизайн сохранён как основа. Ссылки на локальные файлы разрешаются.
- Есть отдельные задачи backend/web/iOS/Android с проверкой в каждом пункте,
  подготовка независимых релизов, прежние клиенты и откат. 37 задач реализации
  остаются открытыми; полная готовность planning artifacts не означает готовность кода.

## Команды

- `npm run --silent openspec -- validate chat-reliability-and-sync --strict` — PASS.
- `npm run agent:check` — PASS; структура OpenSpec, локальные инструкции,
  закреплённый CLI и ссылки документации.
- Дополнительная проверка относительных Markdown-ссылок нового изменения — PASS.
- `git diff --check` и проверка staged diff нового изменения — PASS.

## Не проверено этим исследованием

Runtime новых SDK, новые миграции, performance budgets, actual storage encryption,
интеграция на облачной БД, реальные клиенты/устройства, релиз и деплой.
Исходники приложений и конфигурация эксплуатации этим изменением не меняются.
Проверки реализации перечислены в validation-plan и остаются в tasks.md.
