## Дефект и исправление

При обычном обновлении черновика пустая очередь захватывала30-секундное
владение IndexedDB. Reload мог прервать finally, оставив новым исходящим
ожидание старой страницы. Независимый исходный fail воспроизведён автором
в1из10 повторов: online=true, visible, остаток lease24626мс, новых POST нет.

Очередь теперь захватывает Web Lock только при наличии исходящего. Браузер
освобождает lock вместе с контекстом страницы; новый владелец заменяет только
lease, помеченный как созданный под таким lock. Живой старый клиент с обычной
lease сохраняет владение до освобождения/expiry. Без Web Locks остаётся атомарная
lease IndexedDB. Epoch и серверный idempotency key сохранены. После durable
sending-update повторно проверяется активность, чтобы logout не начинал POST.
Стандарт: [W3C Web Locks](https://www.w3.org/TR/web-locks/).
