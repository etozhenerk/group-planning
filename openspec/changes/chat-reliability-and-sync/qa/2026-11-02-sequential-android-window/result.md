# Android6.3 — bounded store и позиция чата

Локальный memory/HTTPS fixture, официальный SDK, отдельный QA target на уже
запущенном emulator-5554/API36; production/Telegram/физические устройства не использовались.

Три адресных UI-сценария прошли: `android-divider-fixed.log`, 3/3 за9,807с.
Два component UI проверяют reverse LazyColumn: prepend/новый хвост, позднюю
высоту строки, уменьшение viewport, возврат и низ огромного сообщения.
Новый настоящий API/UI-путь создаёт120 сообщений и first_unread в середине:
разделитель видим, открывается настоящая экранная IME, Back сохраняет draft,
чужой новый хвост и собственный подтверждённый POST не уводят читателя;
выход/повторный вход возвращает то же сообщение с допуском2dp.
Снимки последнего прохода — `android-actual`, осмотрены основным агентом.

Найден и исправлен реальный сбой: сохранённый offset контейнера включал
разделитель непрочитанных; после прочтения и повторного входа разделителя уже
не было, пузырёк сдвигался. Теперь viewport хранит необязательный измеренный
leadingInsetDp и учитывает его изменение; при первом входе ожидается настоящее
измерение разделителя, чтобы не прятать его за шапкой. Старое значение без
нового поля и недоступный anchor сохраняют прежний fallback.

Первоначальные ошибки QA (limit200 и сравнение пустого Text с placeholder),
исходный настоящий FAIL повторного входа и промежуточный первый фикс сохранены
раздельно. После осмотра снимков первый фикс уточнён: разделитель обязан быть
видимым при первом входе; последняя проверка содержит assertIsDisplayed.

Ограничение окна500 и повторная загрузка вытесненной области подтверждены
`ChatMergeTests.windowRemainsBoundedAroundReaderAndDiscardedEdgesCanReload`:
2000 входных строк, anchor500, окно500, оба края доступны. FeedLoadingTests
проверяют независимый receive cursor/history и отзыв доступа; FeedRowTests —
тот же ключ pending/ACK. Эти текущие unit входят в обязательный Android check.

Полный измерительный профиль10k/frame/memory/commit→visible остаётся в1.6/7.9;
этот адресный результат не является его PASS и не закрывает общий7.8/qa:ready
или независимый design-review. Работа выполняется основным агентом последовательно
по прямому указанию пользователя без запуска субагентов.

Окончательный `android-check-final.log`: PASS — formatCheck,197/197 unit,
Debug/Release APK, Debug/Release Lint и Debug instrumentation APK. Это
инкрементальный повтор после последнего уточнения; до него полный clean
`check.sh` прошёл в `android-check.log`. `agent:check` и `git diff --check` PASS.
