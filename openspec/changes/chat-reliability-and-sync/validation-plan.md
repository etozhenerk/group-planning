# План проверки

Это критерии разрешённой реализации, не результаты замеров. Подготовка
тестспецификации 27.10.2026 не запускала приложения, SDK или миграции.
Исполняемые кейсы и платформы перечислены в [testing.md](testing.md);
статический baseline в current-state.md не считается воспроизведением.

## Baseline и измерения

Вначале измерить текущую версию теми же сценариями. Профиль пилота: 100
активных соединений, 5 сообщений/с 15 минут, всплеск 20/с 60 секунд,
отдельно одна горячая встреча и распределённая нагрузка. Это тестовый бюджет,
не обещание мощности и не создание дополнительной платной инфраструктуры.
Согласовать доступную тестовую ёмкость существующего окружения; не нагрузить
пользовательский production. Локально только memory.Store и mock dispatcher.

| Что | Критерий / условия |
| --- | --- |
| Commit→visible | p95 ≤ 1 с, p99 ≤ 2 с: foreground, RTT 150 мс, без потерь, указанный профиль. Отдельно время SQL, dispatch, HTTP catch-up, merge/render. |
| Возврат после 5 минут offline | До 100 пропущенных изменений отражены ≤ 2 с после восстановления доступного соединения при тех же условиях. Большие разрывы имеют отдельный замер; не обещать этот срок для любой истории. |
| Пустой after и страницы | Истории 1k/10k/100k; SQL LIMIT/индекс, EXPLAIN не показывает полный проход по JSON-истории ради страницы. p95 запроса страницы ≤ 100 мс в записанном тестовом окружении. |
| Metadata/unread/receipts | Измерить отдельно на тех же объёмах: отсутствие полной загрузки JSON, адекватные индексы, p95 ≤ 100 мс. При провале сначала проекция/индекс, а не сокрытие стоимости в общей метрике. |
| Исправный idle | Нет периодических GET feed/sync и опросов карточек при отсутствии изменений; heartbeat допустим. |
| Scroll anchor | После prepend, ACK, resize и клавиатуры смещение той же строки ≤ 2 CSS px / pt / dp; отсутствует скачок к хвосту при чтении прошлого. |
| Объём | Не более 500 серверных записей обычного окна; web ≤ 200 смонтированных строк; память стабилизируется при проходе 10k записей. Outbox/focus исключения учитываются отдельно. |
| Кадры | Цель p95 frame ≤ 16,7 мс на 60 Hz при сценарии прокрутки на записанном устройстве; длинные кадры и dropped frames отчётно, без обещания 120 fps. |

Commit→visible проверяется общей трассой/управляемым тестовым временем,
а не вычитанием несинхронизированных часов телефона и сервера. Метрики
без текста/токенов: outbox age/retries, reconnect count, sync resets, sync lag,
lock wait, page duration, bounded queue size, discard stale callback.

## Обязательные сценарии надёжности

1. Race 100/101/102 из current-state: POST не пропускает чужую запись.
2. HTTP response потерян после commit; повтор после истечения receipt;
   повтор того же ID с другим телом; чужой автор с тем же локальным ID.
3. Процесс клиента уничтожен до POST/после commit/до merge; восстановление
   нескольких pending, ошибка диска/quota, draft уже изменился, две web-вкладки
   одновременно забирают очередь и одна выходит из аккаунта.
4. Разрыв между snapshot и subscribe; reconnect во время записи; события
   повторены/переставлены, последняя страница has_more, истёкший cursor/epoch.
5. Crash dispatcher до publish/после publish до отметки; потеря NOTIFY;
   обрезка журнала, рестарт MemoryBroker, медленный клиент и переполнение очереди.
6. Изменение старой карточки, закрытие скрытого опроса, обезличивание автора
   за пределами короткого окна, полное удаление встречи.
7. Отзыв RSVP/сессии между hint и HTTP, logout/login другим аккаунтом
   во время записи outbox, late SDK callback и late read-marker response.
8. Одновременное чтение двух устройств; out-of-order markers; initial baseline
   не создаёт receipts; first join/rejoin; собственные/системные записи не unread.
9. Readers: только автор, только текущие участники, пагинация, выход/удаление
   после открытия списка; прежний клиент без markers не считается прочитавшим.
10. Healthy/fallback/foreground lifecycle: один цикл запросов, прекращение
    fallback после восстановления, отсутствие фоновой отправки read state.

## Проверка безопасности и совместимости

Проверить Origin/session auth, expired session, чужой channel, отсутствие
секретов/текста в URL и логах, скрытые голоса, чужие readers, очистку outbox.
Сверить фактическую защиту БД/backup и восстановление с уже закрытой
эксплуатационной документацией; не выдавать TLS за E2EE.

Проверить новые серверы со старыми поддерживаемыми сборками и новые клиенты
с отключённой capability. Версии фиксируются в отчёте. Откат backend без
журнала обязан менять epoch при возврате. Пользователь 27.10.2026 разрешил
необходимые релизы бэкенда и миграции production-БД после release-test и получения
receipt точного кандидата. Публикация клиентов в магазинах остаётся отдельной
работой; локальные воспроизводимые артефакты готовятся отдельно от приёмки.

Структурная проверка OpenSpec, agent:check и markdown links проверяют пакет
планирования; они не доказывают прохождение перечисленных runtime-критериев.
