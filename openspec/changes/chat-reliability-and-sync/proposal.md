# Proposal

## Why

Пользователь 25.10.2026 запросил исследование и техническую переработку чата:
задержки, прокрутка, дозагрузка, прочитанность и шифрование. Текущий polling
и различающиеся клиентские состояния требуют доработки до добавления медиа
и реакций из `meeting-experience-refresh`.

## What Changes

- Предлагается Centrifuge внутри существующего Go-приложения и его клиентские
  SDK: push по WebSocket, HTTP-команды, подтверждение только после commit.
  Polling остаётся ограниченным запасным режимом и путём прежних клиентов.
- История и восстановление остаются в PostgreSQL: SQL-пагинация по ключу,
  отдельный курсор изменений, атомарный журнал уведомлений, восстановление
  после пропуска/перезапуска без перескакивания через сообщения.
- Единая модель черновика, исходящих и серверных сообщений на web/iOS/Android;
  сохранение намерения отправить до POST, повтор с прежним ID, стабильная строка.
- Ограниченная по памяти лента, автоматическая догрузка, сохранение видимой
  строки, работа клавиатуры и возврат к непрочитанным. UX — [ux.md](ux.md).
- Серверная позиция прочтения, личные непрочитанные между устройствами
  и список прочитавших собственное сообщение. Оба сценария подтверждены
  пользователем 25.10.2026; WebSocket сам по себе не подтверждает прочтение.
- Сравнение TLS/защиты хранения и E2EE, готовых технологий и их ограничений —
  [research.md](research.md) и [security.md](security.md). Рекомендация для
  текущего этапа — защищённый серверный чат; это предложение, не согласие
  пользователя отказаться от E2EE. Самописный криптопротокол не предлагается.
- Проверяемые бюджеты задержек, памяти, запросов и поведения при сбоях;
  независимая поставка backend/web/iOS/Android с обратной совместимостью.

Это планирование, без реализации, установки SDK, миграций или деплоя.
Не добавляются редактирование сообщений, typing/presence, push ОС, поиск
и новая система модерации. Медиа/реакции остаются в соседнем изменении,
здесь определяются точки их подключения и корректная синхронизация.

## Capabilities

### New Capabilities

Постоянный `openspec/specs/` пока пуст. Для существующей области используем
имя `event-feed`; добавляем технические требования, не копируя базовые правила.

- `chat-sync`: доставка обновлений, восстановление, исходящие и жизненный цикл.
- `chat-read-state`: позиция прочтения и непрочитанные между устройствами.
- `chat-security`: защита каналов, локальных данных и честная модель шифрования.
- `event-feed`: ограниченная лента, стабильные строки, дозагрузка и прокрутка.

### Modified Capabilities

Нет опубликованных main specs. Перед синхронизацией объединить дополнения
`event-feed` с `gathering-activity-feed` и `meeting-experience-refresh`.

## Impact

- Backend: `meetings`, `httpapi`, `storage/memory`, `storage/postgres`, общий
  API и fixtures; один модульный монолит по ADR 0003, без отдельного чат-сервиса.
- Web: FSD-модель синхронизации/исходящих, `FeedTimeline`, `SendMessage`,
  счётчики списка, адаптеры Centrifuge и виртуальной ленты.
- iOS: владельцы Feed, адаптер потока, защищённое локальное хранение,
  SwiftUI-лента и жизненный цикл; Android: repository/Flow, MessageOutbox,
  FeedViewModel и LazyColumn. Общий контракт, отдельная реализация UI.
- Предлагаемые зависимости проверяются и закрепляются в начале реализации:
  Centrifuge + JS/Swift/Java SDK, бесплатный `react-virtuoso` для web.
  Коммерческий Message List, Redis, Kafka и новый облачный сервис не включены.
- SQL-расширения проверяются на существующей изолированной облачной БД.
  Локальная разработка остаётся на memory.Store; локальную БД/Docker не поднимать.
- Эксплуатация получает требования к соединениям, метрикам, защите хранения
  и откату; текущая параллельная работа по деплою не изменяется этим предложением.
