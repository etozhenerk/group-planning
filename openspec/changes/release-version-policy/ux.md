# UX: версия web-клиента, v2

## Статус и границы

25.10.2026 пользователь выбрал полный номер в футере: `0.1.0`, для кандидата
`0.1.0-rc.2`. Это уточняет короткую подпись `0.1` из
[предыдущего UX](../meeting-experience-refresh/ux.md#футер-версия-и-документы).
Политика выпуска из [design.md](design.md) также принята пользователем для реализации.
Позднейшее решение 25.10.2026: «футер только в десктоп версии и только на онбординге».
Оно отменяет размещение футера на mobile web, внутренних и native-экранах.
Ниже эскиз изменения существующих компонентов, а не новая страница или проверка
реализованного интерфейса.

## Путь и размещение

На десктопе посетитель открывает онбординг (`/`) → видит полный номер в футере →
открывает «О somewhere» → читает тот же номер и отдельную строку сборки.
Десктопный футер требует ширину от 740 px и основной точный указатель с hover
(`pointer: fine`, `hover: hover`). До 739 px и на touch-устройствах он скрыт,
включая горизонтальное положение телефона 844×390.
На мобильном экране и внутренних страницах футера нет: сведения доступны через
раздел профиля или прямой переход `/about`. Переход назад остаётся штатным;
чтение версии по прямой ссылке не требует входа.

Основа — [макет справки](../meeting-experience-refresh/assets/about.html)
и десктопный онбординг `meeting-experience-refresh`. Прежний мобильный
[макет футера](../meeting-experience-refresh/assets/screenshots/version-footer-390.png)
сохранён как исторический и не определяет актуальное размещение.
Сохраняются тема, колонки, отступы и подпись
Developed by MintyDev. Новых кнопок и ссылок на GitHub для обычного пользователя нет.

## Эскиз v2

Футер десктопного онбординга:

```text
[существующие группы ссылок]
Версия 0.1.0-rc.3                  Developed by MintyDev
```

На телефоне футер отсутствует. На внутренних страницах он отсутствует
при любой ширине, включая справку, профиль, встречи, чат и альбом.

Секция справки:

```text
О somewhere
[существующий текст о приложении]

Версия 0.1.0-rc.3
Сборка 42
Developed by MintyDev
```

В табличной разметке справки подпись «Версия» находится в `dt`, а полный
номер без повторения подписи — в соседнем `dd`. `AboutContent` получает
тот же источник, что и футер десктопного онбординга.

Это иллюстративные номера, не утверждение о текущей production-сборке.
SHA и технический тег остаются в release metadata; в обычной подписи они не нужны.

## Состояния и адаптация

| Состояние | Десктопный онбординг / справка на всех экранах |
| --- | --- |
| Окончательный релиз | `Версия 0.1.0` |
| RC | `Версия 0.1.0-rc.3`, весь суффикс сохранён |
| Локальный запуск | `Локальная сборка`; без выдуманного build number |
| Demo | `Демо`; без выдуманного production-номера |
| Нет метаданных в старой/повреждённой сборке | `Версия недоступна`; новый release с этим состоянием запрещён |
| API недоступен | Подпись остаётся: сетевого запроса за версией нет |
| После деплоя в старой вкладке | Номер загруженной в неё сборки до обновления страницы |

Загрузка, пустой список, форма ввода, повтор отправки и диалог подтверждения
неприменимы: это статический текст. Допустим перенос строки без ellipsis;
проверить справку на 320/390/1280 px, футер на десктопном онбординге,
отсутствие футера на 320/390 px, увеличение текста и выделение номера. Не добавлять
tab-stop неинтерактивной строке. Существующие ссылки сохраняют фокус и области
нажатия. Экранная читалка должна получить строку целиком.

## Платформы и ответственность

- Web: `shared/config` хранит метаданные и производную подпись;
  `widgets/service-footer` и `pages/service` отображают её через публичные API FSD.
- iOS и Android: новый UI вне объёма. Существующий план разделов профиля/справки
  остаётся в `meeting-experience-refresh`; каждый клиент показывает свою версию.
  Полный RC в release manifest не следует записывать в числовое поле версии iOS.
- Backend: версии сайта не назначает и дополнительный endpoint не требуется.

## Проверка текстов

Применён product-copy-editor: задача пользователя — назвать свой выпуск при
сообщении об ошибке. Футер даёт номер сразу; справка добавляет отдельный номер
сборки. `Версия` и `Сборка` не используются как синонимы.

| Место | Правка |
| --- | --- |
| Футер ServiceFooter | Полный номер; только десктопный онбординг |
| Секция версии в AboutContent | Полный SemVer — «Версия»; CI number — «Сборка», без футера |
| Developed by MintyDev | Сохранить без изменений |
| Остальные блоки справки и футера | Сохранить, не добавлять объяснение SemVer в продукт |

Визуальная и браузерная проверка реализации остаётся задачей apply.
