# Реализация и проверки политики релизов

Дата: 25.10.2026. Пользователь поручил применить план, закрепить политику
повышения версий и шаблон описания. Изменения выполняются в общем `main`
с `meeting-experience-refresh`; принадлежность файлов согласована между чатами.

## Реализовано

- Независимые SemVer пяти компонентов, правило максимальной значимости,
  отличия `0.x`/`1.x`, RC, неизменяемость и мобильный счётчик описаны в
  [инструкции](../../../docs/releases.md).
- `prepare.py` проверяет чистоту, принадлежность SHA `origin/main`, историю
  компонента и bump; сохраняет карточку без создания тега. Карточка входит
  в аннотацию тега и manifest schema 2. CI проверяет её перед сборкой
  и повторно перед публикацией после обновления списка тегов.
- [Шаблон описания](../../../docs/release-description.md) реализован генератором:
  номер и причина, изменения, совместимость, фактические проверки до тега/в CI,
  ограничения, файлы с размерами. Секреты в карточку не включаются.
- Web получает встроенную идентичность и `build-info.json` из одного
  проверенного объекта. Сокращения SemVer и fallback из package.json нет.
  Футер показывает полный номер, справка — тот же номер и отдельную сборку.
  Dev/demo имеют собственные подписи. Запрос к API за версией не выполняется.
- Проверка архива сравнивает его идентичность с manifest даже при корректно
  пересчитанных SHA256. Отдельный browser smoke открывает распакованный bundle.
  `infra/host/deploy-release.py` не менялся: существующие старые артефакты
  и путь отката не переводятся принудительно на schema 2.

штатном origin. Релизный browser smoke не зависит от этого набора и использует
отдельный порт 9328 без API.

## Совместимость и границы

`android.py` и `ios.py` по-прежнему получают числовую часть SemVer и отдельный
build number. Проверены оба края 1/9999 и отказ 0/10000. Store-номера сверяет
ответственный перед каждой загрузкой; доступа к истории магазинов у CI нет.
Подписанные IPA/AAB/APK и upload в этом изменении не выполнялись.

Маршрутизация Component releases сохранена: пять префиксов, только выбранный
компонент. Go-код, нативные приложения, API, схема БД и infra provisioning
этим изменением не редактировались. Backend/monitoring получают новую карточку
в общем manifest, содержимое их сборочных команд не изменилось.

Новые Git-теги, GitHub Releases и production-деплой в рамках этих проверок
не создавались. При настоящем выпуске нужно выбрать актуальные номер и SHA,
подготовить конкретную карточку и проверить сайт после установки артефакта.
