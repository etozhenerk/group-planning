# Design

## Context

Мотивация — [proposal](proposal.md). `feature-test` получает cases/requirements,
`release-test` проходит полный каталог; они решают задачу приёмки. Новый навык
ищет неизвестные проблемы и не заменяет их. Актуальные specs ещё находятся
в активных изменениях. Продуктовые данные, API и клиенты не меняются; UX/UI
и совместимость сборок неприменимы. Проверки — [testing.md](testing.md).

## Goals / Non-Goals

**Goals:** воспроизводимый запуск независимого исследователя по запросу,
проверяемая политика вызова, полезные доказательства и отдельный разбор.

**Non-Goals:** новый browser runner, установка сторонних CLI, автопочинка,
автоматические расписания, изменение feature/release gates, проход продукта
в рамках создания навыка.

## Decisions

1. **Свой короткий навык без новой зависимости.** Используем идеи
   [Vercel dogfood](https://github.com/vercel-labs/agent-browser/blob/main/skill-data/dogfood/SKILL.md),
   [Callstack dogfood](https://github.com/callstack/agent-device/blob/main/skills/dogfood/SKILL.md)
   и [исследовательского тестирования](https://www.satisfice.com/exploratory-testing).
   Переносим принцип наблюдения и evidence, не копируем квоту ошибок, обязательные
   CLI или отбрасывание нерегулярных сбоев. Альтернатива
   [ce-dogfood](https://github.com/EveryInc/compound-engineering-plugin/blob/main/skills/ce-dogfood/SKILL.md)
   ориентирована на diff и исправления, что не соответствует независимости.
2. **Два исполнителя.** Родитель готовит нейтральное окружение и бриф;
   `spawn_agent` с `fork_turns: "none"` получает только бриф, нейтральные правила
   исследователя и шаблон отчёта. Нет наследования истории, чтения корпуса
   продукта или общих стартовых документов. После фиксации отчёта родитель
   делает отдельный triage, ссылаясь на исходные ID. Это изоляция контекста
   инструкциями, не обещание файлового sandbox.
3. **Явная политика Codex.** `agents/openai.yaml` содержит
   `policy.allow_implicit_invocation: false`; `agent:check` проверяет значение
   как boolean, включая отсутствие/ошибочный тип. AGENTS и config объясняют
   естественный явный запрос и исключают автозапуск из apply/release/CI.
4. **Ограниченная сессия.** При отсутствии бюджета — 30 минут исследования
   суммарно на заявленные платформы с сообщением допущения; отчёт завершает
   сессию. Нет самостоятельного расширения или запуска по расписанию.
   Доступ и test-only эффекты готовит родитель. Инструменты выбираются из
   доступных UI/browser/device средств, без выдуманных CLI-вызовов.
5. **Отчёт вне acceptance schema.** `.qa-runs/exploratory/<session>/` хранит
   бриф, отчёт и evidence; итог обезличивается и сохраняется долговременно
   по правилам testing. Нет конвертации в `run.json`/receipt или изменения
   automation. Frozen-отчёт и evidence фиксируются SHA256; triage — другой файл.

## Risks / Trade-offs

- [Доступ к репозиторию технически возможен] → явный allowlist контекста,
  запись использованных источников, перезапуск при загрязнении; не обещаем
  жёсткую техническую изоляцию.
- [Необычное действие ошибочно названо багом] → основание ожидания в UI,
  отдельные категории и уверенность; сверка требований только на triage.
- [Недоступно устройство/логин] → blocked для этой области, без фиктивного
  прохода макетов; остальные доступные области продолжаются.
- [Длительное исследование или побочные эффекты] → бюджет, область и тестовые
  данные в брифе; остановка при исчерпании, приватные evidence вне Git.

## Migration Plan

Добавить навык и документы, зарегистрировать его и непродуктовую область
изменения, проверить metadata и синтетическое поведение, выполнить проверки
репозитория. Для отката удалить навык и его ссылки/регистрацию; каталог кейсов,
приложения и gates не мигрируют.
