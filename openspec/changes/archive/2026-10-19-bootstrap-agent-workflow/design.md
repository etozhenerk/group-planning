# Design

## Context

См. мотивацию в `proposal.md`. В репозитории есть только начальный каркас
четырёх приложений. OpenSpec добавляется как инструмент разработки; работающие
приложения и продуктовые требования ещё отсутствуют.

## Goals / Non-Goals

**Goals:** агент получает контекст из файлов, выбирает правила затронутого
приложения и запускает воспроизводимый стандартный процесс OpenSpec.

**Non-Goals:** выбор стека приложений, пользовательские фичи, схема данных,
API, сборки клиентов, деплой и CI. Для бэкенда и всех трёх клиентов изменяются
только инструкции; формат обмена данными остаётся открытым решением.

## Decisions

- **Пять файлов AGENTS.md.** Один в корне и по одному в четырёх приложениях.
  Корневой файл явно требует чтения правил перед редактированием соответствующей
  области. Дополнительный уровень `frontend/AGENTS.md` исключён по решению пользователя.
- **Оригинальные навыки.** Установить стандартную схему и core-навыки OpenSpec
  с дополнительным verify. Собственный набор навыков повторял бы готовый процесс.
  Настройки проекта добавляются через `openspec/config.yaml`.
- **Версии закреплены локально.** Использовать npm lock-файл, публичный registry
  и `.nvmrc`. Это обеспечивает одинаковую установку при разных настройках машины.
  Глобальная установка CLI уступает локальной по воспроизводимости версии.
- **Тонкая обёртка CLI.** Upstream-профиль задаётся глобально, поэтому обёртка
  передаёт дочернему процессу репозиторные XDG-пути и профиль из отслеживаемого JSON.
  Команды выполняются официальным CLI; схема и навыки не переписываются.
- **Исполняемая проверка обвязки.** Проверять инструкции, метаданные навыков,
  lock-файл, ссылки, версию CLI и разрешение корня; при наличии артефактов
  запускать строгую структурную валидацию OpenSpec. Проверки продукта пока неприменимы.
- **Контекст отдельно от гипотез.** Видение, принятые решения и открытые вопросы
  хранятся в отдельных документах. Для bootstrap используется `skip_specs: true`,
  поскольку пользовательское поведение не изменяется.

## Risks / Trade-offs

- Готовый навык показывает голую команду `openspec` → корневые инструкции
  и workflow требуют префикс `npm run --silent openspec --`.
- Генерация может изменить сохранённые навыки → версия закреплена, а повторная
  генерация проверяется на отсутствие непреднамеренного diff.
- Структурные проверки могут быть приняты за проверку функций → документация
  и вывод команды явно ограничивают результат обвязкой.
- Правила языка пока неполные → инструкции честно отражают невыбранный стек;
  конкретные команды и соглашения добавляются при инициализации приложений.

## Migration Plan

Добавить инструменты, конфигурацию, навыки и документацию одним изменением.
Проверить чистую установку, повторную генерацию и диагностические отказы на
повреждённых данных в отдельной временной копии. Записать результат проверки,
архивировать bootstrap стандартным CLI и доставить изменение через Git.
Откат — возврат этого изменения; продуктовых данных для миграции нет.
