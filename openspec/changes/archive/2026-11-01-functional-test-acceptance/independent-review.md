Существенных незакрытых замечаний к проверенной обвязке не обнаружено.
Это результат проверки инструментов и инструкций. Он не подтверждает
функциональную готовность приложения или релиза.

| `git diff --check` по проверяемым областям | Ошибок пробелов нет |

Тесты проверяют полноту релизного набора и профилей, изменение требований
и кода после приёмки, изменение файлов кандидата/evidence, пропущенные и
повторные результаты, self-review, отсутствие suite, недостоверный automated
pass и task checkbox без приёмки. Исполнение suite проверяется настоящим
дочерним процессом на временном fixture-репозитории. Экспорт сохраняет failed
suite и blocked case; они не превращаются в успешные результаты Allure.
Тесты host deployer вызывают только локальную функцию валидации; выкатка
и изменение файлов сервиса не выполнялись.

## Замечания первого прохода и повторная проверка

- Сценарии chat-reliability-and-sync отсутствовали в первоначальном наборе.
  Добавлены источники и кейсы; каждый актуальный spec теперь должен быть
  классифицирован как источник или иметь явное исключение с причиной.
- Manifest мог не перечислять завершённую задачу. Теперь классифицируются
  все task IDs, а закрываемые продуктовые задачи связаны с case/platform парами.
- `kind=raw` раньше принимался без проверки результата конкретного автотеста.
  Теперь проверяются selector, файл, исходный статус и дата, а нормализованный
  результат связан с текущим планом. Исходный failed или прежний pass недостаточен.
- Автотесты исходников могли освобождать релизный кандидат от ручной проверки.
  Теперь у runner указан scope. Текущие `source` runners сохраняют обязательный
  проход кандидата; `artifact` требует отдельного проверенного контракта запуска.
- Web inputs не включали все конфигурации сборки. Теперь хэшируется весь
  `frontend/web`, корневой `package.json` и lock-файл вместе с API inputs.

## Проверка инструкций и ограничений

Навыки разделяют подготовку кейсов, приёмку фичи и полный предрелизный проход.
Unit/integration сохраняют основную проверку правил и взаимодействий;
ключевые пользовательские пути проверяются E2E. Число приёмочных сценариев
не выдаётся за распределение автотестов. Partial/flaky/quarantined не исключают
ручную проверку. Изменение требований требует пересмотра кейсов и нового прогона.

Основной ручной исполнитель — независимый агент. Отсутствие доступа, устройства
или инструмента сохраняет blocked. Навыки запрещают считать макет, исходники
или один screenshot подтверждением работающей фичи, менять ожидания в роли QA
и отправлять тестовые сообщения реальным получателям без разрешения.

Пилот имеет явно записанный blocked: IAB остановлен ошибкой доверия TLS,
другой браузер — ограничением sandbox. По сохранённому отчёту создание,
чат и участие через UI не проверены. Этот review не заменяет недостающий проход,
не снимает blocked и не выдаёт приёмку native/OAuth/store-сборок.

Receipt проверяется установщиком до изменений хоста и связан с файлами кандидата.
Установщик не имеет текущего каталога и полного evidence: их повторная проверка
через `qa:release-ready` непосредственно перед выкаткой остаётся обязательной
на доверенной рабочей машине. Это ограничение и отсутствие криптографической
аттестации указаны в документации. Ручное продвижение в stores описано как
обязательный шаг оператора; автоматическая интеграция со store API не заявлена.
