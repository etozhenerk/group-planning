# Spec Delta

## Purpose

Разрешать выкатку somewhere только после полного актуального набора ручных
и автоматических проверок применимых сценариев выпускаемого компонента.

## ADDED Requirements

### Requirement: Full release scope
Релизный план MUST включать все действующие применимые кейсы по утверждённой
матрице платформ/окружений, включая неизменявшиеся функции. Partial, planned,
manual и недостоверная автоматизация MUST оставаться в ручном наборе.
Пропущенный или пустой набор MUST не давать готовность.

#### Scenario: Old feature unchanged
- **WHEN** старый неавтоматизированный кейс не затронут diff релиза
- **THEN** он всё равно включён в полный применимый прогон

#### Scenario: Backend release
- **WHEN** меняется серверный компонент
- **THEN** план включает применимые сценарии поддерживаемых клиентов и API

### Requirement: Artifact bound acceptance
Готовность MUST быть привязана к точным файлам артефакта, конфигурации,
матрице окружений и версии кейсов. Новая сборка MUST требовать новой приёмки.
QA-сборка MUST не подтверждать автоматически подписанный магазинный артефакт.

#### Scenario: Rebuilt candidate
- **WHEN** checksum релизного файла отличается от проверенного
- **THEN** проверка выкатки отклоняет прежний отчёт

### Requirement: Honest release blocking
Failed, blocked, skipped, not-run, повреждённые evidence и незавершённая
инвентаризация MUST блокировать релиз. Пропуск MUST не превращаться в pass
через ретрай, переименование или замену ожиданий. Публикация кандидата для
тестирования MUST отличаться от разрешения выкатки пользователям.

#### Scenario: Unavailable external login
- **WHEN** реальный OAuth не проверен на кандидате из-за отсутствия доступа
- **THEN** fake-provider тест не закрывает этот кейс и релизная готовность остаётся заблокирована

#### Scenario: Regression found
- **WHEN** ручной проход обнаружил дефект
- **THEN** он сохраняется, исправление проверяется повторно и по возможности получает регрессионный тест на подходящем уровне пирамиды
