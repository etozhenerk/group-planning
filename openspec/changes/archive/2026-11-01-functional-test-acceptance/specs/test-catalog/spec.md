# Spec Delta

## Purpose

Хранить проверяемые сценарии somewhere вместе с требованиями, покрытием платформ
и честным состоянием автоматизации, чтобы новые фичи не оставались без приёмки.

## ADDED Requirements

### Requirement: Traceable test cases
Каталог MUST хранить стабильный ID, требование, предусловия, действия,
ожидаемые результаты, очистку, платформы и критичность каждого кейса.
Состояние кейса MUST отличаться от результата его выполнения.

#### Scenario: Requirement changes
- **WHEN** изменился исходный сценарий или кейс
- **THEN** прежний результат не подтверждает текущую приёмку

#### Scenario: Missing coverage
- **WHEN** действующий сценарий продукта отсутствует в каталоге или новая версия не разобрана
- **THEN** проверка полноты сообщает пробел и не разрешает полный релизный pass

### Requirement: Testing pyramid
Проверки MUST иметь уровень unit, integration или e2e. Правила проверяются
на минимальном достоверном уровне; E2E покрывают ключевые пользовательские пути.
Процесс MUST не требовать искусственных процентных квот или дублирования всех
комбинаций на всех уровнях.

#### Scenario: Boundary rule
- **WHEN** правило отсечки имеет несколько граничных комбинаций
- **THEN** нижние уровни проверяют комбинации, а E2E подтверждает пользовательский путь и отображение результата

### Requirement: Separate automation and execution
Покрытие MUST учитываться по платформе: manual, planned, partial, automated.
Автоматизированное покрытие MUST ссылаться на воспроизводимый тест и регулярный
запуск; stable/flaky/quarantined учитываются отдельно. Ручной проход агентом
MUST не менять статус на automated.

#### Scenario: Only web automated
- **WHEN** кейс имеет автотест только для web
- **THEN** iOS и Android остаются в ручном наборе

#### Scenario: Unit is not the user journey
- **WHEN** unit проверяет правило доступа
- **THEN** пользовательский E2E-кейс не становится полностью автоматизированным только по этому тесту
