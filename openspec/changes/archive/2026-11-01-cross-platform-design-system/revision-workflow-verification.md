# Проверка процесса изменения дизайна

27.10.2026. База — c384ca5. По запросу пользователя закреплён цикл коррекции
дизайна во время реализации/ревью. Изменены SDD, инструкции и два проектных
навыка. Продуктовые макеты, значения токенов и код клиентов в этой задаче
не изменяются; публикация новой версии UI не требуется.

## Пройдено

- `npm run agent:check`: строгая валидация OpenSpec, инструкции, навыки и ссылки.
- `npm run --silent openspec -- instructions apply --change cross-platform-design-system --json`:
  context и operationGuidance содержат цикл ревизии, повторную публикацию,
  сохранение прежних отчётов, открытие задач и повторное независимое ревью.
  Схема остаётся spec-driven; сгенерированные OpenSpec-навыки не редактировались.
- `quick_validate.py` для design-system-publish и design-review: оба валидны.
- `npm run design:test`: 28 тестов прошли, включая отказ при изменении макета,
  токенов, контракта или клиентского исходника; связь checkbox с приёмкой,
  неполное покрытие, независимость, provenance и явную паузу.
- `npm run design:check`: генерация и структура проходят; это не приёмка UI.
- `npm run design:ready -- --manifest openspec/changes/meeting-experience-refresh/design-manifest.json`:
  ожидаемый отказ для устаревшего historical-отчёта. Его hash/evidence сохранены,
  результаты не переписаны в актуальный pass после изменения общих документов.
- Просмотрен diff, `git diff --check` без ошибок.

## Проверенные правила

При чтении инструкций сопоставлены сценарии delta specs с порядком в
[revisions.md](../../../docs/design/revisions.md) и обоих навыках:

| Ситуация | Действие агента |
| --- | --- |
| Конкретная принятая коррекция | Обновить сам макет и связанную документацию, перепубликовать затронутую систему, продолжить разрешённую реализацию без повторного подтверждения |
| Запрос вариантов | Подготовить макеты, сохранить их черновиками до решения пользователя |
| Общий токен/компонент | Проверить потребителей и платформы; синхронизировать версии зарегистрированных манифестов и снять устаревшую готовность |
| Новое решение во время ревью | Остановить приёмку прежней ревизии, сохранить историю, после реализации начать новый независимый проход |
| Ошибка реализации без нового дизайна | Исправить приложение по текущему эталону, не подгонять baseline |
| Изменение уже принятого экрана | Открыть связанные задачи заново; закрыть только после нового pass и design:ready |

Это проверка согласованности инструкций и существующих машинных ограничений,
а не новый сквозной прогон агента на интерфейсной задаче. Live-ревью клиентов
и их сборки в документационной задаче не запускались. Stop hook не менялся;
фактическая активация в Codex здесь не проверялась. Параллельные изменения
в основном рабочем каталоге не включались и не редактировались.
