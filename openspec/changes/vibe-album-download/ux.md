# UX/UI

## Путь и принятые решения

Запрос пользователя: «добавить опцию загрузки всех вайбов». Все фотографии текущей встречи; пользователь подтвердил: «Да, web — ZIP, телефоны — галерея».

Точка входа — вторичная кнопка с общей иконкой download рядом/под «Добавить фото» в заголовке альбома. Основное добавление остаётся заметнее. Desktop: действия в одном ряду, mobile: перенос по доступной ширине без горизонтального overflow. Для iOS не возвращаются общий бренд или надпись «Прошедшие встречи».

## Состояния

- Пустой альбом: только добавление, без скачивания.
- Фото есть: «Скачать все фото» (web), «Сохранить все фото» (native).
- Подготовка: общий spinner/подпись «Подготавливаем фото…», повторное нажатие выключено, рядом «Отменить»; альбом сохраняет индекс и остаётся доступным для просмотра.
- Ошибка: «Не удалось подготовить фотографии. Попробуйте ещё раз.» с действием повтора; нет ложного успешного счётчика.
- Отказ записи native: «Разрешите сохранять фото в настройках приложения.»; открыть системные настройки только по явному нажатию.
- Web готов: запуск обычного скачивания, «Скачивание началось»; после возврата кнопка снова доступна.
- Финальная системная запись native: «Сохраняем фото…», без отмены после передачи пакета системе. Временные файлы очищаются после её результата.
- Native готов: «Фотографии сохранены» только после подтверждения системной записи.
- Отмена, уход, выход, отзыв: подготовка прекращается, временные данные очищаются, поздний ответ не восстанавливает старую операцию.

## Компоненты и проверка

Переиспользовать опубликованные secondary button, download icon, spinner, error text, spacing и minimum target44/48. Новые размеры/цвета не вводятся. Требуется реальный небольшой прототип действия до UI-кода, публикация manifest и независимые desktop/mobile/native проверки. Текст не рассказывает пользователю про ZIP workers, временные файлы, очереди или backend.
