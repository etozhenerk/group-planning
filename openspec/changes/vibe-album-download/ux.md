# UX/UI

## Принятые решения и композиция

Пользователь подтвердил полный альбом текущей встречи: web — ZIP, телефоны —
галерея. 29.10.2026 уточнил расположение: «рядом с добавить фото». Предыдущий
перенос кнопки под основной отклонён. [Web-эталоны 4.1.1](assets/revisions/2026-10-29-album-actions-row/index.html) и
[нативные эталоны 4.1.0](assets/revisions/2026-10-29-album-download/index.html)
используют существующий альбом; его фото, жесты и возврат не меняются.

Desktop: primary «Добавить фото» и secondary «Скачать все» рядом в шапке.
Это одна неразрывная группа: при нехватке места переносится целиком под
заголовок, сами кнопки не переходят на отдельные строки.
Телефоны: эти же два действия в одном ряду, две равные колонки и space.s8;
native secondary называется «Сохранить все». На320 подписи переносятся внутри
кнопок, обе имеют одинаковую высоту. Полное доступное имя — «Скачать все фото»
или «Сохранить все фото». Minimum target44/48 и существующая иконка download.
Нет нового футера/нижних вкладок; на native остаётся стандартный «Назад».

## Состояния и переходы

- Пустой альбом: только добавление, скачивания нет.
- Запуск: снимок всего набора, вторая кнопка показывает общий spinner и «Отменить».
  Отмена доступна до передачи системной записи; третья строка не появляется,
  фото и выбранный индекс остаются на месте. Нет отдельных progress по файлам.
- Ошибка подготовки: «Не удалось подготовить фотографии. Попробуйте ещё раз.»
  и «Повторить»; новый запуск заново проверяет доступ.
- Отказ native разрешения: «Разрешите сохранять фото в настройках приложения.»;
  «Настройки» открывает систему только по явному нажатию. Android API29+ лишнего
  разрешения не запрашивает, legacy permission учитывается по версии.
- Web готов: authenticated download средствами браузера без Blob;
  «Скачивание началось» не обещает сохранение на диск.
  После передачи скачивания браузеру переход со страницы не прерывает его;
  выход из аккаунта и отзыв доступа по-прежнему контролируются сервером.
- Native финальная запись: «Сохраняем…» без отмены после передачи пакета системе;
  «Фотографии сохранены» только после её подтверждения. Private temp очищается.
- Ошибка финальной записи: понятная ошибка. Если Android мог опубликовать часть
  пакета, «Часть фотографий могла сохраниться. Проверьте галерею перед повторной
  попыткой.» и «Понятно»; без автоматического повторного сохранения/удаления копий.
  При подтверждённом полном publish и ошибке private cleanup сохранение успешно;
  recovery убирает журнал позже, повтор не запускается сам.
- Отмена, уход, выход, отзыв прекращают подготовку и очищают временные данные.
  Для web отмена при уходе действует до передачи скачивания браузеру; если
  передача не началась, оставшийся ready-архив удаляется по серверному TTL.
  Поздний ответ не возвращает старую операцию или данные другого пользователя.

## Проверка

Используются опубликованные secondary/primary, spinner, text/error, spacing,
minimum target и native text scaling. Новых цветов/размеров токенов нет.
Независимые feature-test и design-review нужны отдельно на web desktop/mobile,
iOS и Android; макет и сборка не доказывают сохранение ZIP/Photos/MediaStore.

## Исправление web-эталона · 4.1.1 · 29.10.2026

После скриншота с вертикальной парой пользователь повторил принятое правило
одной строки. Новая web-ревизия исправляет flex-wrap исходного макета;
предыдущие HTML/CSS и evidence не меняются. Состояния ready/preparing/cancelled/
error/success и desktop с недостатком места проверяются заново. Пустой альбом
по-прежнему имеет только добавление. Нативные композиции остаются прежними.
