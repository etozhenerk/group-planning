# Исправление строки действий альбома

Пользователь повторно указал на вертикальное расположение «Добавить фото» и
«Скачать все» в production rc.13. Правило одной строки уже было утверждено;
ошибка воспроизводилась при сжатии desktop-шапки названием встречи.

В приложении группа действий больше не переносит отдельные кнопки и не
сжимается заголовком. Шапка может перенести всю группу целиком. Mobile сохраняет
две равные колонки. Новых токенов, текстов, API или CI-настроек нет.
Согласованное правило опубликовано отдельной ревизией 4.1.1; прежние эталоны
и отчёты сохранены.

## Проверено

- Typecheck, ESLint, CSS structure, FSD, Prettier и 211 unit tests — PASS.
- Demo build — PASS.
- Один затронутый E2E в Chromium и WebKit — 2 PASS: 1440/1280/1024/800/740/320,
  одинаковая строка и высота, отсутствие пересечения и выхода за viewport;
  mobile равные колонки; подготовка, отмена, ошибка и повтор скачивания.
- В первой попытке новый resize-loop прочитал два bounding box по разные
  стороны асинхронного переключения mobile-layout. Добавлено ожидание смены
  `data-mobile` перед измерением; таймауты и требования геометрии не ослаблены.
  Исходный failed-run сохранён в `/tmp/somewhere-album-row-regression`, итоговый
  — `/tmp/somewhere-album-row-regression-final`.
- Первоначальный style-check остановила песочница на IPC tsx. Оставшиеся шаги
  выполнены с разрешённым IPC; успешно пройденные typecheck/lint не повторялись.
