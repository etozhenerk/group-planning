## Дизайн и движение

Просмотрены actual ready/preparing/error/success/denied/XXXL и живые reference ready/preparing/error. Эталоны сняты корневым агентом через IAB на 390×844 с реальным DOM, затем viewport восстановлен, временная вкладка закрыта. Сам reviewer просмотрел изображения; `reference-provenance.json` отмечает помощь при захвате. Разница текста встречи/даты/фотографий и 402 vs 390 зафиксирована: это проверка композиции, не pixel-equivalence.

Соседние primary/secondary, одинаковая геометрия, отступ между ними, доступные подписи и spinner соответствуют 4.1.0. При normal text обе подписи в одну строку; при XXXL нет клиппинга, но появляются переносы внутри слова. Числа размеров/равенство проверены XCUITest, снимки и sidecar содержат измеренное окружение.

Motion просмотрен по последовательности кадров (0.5 с для подготовки, 0.2 с для свайпов) и сохранён в коротких clips. На 30–37.5 с меняется только действие: фото сохраняет геометрию при prepare/cancel. Ошибка добавляет опубликованный feedback под действиями. На 84–91 с виден вылет по направлению жеста, следующее фото, затем пересборка после последнего с opacity/углами. После завершения перехода в этом наборе позднего скачка размера не наблюдалось. Частота кадров не доказывает точную кривую/длительность анимации; полный raw video сохранён локально.

**Расхождение эталона:** `ios-error.html` содержит `.download-feedback.error`, CSS назначает color.error, но общий `styles.css:78–79` задаёт цвет самому `p`, поэтому live reference серый. iOS отображает опубликованный color.error (#ffb8b2). Это конфликт текущего render эталона с CSS/UX-намерением; приложение не объявлено дефектным на его основе, визуальный 1:1 PASS этого состояния не выдан. Эталоны не менялись.

## Почему нет общего PASS

Начальный inputHash `e12169412704feaa6f0b0a82b1d1e1bbbc88a50f72fd5898e661314a49431587` сменился на `d732edef46139781e4611e66151404b55f7a6e41c51f02f74678dea3ce5f4701` во время параллельной работы. При обнаружении формальная текущая приёмка остановлена; исходный hash сохранён, 15 iOS inputs и точный app не менялись. `design-scoped-review.json` сохраняет blocked для текущего общего manifest, а не переносит результаты на другой hash.

Начальный `design:check` также сообщил новые literals в параллельном Android `ic_download.xml`; это не отказ iOS runtime. Сохранён исходный лог, чужая реализация не исправлялась.

Непроверено: native 320 pt, empty, live logout/отзыв доступа, delayed final PhotoKit saving и save-error, возврат из Settings, VoiceOver/reduced motion, большой/разноформатный альбом. Для этих случаев текущий fixture/набор тестов не создаёт нужные состояния. Success не превращает их в PASS. TC-VIBE-EXPORT-GALLERY/ALL/ACCESS выполнены частично; задачи/checkbox/manifest не менялись.

## Очистка и сохранённые данные

Fixture остановлен, штатный simulator lock освобождён. Orientation возвращён в portrait; keyboard и Reduce Motion не менялись. Тест временно сбросил add-only authorization только QA bundle и вернул его в notDetermined в defer. Крупный текст задан launch arguments, глобальная настройка не менялась.

Три новые synthetic фотографии оставлены в тестовой медиатеке с точными именами/SHA из `photos-added.json`: удаление raw DCIM файлов повредило бы учёт Photos, а отдельный доступ на управление всей медиатекой не запрашивался. Существующие фотографии и библиотека не очищались. Это явный остаток QA, не выполненный cleanup галереи. Все пути/байты результата задокументированы для безопасной точечной уборки через PhotoKit позже.

Продукт, тест-кейсы, эталоны, задания и исходные hash не изменялись. Коммиты, релизы и установка на физическое устройство не выполнялись.
