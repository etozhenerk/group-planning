# Действия альбома · 4.1.0

Решение пользователя 29.10.2026: «рядом с добавить фото». Первый черновик с
переносом вторичной кнопки под основной отклонён. Текущие действия занимают
один ряд на desktop и телефонах; на узкой ширине подписи могут переноситься
внутри равных колонок. Добавление остаётся primary, скачивание — secondary.

[Каталог состояний](index.html): web desktop/mobile, iOS и Android. Общие состояния:
ready, empty, preparing, cancelled, error, success; native также permissions,
saving, save-error; Android partial сохраняет честное предупреждение о возможных
личных копиях после прерванной публикации и не предлагает слепой повтор.

Видимые подписи — «Скачать все»/«Сохранить все», полные доступные имена содержат
«фото». Подготовка заменяет secondary на spinner с «Отменить», не создавая
третью кнопку/новую строку и не сдвигая фото. Финальная native запись показывает
«Сохраняем…» без отмены. Web сообщает начало скачивания, native — подтверждённое
сохранение. Ошибки и разрешения используют те же действия и отдельную строку.

Используются существующие tokens: space.s8/s12/s16, typography.size.small,
button.minimumHeight и target.web/ios/android, ButtonSpinner, Lucide Download.
Фотостопка, её жесты и геометрия из текущих эталонов не меняются. Футер и нижние
вкладки из устаревшего web исходника удалены по действующему navigation contract.

Root проверил реальный HTML во встроенном браузере: desktop1440×1000, phone390×844,
узкий phone320×740, переходы подготовки/отмены. Это проверка макета, не независимое
ревью приложения. Старые structural-check/provenance описывают первоначальный
черновик; новая публикация и hashes находятся в design-publication-4.1.0.md и
общем authority. Статусы success/permissions/saving выбираются явно, таймер успеха
не имитируется. Runtime API/галерея здесь не вызываются.
